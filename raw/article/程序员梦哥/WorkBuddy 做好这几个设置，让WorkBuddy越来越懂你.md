## 先看存储路径，别让 C 盘越用越满

这个设置我放到第一个说，因为我觉得很多小伙伴一定没注意过这个问题，我也是在使用了一段时间后才发现的。

我电脑原来的硬盘只有 512 G，C盘更是只有可怜的 125 G。用了 **WorkBuddy** 一段时间后，我发现C盘动不动就满了。搞得我不得不隔几天就清理一次。

后来，我还赶上硬盘涨价，忍痛加了一块 1TB 的固态硬盘，真是肝疼！

折腾了一段时间后，我才发现，虽然我把 WorkBuddy 安装到了D盘，但它的系统缓存目录还在 C 盘。

这里先分清两个位置，一个是任务文件存在哪儿，另一个是对话记录和运行缓存放在哪儿。

**打开「设置」，选择「通用」，找到存储，更改 WorkBuddy 默认工作空间存储路径。**
![[file-20261116214902068.png]]
==这个设置管的是以后新建的任务和分组，换个盘只会改变之后的保存位置。旧任务和系统缓存要另外处理。== 

如果 C 盘空间紧张，可以先把默认工作空间选到空间充足的盘。系统缓存要不要迁，先看它实际占了多少。真要动已有数据，先备份哈。
## 自定义指令，把常用要求提前说清楚

我在开始用新的 Agent 工具前，都会先设置一下这个自定义指令的配置。==所谓自定义指令，说白了就是提前给 Agent 定好一些约束规则，之后的对话和任务都会默认参考这些要求，省得每次都重复交代。==

如果你之前用过 Claude Code、Codex 或 OpenCode 这类 Agent 工具，那一定知道                CLAUDE.md、AGENTS.md 这样的规则文件。WorkBuddy 则可以直接在设置里填写。

**打开「设置」，选择「个性化」，找到「给 WorkBuddy 的指令」，点击右侧的「编辑」，填入内容后保存。**
![[file-20261118180703719.png]]
下面这份是我常用的指令，大家可以直接使用，也可以根据自己的需求做调整。

```自定义指令
# 行为准则  
减少常见 LLM 编码错误的行为准则。可根据需要与项目特定说明合并使用。  
权衡：这些准则偏向谨慎而非速度。对于琐碎任务，请自行判断。  
  
1. 编码前先思考  
不要假设。不要隐藏困惑。要摆出权衡。  
在实现之前：  
明确陈述你的假设。如果不确定，就提问。  
如果存在多种理解方式，把它们都列出来——不要默默选择一种。  
如果有更简单的方案，就说出来。该反对时就反对。  
如果有不清楚的地方，停下来。指出困惑点。提问。  
  
2. 简单优先  
用最少的代码解决问题。不做任何投机性设计。  
不添加未被要求的功能。  
不为一次性代码做抽象。  
不添加未被要求的“灵活性”或“可配置性”。  
不为不可能发生的场景写错误处理。  
如果你写了 200 行而其实 50 行就够，重写它。  
问自己：“资深工程师会觉得这过度复杂吗？”如果会，就简化。  
  
3. 外科手术式修改  
只动你必须动的地方。只清理你自己造成的混乱。  
编辑现有代码时：  
不要“改进”相邻的代码、注释或格式。  
不要重构没坏的东西。  
匹配现有风格，即使你自己会写得不一样。  
如果发现无关的死代码，提一下——不要删除。  
当你的改动产生孤儿代码时：  
移除因你的改动而变得未使用的导入/变量/函数。  
不要移除预先存在的死代码，除非被要求。  
检验标准：每一行改动都应能直接追溯到用户的需求。  
  
4. 目标驱动执行  
定义成功标准。循环直到验证通过。  
把任务转化为可验证的目标：  
“添加验证” → “为非法输入写测试，然后让它们通过”  
“修复 bug” → “写一个能复现它的测试，然后让它通过”  
“重构 X” → “确保重构前后测试都通过”  
对于多步骤任务，先说明简要计划：  
[步骤] → 验证：[检查项]  
[步骤] → 验证：[检查项]  
[步骤] → 验证：[检查项]  
强的成功标准能让你独立循环推进。弱的标准（“让它能跑”）则需要不断澄清。  
  
如果出现以下情况，说明这些准则正在起作用：diff 中不必要的改动更少、因过度复杂而重写的情况更少、澄清性问题出现在实现之前而不是犯错之后。
```

==如果你仔细看过这段自定义指令内容，就会发现，这个指令主要是针对写代码时容易出现的问题，进行的约束。==

==要求它在写代码时先想清楚、少加没必要的功能、只改相关部分，并在完成后检查结果。==

如果你有自己的业务需求，也可以照着模板自己做调整。
## 回复风格，选一个你聊着舒服的

你是不是在和 WorkBuddy 聊天的时候，发现有时候他很啰嗦，或者他的回复语气你不是很喜欢，又或者需求还没说清楚，它就急着给答案。其实 WorkBuddy 在设置中提供了多种回复风格。

![[file-20261117214549904.png]]

**小伙伴们可以打开「设置」，选择「个性化」，找到「回复风格」。** 这里我选几个重要的给大家介绍一下。

- **专业严谨**：像个认真做汇报的同事，讲究条理，解释也比较细。想把一个问题掰开讲清楚，可以选它。
- **高效务实**：主打一个说重点。少点铺垫，尽快给结论，适合需求明确、只想赶紧把活干完的时候。
- **启发引导**：偏向通过提问帮你想清楚。特别适合那种「我有个想法，但一时半会儿说不明白」的情况。

我平常用得最多的是「高效务实」，回答言简意赅，也比较合我的习惯。大家可以根据自己的喜好和习惯自行调整。

另外，在这个设置的上面还可以改你俩互相的称呼。我给 WorkBuddy 设置的是大黄，它叫我boss，这个还是挺好玩的。
![[file-20261117215038827.png]]
## 人设设定与长期记忆

这两个设置的入口也在「个性化」，一个写你希望它怎么跟你打交道，一个写你希望它以后还能记得的信息。
### 人设设定

人设设定可以写你希望 WorkBuddy 是怎么跟你打交道。你可以给 WorkBuddy 设定一个身份，你希望它的回答方式、性格以及其他的一些约束条件。

比如我希望大黄像熟悉的同事一样跟我说话，遇到有分歧的地方可以直说。


![[file-20261118145732609.png]]
### 长期记忆

不知道你有没有这个问题，你在一个聊天窗口和 WorkBuddy 聊天的时候，交待了你是谁，做什么工作的，换个窗口它就完全不知道了。这个设置就是为了解决这个问题的。

你可以把你的职业、身份、工作内容、偏好等一些信息写到这里，这样即使新开一个会话框，WorkBuddy 也能认得你，不会说话太离谱。
![[file-20261118145712556.png]]
如果实在不知道怎么写，也可以把相关信息告诉 WorkBuddy，让它按「人设」和「长期记忆」分别整理成 Markdown 内容。自己看完，改改，再贴到对应的输入框。

先写几条常用的就行。用一阵子，发现人设有些别扭，或者记忆里留着过时的信息，再回头改。

## 记忆与进化

这个设置是默认开启的，我也建议你不要关闭。因为这个设置会记录你与 WorkBuddy 协作中长期有价值的项目成果和约定。并且支持用户级和项目级，让智能体在后续任务中也遵循这些约定。这也是让你和WorkBuddy 越来越懂你的关键。

**打开「设置」，进入「记忆与进化」，找到「本地记忆与技能」。** 

![[file-20261118161213816.png]]
拿做周报举个例子。你平时总让 WorkBuddy 先列出本周最重要的两条变化，这类偏好它可以从对话里自己总结出来。如果只有某个项目要求「周报只统计工作日」，就在做这个项目时把范围说清楚。过一阵可以去「个性化 → 长期记忆」看看，它有没有把某个项目的要求当成你的通用习惯。

如果你每周都要先读订单表、按渠道汇总，再核对合计，等这套流程跑顺了，还可以让                WorkBuddy 把它做成一个 Skill。下周换一份订单表，就可以用同一套步骤再跑一遍。
## 窗口设置和模型选择

这个设置就是经验之谈了，WorkBuddy 在对话框中是可以切换模型的。并且经常有一些限时免费的。比如 WorkBuddy 最近的新发布的混元 Hy4 Flash 模型。
![[file-20261118151235237.png]]
如果你把鼠标放到模型上，还会发现这里还有个思考强度和窗口上下文设置。这两个设置都是根据需求来选择的。

如果只是做简单任务，用默认的思考强度和上下文窗口就行。但是如果是 Vibe Coding 或调研这类任务，要参考的资料或者聊天记录比较多，最好把上下文窗口调到当前模型支持的最大参数。因为窗口越大，一轮对话就能容纳更多内容。聊得太长时，前面的内容有可能被压缩成摘要。

碰到需要反复推敲的问题，可以试着调高思考强度，做完再检查结果。
![[file-20261118151348857.png]]
==这里再分享一个省 Token 的小技巧。有些活儿得分几次做，比如写一份调研报告，或者整理几个月的销售数据，又或者是 vibe coding 项目。每做完一部分，先让 WorkBuddy 把做完的事、定下来的方案、相关文件的位置和下一步要做什么写到台账里。接下来，在同一个工作空间新开一个对话，让它先读台账，再接着做。如果台账和少量文件就能交代清楚下一步，新对话就有机会少带一些旧聊天记录，省下一些输入 Token。不同阶段也可以按任务需要，换个模型或者调一下思考强度。==
