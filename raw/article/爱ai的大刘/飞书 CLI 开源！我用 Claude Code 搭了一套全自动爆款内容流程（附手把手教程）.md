## 安装配置——让 Claude 当你的装机师傅

01

最快的方式：让 Claude 帮你装

如果你已经在用 Claude Code，那恭喜你， **安装这件事你可以完全外包** 。

打开 Claude Code，说一句：

> 帮我安装飞书 lark-cli，检查一下环境，装好之后简单验证一下能不能用，具体方法：https://github.com/larksuite/cli/blob/main/README.zh.md。

Claude 会自动帮你检查 Node.js 版本、执行安装命令、跑配置初始化。你需要做的，就是在它弹出授权页面的时候 **拿手机扫个码** 。

## 让 Claude 读懂飞书——教 AI 做事的第一步不是"做什么"

02

装完 lark-cli 之后，大多数人的第一反应是"来，帮我建个表"。

但我没这么做。

说实话，这些年用 AI 用下来，我得出了一个反直觉的认知—— **教 AI 做事的第一步不是"做什么"，是"你能做什么"。**

你着急让 Claude 干活，它就只能用猜的。你让它先读完说明书，它后面的每一步都会比你预期的准。

所以我做了一件看起来"多余"的事（但是很必要）。

喂文档，建认知

我把这份网页文档丢给了 Claude Code——lark-cli 的 GitHub README。

> "把这份文档读一遍，帮我梳理出 lark-cli 的完整能力边界，https://github.com/larksuite/cli/blob/main/README.zh.md。"

这不是什么高级操作。但这一步， **决定了后面所有设计的质量** 。

Claude 给了我什么

几分钟后，Claude 输出了一份结构化的能力地图。

**11 个业务域** ，一个不少：

\- base（多维表格）——65 个快捷命令，整个 lark-cli 里功能最猛的模块

\- docs（云文档）——创建、编辑、搜索，支持 Markdown 直接注入

\- im（即时通讯）——发消息、搜群、管群成员

\- calendar（日历）——查日程、建日程、查忙闲

\- task（任务）——创建待办、建清单、分配成员

\- contact（通讯录）——搜人、查组织架构

\- sheets（电子表格）——创建、读写、导出

\- drive（云空间）——上传下载文件、管理权限

\- wiki（知识库）——解析知识库链接

\- vc（视频会议 / 妙记）——搜会议记录、拉纪要

\- mail（邮箱）——写邮件、搜邮件、看收件箱

**三层命令架构** ，从简到繁：

| 层级 | 语法 | 适合谁 |
| --- | --- | --- |
| 快捷命令 | `lark-cli base +record-upsert` | 日常使用，人类和 AI 都友好 |
| 标准命令 | `lark-cli calendar events list` | 需要更多控制参数时 |
| 通用 API | `lark-cli api GET /open-apis/...` | 覆盖飞书 2500+ API，万能兜底 |

还有一个重点—— **19 个 AI Agent Skills** 。这些 Skill 是专门给 Claude Code 这类 AI Agent 用的知识包，教 AI 理解飞书 API 的模式和最佳实践。装了这 19 个 Skill，Claude 操作飞书就像你操作微信一样自然。

为什么这一步重要

这就像你雇了一个新助理。

你不会上来就让他干活。你会先让他读一遍公司手册——我们有哪些系统、每个系统管什么、不同场景走什么流程。

**AI 理解越深，后面的设计越准。**

很多人觉得这步多余。但我告诉你，省了这步的人，后面一定会反复返工——因为 Claude 不知道 lark-cli 有视图分组功能，不知道有 `+data-query` 做服务端聚合计算，不知道飞书妙记可以转录视频。

**你不告诉它这些能力存在，它就永远不会用。**

这是我这几年用 AI 最大的心得： **AI 的上限不是模型的能力，是你喂给它的上下文。**

然后我问了一个问题

> "你觉得作为一个自媒体博主，我应该怎么用飞书来管理我的内容生产流程？"

这个问题的本质不是"帮我建几张表"。而是—— **你已经了解了飞书的全部能力，现在帮我设计一套系统。**

## 设计数据底座——让 AI 当你的架构师

03

大多数博主的痛：东西散落在各个角落

你有没有这种经历？

选题灵感散落在备忘录里，看到的好文章收藏在微信收藏夹里，写作进度记在脑子里，发布排期写在 Excel 表格里，数据复盘？ **不存在的** 。

每次想找上周的选题灵感，得在三个 App 之间来回翻。每次想看这个月发了几篇，得手动数。

**问题在于你缺一个系统。**

Claude 的架构产出

当我把需求丢给 Claude 之后，它没有急着建表。它先给了我一张架构全景图：

●●●

飞书多维表格 Base："自媒体运营中心"  
├── 表 1：选题灵感库 ← 所有选题想法、灵感、待评估的方向  
├── 表 2：积累素材库 ← 持续跟踪的优质内容（文章+视频）  
├── 表 3：内容管理表 ← 每篇文章从立项到发布的状态追踪  
└── 表 4：发布计划表 ← 各平台的排期和发布状态

4 张表。各司其职。

不过 Claude 第一版方案有个问题——它把发布计划表设计成了内容管理表的子表，所有发布记录塞在一个"发布平台"多选字段里。我一看就不对：同一篇文章发公众号和小红书，数据肯定不一样，你用一个多选字段怎么分别记阅读量？我让它把发布计划拆出来独立建表，一篇文章在每个平台各一条记录，数据关联更灵活。

**AI 给你的第一版方案，不一定是最优解。但它给了你一个足够好的起点，让你知道该往哪里改。**

关联关系：数据怎么流转

4 张表之间怎么打通，才是关键。

●●●

积累素材库 ──启发──→ 选题灵感库 ──立项──→ 内容管理表 ──排期──→ 发布计划表

**数据是单向流动的** ——从素材到灵感，从灵感到内容，从内容到发布。每一步都有关联字段打通，没有孤岛。

选题灵感库：重点看两个字段

9 个字段，覆盖一个选题从"脑子里冒出来"到"决定写不写"的完整决策链。选题标题、来源类型、关联素材、写作角度、适配平台、优先级、时效性、状态、备注——其余字段你看名字就懂，不展开了。

重点看两个—— **"来源类型"和"时效性"** 。

来源告诉你灵感从哪来（热点追踪、个人灵感、积累启发、读者反馈、AI 推荐），时效性告诉你该不该立刻动手（紧急热点 24h 内 / 近期热门本周 / 长青内容不急）。当你有 20 个待评估选题的时候，这两个字段就是你的筛选器。

积累素材库：一个字段值回票价

11 个字段。标题、来源账号、内容形式、原始链接、核心观点、亮点标注、对我的启发、所属领域……不逐个讲了。

**这张表最精妙的地方在于"妙记链接"字段。**

就这一个字段，把视频和文字两个平行宇宙打通了。以前你收藏的视频，三天后就是薛定谔的猫——你永远不知道里面到底说了啥。现在，视频丢进飞书妙记，自动转录成文字，转录结果链接回这张表。视频 → 妙记转录 → 要点提取 → 入库 → 关联选题， **一条链路打通** 。

光这一个设计，就值回票价了。以前你觉得"视频素材难管理"是无解的——现在它有解了，而且解法比你想象的优雅。

内容管理表：看板才是精髓

8 个字段，干净利落。

这张表的核心玩法不在字段——在 **看板视图** 。按"写作状态"分组，草稿中、修改中、已定稿、已发布，四列清清楚楚。打开一看，就知道手头有几篇在写、几篇在改、几篇可以排期了。 **不用记在脑子里，不用翻聊天记录。**

发布计划表：数据闭环的关键

12 个字段。一篇文章在多个平台发布 = 多条记录。关联文章、发布平台、计划发布日、发布状态、发布链接，再加上阅读量、点赞、收藏、评论、转发、涨粉——全是数据字段。

**注意最后两个——"涨粉"和"数据备注"。**

阅读量 8000，点赞 300——这是数据。"这篇标题用了悬念式，打开率比上篇高 40%，但转发偏低，可能是缺少社交货币设计"——这是认知。 **数据备注字段，就是你的复盘笔记。**

设计原则：三句话

**关联字段打通** ——数据不孤立。 **状态字段用单选** ——方便做看板视图。 **数据字段留闭环** ——发布后的数据回填，为下次选题提供依据。

**好的工具帮你建表。好的系统帮你做决策。Claude 给我的不是 4 张表——是一整套决策链。**

## 一键搭建——说一句话建一张表

04

纸上谈兵结束了。接下来，把蓝图变成真的。

首先用飞书多维表格简历一个数据管控中心

在 Claude Code 里说一句：

> "帮我在飞书创建一个多维表格，叫'自媒体运营中心'。"

这时候 AI 自动执行背后的命令：

●●●

lark-cli base +base-create --data '{"name": "自媒体运营中心"}'

一秒钟不到，返回了一个 `app_token` 。这就是你的大本营地址，后面所有的表、字段、记录操作都基于它。

第一张表：选题灵感库

> "在运营中心里建一张'选题灵感库'，9 个字段：选题标题、来源类型、关联素材、写作角度、适配平台、优先级、时效性、状态、备注。来源类型的选项是热点追踪、个人灵感、积累启发、读者反馈、AI推荐。"

Claude 自动把这句话翻译成了建表命令——字段类型、单选选项、多选配置，全帮你搞定。你不用知道 JSON 长什么样，它替你写。

一句话，9 个字段，自动创建。打开飞书看一眼——表已经在了，字段齐了，选项也配好了。

![选题灵感库建完后的多维表格界面，展示字段结构](https://mmbiz.qpic.cn/sz_mmbiz_jpg/J1Cdba5GUc2feDUhKhLOmbdk8RV99bMMdILib4bmNDGTbZy5HjVs0F09wDfh1yDia7GjVJIAQG3VYRVmw8usWry4nq00OY4ia6qfiaNmzWXAMQk/640?wx_fmt=jpeg&from=appmsg#imgIndex=3)

其余三张表：同样的路子

同样的方式，我又让 Claude 建了积累素材库（11 个字段）、内容管理表（8 个字段）和发布计划表（12 个字段）。三句话，三张表，Claude 一气呵成。

看板视图：两条命令搞定

内容管理表建好之后，重头戏来了——看板视图。

●●●

\# 创建看板视图  
lark-clibase+view-create\\  
\--app-token"$APP\_TOKEN"\\  
\--table"内容管理表"\\  
\--data'{"view\_name": "看板视图", "view\_type": "kanban"}'  
  
\# 按 "写作状态" 分组  
lark-clibase+view-set-group\\  
\--app-token"$APP\_TOKEN"\\  
\--table"内容管理表"\\  
\--view"看板视图"\\  
\--data '{"group\_by": \[{"field\_name": "写作状态", "order": "ASC"}\]}'

两条命令，看板就出来了。草稿中、修改中、已定稿、已发布——四列清清楚楚。

搭建完成：回顾一下

4 张表，40 个字段，1 个看板视图。整个过程： **5 分钟，全程自然语言。**

以前搭这样一套系统，光想字段就得半天。现在你只需要描述你要什么，Claude 替你翻译成飞书能理解的语言。

**当搭建系统的门槛降到"会说话"，系统就不再是大公司的特权了。**

## 封装成 Skill——从"一句一句说"到"一句话跑完"

05

4 张表搭好了。但空表不等于系统。

如果每次操作都要我一步步跟 Claude 说"先查选题库、再建记录、再关联字段"——那跟手动操作有什么区别？无非是从点鼠标变成了打字。

**真正的自动化，是把整条链路封装成 Skill。**

什么是 Skill？

Claude Code 有一个能力叫 Skill——你可以把一套完整的操作流程写成一份指令文档，Claude 读完之后就知道"遇到这种需求，按这个流程一步步执行"。

打个比方：你第一次教助理做一件事，得手把手一步步说。但教完一次之后，你把流程写成 SOP 手册，下次只要说"按手册来"，助理就能自己跑完全流程。

**Skill 就是给 Claude 的 SOP 手册。**

我一共封装了 **10 个 Skill** ，从素材积累、选题管理、文章写作，到发布排期、数据分析、周报生成——覆盖了自媒体内容生产的完整生命周期。每个 Skill 都知道该读哪张表、写哪张表、调哪条命令。 **你不用记任何命令，说人话就行。**

挑几个最亮的给你看

> "这个妙记链接里有个关于 RAG 的视频，帮我提取要点存进素材库。"

飞书妙记转录 → AI 提炼观点 → 写入素材库。再说一句"帮我转化为选题"，素材库和选题库自动关联。 **一条视频，两句话变成一个选题。**

> "帮我搜一下今天 AI 领域有什么热点，挑 9 个适合我写的录进选题库。"

Claude 联网搜索 → 评估适配度 → 批量写入选题灵感库。还能更懒——"帮我推荐今天写什么"，Claude 综合时效性、优先级和历史数据表现，直接给你 Top 3。

> "过去一个月互动率前 5 的文章是哪些？分析一下共同特征。"

Claude 跨 4 张表关联查询 → 聚合计算 → 输出分析报告。"帮我生成这周的内容周报"——一键存为飞书文档。

10 个 Skill 串起来长这样

●●●

视频/网页 → 素材库 → 选题库 → 内容管理表 → 飞书文档 → 发布计划表 → 数据分析/周报
