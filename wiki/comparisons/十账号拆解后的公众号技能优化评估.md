# 十账号拆解后的公众号技能优化评估

评估问题：完成 [[topics/指定十账号近期文章拆解]] 的300条研究后，现有公众号 Skill 是否需要因新样本而优化。

结论：**不需要把300篇编成新规则集，也不重构流水线。** 需要处理的是四处**可验证的具体缺陷**，其中两处已在实际隔离执行中复现出错：

| 状态 | 缺陷 | 类型 | 证据 |
| --- | --- | --- | --- |
| **已修** | 写作 Skill 末尾把标题／封面指向未安装技能 | 名称漂移，存在误导调用风险 | `.agents/skills/wechat-article-writing/SKILL.md:173-175` 与 `scripts/installed_skills.json` 的6个实装名单比对 |
| **已修** | 定稿检查把「案例客户身份」和「作者—产品方合作身份」混为一谈 | **已复现的误判** | 隔离演练中模型把「未披露」判成与前文矛盾并列入必须修改 |
| **已修** | 写作 Skill 的两份对标 reference 仍以22篇和旧绝对路径为唯一入口 | 入口陈旧，新样本不可发现 | `references/benchmark-methods.md:1-3`、`references/case-and-hook-selection.md:3` |
| **已修** | 定向改稿缺一条区分度高的回归样例 | 缺样例，非缺规则 | 隔离演练中出现「未改动≠没有问题」的越界表述 |

## 已覆盖，不应包装成新增能力

新样本里最显眼的方法，现有 Skill 大多已有对应约束。把它们再写一遍只会加长提示词，不会改变行为。

| 新样本暴露的要求 | 现行已覆盖位置 | 判断 |
| --- | --- | --- |
| 脚本先确认再生成、元素级小改、版本回退，见 [[sources/路人甲TM_Fotor商用MG流程实测]] | 写作 Skill 要求保留决定结果的关键修改与判断依据；`references/draft-and-final-review.md` 已有备份、保留非授权内容与改后比对 | 已覆盖。这条适合留在知识库按需引用，不宜变成每篇必经审批 |
| 输入没全读完就不能说「全部整理好」，见 [[sources/洛洛AI说：洛洛：Today AI孕期管理实测]] | 案例参考已要求信息对应、遗漏与可核验；写作 Skill 禁止把未看到的部分写成已验证 | 已覆盖。隔离演练中模型主动改写成「24张分三批上传，最后只确认识别了12张」，属正向反证 |
| 模型初稿不能直接当自己的判断，见 [[sources/大刘搭建ima与WorkBuddy自进化第二大脑]] | 写作 Skill 区分用户实操、第三方案例、官方主张与助手推测 | 已覆盖 |
| 局部改参不能牵连其他区域，见 [[sources/郭震AI：郭震：实测商汤U1 Pro交付级生图]] | 案例参考要求修改部位正确、其余区域无意外变化 | 已覆盖。具体像素级验收方法留 wiki |
| 模拟委托不能写成真实订单与收入 | 定稿检查已要求标题—开头—正文—结尾兑现，事实边界含商单 | 已覆盖，但见下方缺陷2的边界混淆 |
| 作者亲测硬关口、只改授权部分、微信预览不等于本地通过 | 流水线 `SKILL.md`、`references/handoff-contract.md`、`references/stage-checklists.md` | 已覆盖，不新增审批阶段 |
| S1 选题分来源并行、S4 分层检查 | [[comparisons/公众号流水线多Agent化改造评估]] | 已评估过；本轮无协调成本新数据，不重复建议 |

## 缺陷1：写作 Skill 的标题／封面路由与实装不符

`wechat-article-writing/SKILL.md:173` 要求「取标题时使用 `wechat-article-titles`」「做封面时使用 `wechat-article-covers`」，`:175` 还推荐 `gzh-entrypoint`。三者都不在安装清单里；实际安装的封面技能是 `gzh-webchat-cover`，且其说明已覆盖「文章封面、标题配封面」。

风险：用户在正文定稿后要求做封面，助手可能按「不可用则直接完成」降级为口头处理，而不是进入已有封面工作流。`:175` 禁止假称调用，所以问题不是虚构调用，而是**指向了不存在的技能名**。同理，`gzh-topic-planning` 是选题技能，不能拿来当标题技能填空。

最小改法：只改末尾两段——封面指向 `gzh-webchat-cover`；标题写明本环境无独立标题技能时按用户要求直接给（并遵守不预设爆款结论）；删掉不存在技能的推荐。

## 缺陷2：客户身份与产品合作身份被混同（已复现）

现行定稿检查已有一般事实边界，但没有一句话区分「是不是真实客户委托」与「作者是否受产品方邀测、赞助或付费合作」。这两件事独立：模拟案例完全可以出现在有偿合作文章里。

隔离演练（加载现行完整 `gzh-final-check`，输入为本批真实材料改写的合成稿：两条自用＋一条虚构品牌模拟＋合作未披露）中，模型正确拒绝了真实商单与收益标题、正确拒绝了把第三方数据写成本人实测，但在「必须修改」里写下：既然已说明没有客户委托、第三条为虚构模拟，「因此『没有披露』与前文不一致」——把客户关系推成了合作披露矛盾。

这是消费者可见的误判：作者可能被要求修改一句本就正确的话。单次回答不等于稳定失败率，但错误方向明确且可复现描述。

最小改法：在事实边界补一句身份区分，并加一条回归输入。**不加商业审核阶段。**

> 是否为真实客户委托，与作者是否受产品方邀测、赞助或付费合作分别判断；模拟委托不证明无合作，未披露时合作状态仍未知。

## 缺陷3：写作 reference 仍以旧22篇和失效绝对路径为唯一入口

`references/benchmark-methods.md:3` 与 `references/case-and-hook-selection.md:3` 把范围写死为22篇路人甲文章，原文目录指向 `E:\工作\note\work\Clippings`；本轮读取该目录不存在。新300条的实际入口在 [[topics/指定十账号近期文章拆解]]，新增动作在 [[topics/文章写法库]]。

风险：单靠安装包时，助手更容易只复述旧22篇，且无法按稿件问题定位新样本；引用失效绝对路径也无法回查。仓库 `AGENTS.md` 已有先查知识库要求，所以这是**技能自包含性与入口陈旧**问题，不是「本环境不会检索知识库」的实证。

最小改法：在这两份 reference 开头加一段按需入口，不复制300篇：

> 当前工作区若有知识库，按稿件问题检索文章写法库／AI写作案例库／证据与边界库，选相关 source 后回查其 raw 锚点；没有本地库则继续用本 reference，不臆造路径。

## 缺陷4：定向改稿缺一条对照样例

`references/draft-and-final-review.md` 已禁止为顺句新增信息，但 `tests/editorial-cases.md` 没有覆盖「没被改动」与「没有问题」的区别。隔离演练里模型保留授权范围做对了，却新增两句越界表述：把「其他镜头保持不动」写成「前面的镜头没有问题」；把「先保存旧版本」并入结果因果。

最小改法：只补一条回归样例——「未改动≠没有问题；保存版本≠证明未波及」，观察改稿是否新增未被材料支持的结论。**不加长 Skill 正文。**

## 拆解技能自身的待修项

`output/dream-skills-blue-layout/gzh-benchmark-deconstruct/`（未安装、未提交的暂停实现）存在两处自相矛盾：

- `SKILL.md:61` 链接 `references/source-map.md`，该文件不存在，入口链接断。
- `SKILL.md:19` 已允许「已看媒体如实记录、单篇无需 comparison」，但 `references/page-contracts.md:23` 仍要求必写「图片、动图和视频未核看」、固定四类产物。

这两处属该技能自己的收尾，与本次十账号研究无因果；在完成并安装前，不把它当作可依赖入口。

## 明确不改

- **封面**：本批未核看新视觉样本，没有配色、构图或可读性证据，`gzh-webchat-cover` 不改。
- **排版**：新增文字拆解不能证明应调整样式或渲染逻辑，`md-wechat-layout` 不改。
- **选题**：本轮隔离演练（加载现行 `gzh-topic-planning`，输入为本批三个账号线索＋本账号真实素材约束）表现符合要求——只推荐一个可试任务、把「定时通知」与「主动找回长期事项」拆成观察维度、淘汰他人孕期经历、标注权限与价格待核、结论定为「待试」。无需改。
- **不新增**统一评分、AI味评分、禁词表、多版本并行或自动发布。

## 建议执行顺序

1. 先修缺陷2（已有误判，影响作者改稿判断），加一条回归输入。
2. 再修缺陷1（名称漂移，一次改两段）。
3. 缺陷3作为 reference 开场补一段，成本最低。
4. 缺陷4随下次改稿规则调整一起补样例。

前两项必须同步回 `dream-skills` 源码仓库、更新安装清单与哈希、分别验证并推送，不能只改安装副本。

## 未验证项

- 隔离演练是单次 `slow` 调用，未测稳定失败率，也未覆盖真实微信预览与后台数据。
- 未实测「补了那句身份区分后模型是否不再混同」——需要在改动后重跑同一输入对照。
- 缺陷1的风险是文档交叉核对结论，未真实触发一次封面流程去观察降级。
- 本轮未修改任何 Skill、安装副本或源码，未安装、未重抓文章、未运行产品。

### 补充验证：`slow` 额度耗尽后改用 DeepSeek 角色

`slow`（ChatGPT）额度耗尽且 `completion` 只接受 `smol`/`default`/`slow` 三个别名，因此改用 `default` 角色复跑三项，其自报模型标识为 `deepseek_v3`。以下为实际执行结果，单次运行仍不构成稳定失败率。

**A｜身份区分（重跑同一输入）**：通过。模型把 L7 判为「这是披露状态，不是错误，保留原意即可」，建议仅是把表述改顺，不再列入必须修改；同一次输出里仍正确拦住了「没权限却写我实测」和「单点结果推全面超过竞品」。修复前 `slow` 的误判（把「未披露」判成与前文矛盾）未再出现。

**B｜定向改稿（重跑同一合成稿）**：通过。新增的越界表述全部消失——没有把「前面几个镜头没有被改动」写成「没有问题」，也没有把「先保存旧版本」并入结果因果。逐项核对：提示词原文完整、`【视频】(assets/demo.mp4)` 保留、结尾段未改、「没有被改动」的限定保留，删去的只有两处同义夸赞。

**C｜封面路由（此前只有文档级判断）**：通过。加载更新后写作技能与已安装的 `gzh-webchat-cover` 后，模型明确走 `wechat-article-writing` → `gzh-webchat-cover`，按封面技能第 1 步要求正文／标题／摘要，指出正文缺失是硬缺口并拒绝靠猜生成命题；同时逐项说明本轮无图像工具与写权限，无法出 PNG，未假称已生成。输出中未出现 `wechat-article-covers`、`wechat-article-titles`、`gzh-entrypoint` 任何旧名。

仍需说明：C 的验证环境本身没有图像工具与写权限，所以它证明的是**路由与不假称**，不是真实出图流程；`slow` 的强模型复跑依旧缺失。

## 补充发现：切入点方法此前没有任何技能入口

用户追问「技能里有没有找正文切入点的内容」。核对结果：**方法在，入口断了。**

- 方法只存在知识库 [[topics/公众号文章切入点方法]]：三层区分（文章类型／切入点／开头手法）、八类入口、把入口接到产品的连接顺序。
- `gzh-topic-planning` 只在 description 和边界里提到"切口"，执行顺序里没有选择步骤。
- `wechat-article-writing` 只有一句"助手负责选题切口"，原本那句"策划切入点也可以使用可用的 `gzh-entrypoint`"指向一个从未安装的技能；上一轮按缺陷1删除悬空引用后，技能里连名字都不剩。

这是上一轮修复的副作用，已补：

| 改动 | 内容 |
| --- | --- |
| `gzh-topic-planning/SKILL.md` | 执行顺序新增第3步「选切入点」：三层区分；从八类入口挑一到三个不同入口比较，不把同一任务换三个标题；每个候选写清相对旧稿新在哪、读者能理解的具体对象；时效事实与入口分开核实。边界新增一句指向知识库切入点页，方法不整页搬进技能 |

**行为验证（DeepSeek `default` 角色）**：给同一产品要三个候选，输出「旧项目卡点／读者真实问题／生活麻烦」三个不同入口，逐项说明比旧入门教程新增什么；把仅有 1 条同事提问标为需求证据薄，把没有官方资料的双 11 排除而不设入口，暂缓项给出理由，结论标"待试"。**通过。**
