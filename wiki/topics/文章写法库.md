# 文章写法库

> 收录约定：路人甲TM 的条目不再重复标注作者；其他作者的条目以「作者名：」开头。跨作者的统计结论要等样本量足够后单独成页。

本页记录可复用的**开头、案例推进、观点形成和收尾方法**，并说明适用条件。两篇样本不足以统计作者最常用的写法。完整单篇分析见 [[sources/百度搭子三道题文章拆解]]、[[sources/GPT-6-Astra连测文章拆解]]。

## 开头钩子

| 类型 | 本库样本如何写 | 适合什么时候 | 失效条件 |
| --- | --- | --- | --- |
| 热点转真实痛点，再设验收标准 | 百度搭子文章先给发布会和榜单，再问生成后的成果能否直接使用 | 新品有明确能力主张，而读者有对应工作问题 | 后文没有真实任务或验收结果，只借发布会信息引流 |
| 新品时效＋先亮个人判断＋预告案例 | GPT-6 Astra 文章先说开放，再表达强烈体验，预告五项案例 | 首发体验、读者最关心「它能做什么」 | 先亮的判断太绝对，后文缺成本、失败或边界 |
| 低预期反差＋成品先行＋疑问引路 | Qwen-Image-3.0 文章先说原本不抱希望，展示三种图，再问「什么时候能做成这样」 | 图片、视频或作品能在开头直接给读者看时 | 没有可见作品，或后文不解释作品的成功与缺陷 |
| 工具选择理由＋学习路径预告 | WorkBuddy 文章先以报告及个人横评感受建立选择理由，再预告安装、界面、设置和两次实战 | 功能多、读者需要先建立使用路径的入门教程 | 排名未经核实，或入口介绍过长使读者迟迟看不到成果 |
| 设问＋外部热度＋门槛变化 | Qwen3.8-27B 文章用「一个只有27B的模型，能有多强？」起手，给榜单与热议，再谈部署门槛降到 8GB 级 | 读者对某类产品的固有印象有争议，且本篇能做真实任务验证 | 只堆热度和排名，没有自己的测试；或把外部讨论当成本人体验 |
| 痛点具体化＋回应读者提问＋阵容预告 | Buzz 文章写「活是AI干的，班是我加的」，回应朋友提问，用一句话说清产品价值，并预告四个 Agent 的分工阵容 | 读者已有同类工具的多开体验，且本篇有明确的角色与成果可展示 | 痛点只停在吐槽，后文没有对应解法与结果 |
| 兴趣与热点背景＋工业化成本铺垫＋提出问题＋先放成品 | Pixmax 文章写自己迷上国漫，给结婴热度与幕后动作组工时，再问这类天地异象 AI 能做到什么程度，随后先放 75 秒成片 | 作品复刻类题材，且能说明真实工业化门槛 | 铺垫过长、迟迟不给成品；或省略工业化对照，让 AI 作品显得越级 |
| 私人趣味开场＋行业热点铺陈＋功能清单＋可用端说明 | Image2.5 文章先用「让两只猫打起来」的图开场，再讲一周内的行业节奏，随后列升级点与两个新功能，最后交代哪些端能用 | 首发评测容易同质化，需要一件私人的具体小事降低距离感 | 趣味开场与后文能力无关，或可用端始终没交代清楚 |
| 即时发布＋行业调侃＋投入宣告 | DeepSeek Harness 文章以「就在刚刚」开场，加一句友商调侃，直接说深夜爆肝三小时先探水 | 抢时效的首发实测，读者已经关注该产品发布 | 读者不了解该厂商时缺少上下文；只喊投入却不给结果会落空 |
| 数字冲击＋个人观感＋成绩铺垫＋反驳直觉＋提出可执行问题 | 天才机甲师文章用「6个人、3到4周、65集、播放破3亿」开场，说读者容易以为做机甲大片不难，再反驳「生成一台机甲和完成一部机甲短剧是两回事」，最后提问普通人能否从零手搓 | 案例成绩亮眼、但真实门槛容易被低估时 | 只反驳不给问题；或数字缺少时间与口径 |
| 常识设问＋自我怀疑＋先立判断标准＋非典型用户自白 | 豆包爱学文章先问「白日依山尽」下一句，说正因为太容易才怀疑「AI+教育」，提出「学习不只是得到答案」的三要素，并承认自己没有作业要辅导 | 作者不是目标用户，需要用标准建立发言资格时 | 立了标准但正文不回应；或自白变成免责声明 |
| 个人兴趣＋自创作品设定＋具体卡点＋先给成品 | updream 文章写自己迷上惊悚短剧、写了《回档后，我成为惊悚之神》，讲清走廊追逐戏要什么镜头，再说提示词写了几百字仍控不住三个细节 | 作者有真实创作需求，且卡点具体可复述时 | 作品设定与卡点无关，或卡点只是「效果不好」这种模糊描述 |
| 生活细节＋自我习惯变化＋反差事实＋数字对比＋提问 | 美图文章从朋友问用什么修图、自己脱口而出「用AI啊」写起，再交代以前第一反应是美图秀秀，用股价从顶峰跌去过九成与累涨超 150% 的反差提出问题 | 公司或行业出现与自己直觉相反的变化时 | 个人细节与主题无关；或反差数字缺少时间与口径 |
| 前文衔接＋承认概念混淆＋先辨别产品线＋低预期反差＋预告案例 | Qoder 文章先接上自己此前测本地模型时用的 CLI，承认三个同名产品把自己也绕晕，先把 CLI／IDE／新桌面端分清，再坦白低预期 | 同一公司有多个同名或相近产品，读者容易混淆时 | 概念解释过长挤掉案例；或澄清完了却没有新信息 |
| 读者请求＋半信半疑＋实测反转＋产品特性交代＋预告案例 | Seed-Evolving 文章从评论区与同事推荐写起，说「起初我也没咋在意」，测完发现「还真能打」，再交代单版本自动升级的特性 | 模型或工具是被读者反复点名要求测的 | 只写「很多人让我测」却没有自己的判断变化 |
| 个人状态＋具体痛点＋反转＋工具对比＋优势预告 | UU远程文章先写自己又进入写代码上头期与多任务并行，再点出「AI在干活但人很难离开电脑」的矛盾，随后反转成在电脑前时间变少，最后与其他远程工具对比 | 工具解决的是「人在等待中被困住」这类不易察觉的痛点 | 痛点描述笼统（如「效率不高」）；或反转没有具体证据 |
| 承认现状＋转折＋三个具体故障＋先给对比＋抬高价值 | 长视频 Skill 文章先承认单看几秒已经很强，再给三个人物与道具穿帮的具体画面，随后用一组前后对比证明有效，最后说价值不止于「记住杯子别乱跑」 | 读者对现状有普遍认同，需要先破再立时 | 故障写得抽象、看不出穿帮；或抬高价值后正文没有对应内容 |
| 数字冲击＋核心理念引述＋翻译成大白话＋主动回应质疑＋具体例子 | DSH 插件文章先给星数与插件数量，再引官方架构文档讲「一切皆插件」，翻成「从里到外没有一块零件是焊死的」，随后回应「技术人自嗨」的质疑并给两个具体需求作例子 | 涉及有门槛的技术理念，需要让非专业读者也懂 | 只引术语不解释；或回避读者可能的质疑 |
| 热点＋价格吐槽＋不服气＋失控式展开＋先给全家福＋互动邀请 | 配件设计文章先吐槽官方配件配色少、壳卖到999，用一句对仗调侃收尾，再说「我有点不服」，随后原本只想换壳却把手写笔与支架都做了出来，先给全家福，最后请读者评判谁更像卖999的 | 有现成参照物可对比，且作者真的做出了东西时 | 只吐槽没有作品；或「失控」是修辞而实际产出很少 |
| 产品线铺垫＋提问差异＋官方定位＋承认拗口＋自设对象并免责＋先给效果 | 火锅店全案文章先交代此前评测过同公司多个产品，再问「市面设计Agent这么多，为什么再出一个」，引官方定位后承认「可能还是有点拗口，不着急，我今天带着大家用一个完整的项目来体验」 | 新产品的官方定位抽象，需要用实例说明差异时 | 只念官方定位；或自设对象却不说清是虚构、易与真实品牌混淆 |
| 行业节奏＋可用性限制声明＋本篇性质声明＋情绪调侃 | Astra 演示汇总文章先写两个模型发布时间贴得紧，随后明确「我们现在还用不上……只向少数组织开放」，再写「所以这篇文章暂时做不了实测，我先把公开的功能和X上流出的演示逐个看一遍」 | 拿到素材但自己还用不上产品时 | 省略性质声明，让读者以为在做亲测；或只讲限制不给可读内容 |
| 行业痛点＋机会数字对比＋个人搁置的念头＋说明具体难在哪＋先给对照 | 出海转绘文章先写国内备案收紧、流量倒挂、做完发不出去，再给海外机会与「在国内挣一万的片子，搬到海外能挣一万五」，随后说自己想做但嫌麻烦，并讲清难在哪 | 选题解决的是「知道有好处却一直没动手」的处境 | 只讲机会不讲难点；或数字无来源、无时间口径 |
| 数字生命卡兹克：事件＋官方定调＋情绪吐槽 | 该篇先给发布的时间点，引官方一句话（「全球最智能且最对齐的模型」）定调，随即转为吐槽厂商只向部分组织开放、自己买了会员却不能用 | 新模型刚发布、自己还用不上时 | 情绪占比过高会盖过信息；引语来源必须可查 |

## 案例推进

- **一个标准贯穿多任务**：百度搭子文章用「交回来的成果能否继续用」连接长程活动、自媒体链路和财报报告。适合功能多、但有统一读者问题的工具。
- **跨能力展示**：GPT-6 Astra 文章用五个差异较大的任务维持新鲜感。适合首发盘点，不适合作为统一条件的横向能力排名。
- **成功后加测并保留失败**：拼图案例第一张大体成功后换风景照，第二次明显失败。适合寻找能力边界；需要交代两次输入差异。
- **先定义可见效果再对照**：布丁案例先描述圆润、拖拽、回弹和晃动，再看不同模型的产物。具体执行可参考 [[topics/AI写作案例库]]。
- **从硬指标扩展到真实场景**：Qwen-Image-3.0 文章先测中文字与高密度信息，再进入海报审美、三页 UI 和宫格分镜。每换场景要重新说明验收点，不能拿一套模糊标准评价全部案例。
- **问题驱动的二次生成**：汉服小字、长文图谱结构和分镜动作都有「首轮哪里错 → 补什么限制或动作说明 → 再看结果」。写稿时保留首轮失败，说明是否还有未解决问题。
- **基础操作到轻重两例**：WorkBuddy 教程先安装和权限，再用生活工作台让新手得到可见成果，最后用 PDF 抽取匹配说明工作价值。复杂 Agent 教程可借这种递进；若读者已有基础，可把最短路线和成品放前面，再展开完整界面。
- **按能力重心换案例**：Qwen3.8-27B 的三个案例分别考规则翻译、文档理解加全栈交付、空间算法与实时计算。同一产品的多案例应换能力维度，而不是把一件小事拆成三段。
- **给肉眼难辨的问题设可判定检查**：落沙案例把每条物理规则写成一条能判对错的检查（是否瞬移、是否固定偏向、是否跳格、是否只溶解一格）。适合结果大致能看、细节容易出错的项目。
- **先划适用条件再讲产品**：Buzz 文章先声明多 Agent 不一定更好、协调要花精力，并给出两类适用场景，再进入教程。适合结论有前提的工具类文章，能避免读者误用。
- **翻车放在成果之前**：Buzz 文章先写全员等指挥、前端未确认后端就开工两次翻车，再给跑顺的流程。读者会把后面的流程理解为对前述失败的回答，而不是单纯成功展示。
- **失败各产出一条规则**：每一步翻车都对应一条可执行规则（协调者即瓶颈、不能全自动接力、写代码的不能自己验收），而不是只写「踩了很多坑」。
- **先给工业化参照再给 AI 作品**：Pixmax 文章先讲几十人动作组一个多月磨两三分钟打戏，再展示自己 75 秒的 AI 成片。这个顺序让读者既能判断差距，也不会低估 AI 作品的门槛。
- **实测在前、推广在后，且推广先讲困境**：该篇把制作流程与成本讲完，才进入企业版功能与充值活动，且每个功能都对应作者自己的对账与协作痛点。需要读者自行分辨效果证据与产品说明；写自己的推广内容时可参考这种顺序，但不能把功能介绍混进实测结论。
- **如实报告没有差异**：Image2.5 文章承认自己两轮小样本编辑对比「差距不大」，给出样本量与场景的可能解释，再引用官方大批量样本作为对照。这类诚实结论比强行制造胜负更可信，也更容易被读者当成有效信息。
- **固定模型只换一个变量**：DeepSeek Harness 的案例一固定同一模型，只替换三种 Harness，让「Harness 对结果影响很大」这个结论有来源；作者同时限定单案例不能代表全部。需要补的是机器、网络与推理强度等条件说明。
- **把故障过程写完整**：自定义 Agent 案例记录模型反复执行占位动作、作者终止任务并追问原因、改走文件系统路径后完成。故障不隐藏，还产出一条可执行建议（连续相同操作时及时打断）。
- **先讲透痛点再让工具登场**：天才机甲师文章先解释为什么 AI 视频像抽卡——即使写明低角度仰拍，模型对机位高度、主体位置与画面留白的理解也未必一致，结果可能很不错却不是要的那一条——再引入先摆机位再生成的做法。痛点讲不清，工具介绍就会变成功能罗列。
- **用职能解释专业概念**：把景别解释成远景给信息、中景给主体、近景给情绪，并说明「观众先理解身处怎样的世界，再逐步接近机甲，最后感受到它活了过来」。用读者能体会的作用替代术语定义。
- **开头标准与正文段落一一对应**：豆包爱学文章开头提出学习还包括串起零散知识、发现自己没懂、愿意继续探索，正文三部分分别对应这三点。立标准容易，难的是让每段都回扣标准。
- **用「原来是什么／改成了什么」讲设计**：该篇对比打开产品先看到地图而不是课程目录，再用从城市看同地多诗、从诗人看迁徙轨迹两组对照说明设计意图，比单纯描述界面更能解释价值。
- **按难度分组给结论**：updream 文章分静态、简单运镜、复杂运镜三组，并坦白第二组「提示词也能控得差不多」，把方法的价值限定在复杂场景。分组给结论能让读者判断值不值得学，比一句「效果很好」有用得多。
- **对照要点报次数与失败表现**：该篇给出纯提示词版跑了四条、相对满意那条仍缺关键元素，白模版一次完成。报次数与具体缺陷比只给结论更有说服力。
- **把战略变化写成因果链条**：美图文章把转型归为技术架构→产品形态→商业模式→组织机制四层，并强调是环环相扣的链条而非并列四点。链条能让读者追问哪一环最脆弱，并列清单则只能逐项点头。
- **先分清用户诉求再上数据**：该篇先用「想让自己好看一点」与「要做出来能用的东西」区分两类产品，再给收入与付费增速。数据放在分类之后，读者才知道每个数字对应什么业务。
- **框架要落到具体压力**：文中用 SWOT 与波特五力分析竞争位置，但重点放在供应商议价权、买方分化与替代品集中这些具体压力上。只放一张框架图不算分析。
- **先帮读者分清同名产品**：Qoder 文章在进入案例前用几句话区分 CLI、IDE 与新的桌面端，解决了读者最容易卡住的第一个疑问。多产品线题材适合在开头做这件事。
- **提示词写全三部分**：该篇三段提示词都包含输入（照片／草图／音频）、交付清单（要哪些具体功能）与自验要求（在浏览器逐页操作测试）。把「怎么算完成」写进提示词，比只描述想要的效果更可执行。
- **按输入类型递进难度**：真实照片（结构清晰）→ 手绘草图（细节缺失）→ 音频（跨模态且带主观判断）。用输入的不确定程度安排案例顺序，能自然体现能力边界。
- **把中断次数当长程指标**：八小时任务记录中断三次，并逐条说明原因，其中电脑休眠导致的明确写「这锅确实不该模型背」，最后得出异常中断只有一次。把非模型原因剔除，指标才有意义。
- **三类能力各配一个案例**：长程结构化（整本书做知识图谱）、前端加推理（跨页面线索的游戏）、检索与交叉验证（事实核查）。用能力类型而非常见题材划分案例，覆盖面更清楚。
- **用敏感场景测不敏感指标**：远程办公看不出延迟，就改用平板玩对延迟敏感的游戏来验证。测不出来的指标，换一个能把它放大的场景。
- **按场景而不是按功能罗列**：该篇把十余项功能收进「手机写代码／办公应急／移动端游戏」三个场景，每项功能都对应一个具体麻烦。功能介绍按场景组织，读者才知道什么时候用得上。
- **用完全相同的输入做对照**：长视频 Skill 文章拿同一个故事，分别带 Skill 与跳过 Skill 各生成一版，观察单段与连起来看分别如何。对照要固定输入，才能把差异归到方法上。
- **先给一组对比再抬高价值**：先用最直观的前后对比证明有效，再说「如果只是这样也没什么意思」，引出真正的价值。对比负责取信，抬高负责给读者继续读的理由。
- **把技术理念翻成大白话**：DSH 插件文章引完官方文档后立刻补一句「翻译成大白话就是：从里到外没有一块零件是焊死的」。术语留给专业读者，白话负责让所有人跟上。
- **主动说出读者的质疑**：该篇替读者写出「这是技术人的自嗨炫技，因为普通人根本不懂代码托管」，再给替代角度。先承认质疑比等读者在心里反驳更有效。
- **教程与实录并存**：前半段回答「你可以装什么」，后半段回答「我怎么做的、遇到什么问题」。读者既能马上动手，也能看到完整过程与失败。
- **每款方案配一句适用人群与一句保留疑问**：配件设计文章给浅色款写「耐不耐脏得等实物出来再看」，给两款笔分别说明适合谁。概念方案阶段主动列出未验证项，比假装已定稿更可信。
- **用「失控」制造阅读期待**：原本只想换壳，结果连笔、支架、模型与展示视频都做了。适合脑洞类文章，但要在结尾把概念与实物的界限写清。
- **每一步都声明继承哪套规范**：火锅店全案的每个环节都写「沿用已经确定的 Logo、配色和字体」。这样「一整套」才是链条而不是产物堆叠，也便于读者检查风格是否真的统一。
- **自设测试对象并加免责声明**：作者虚构「河底捞」做测试，并明确声明与海底捞无关。用虚构品牌演示时，这一句是必要的。
- **承认官方话术拗口再改用实例**：官方定位不好懂时，直接说「可能还是有点拗口」，然后用一个完整项目代替解释。这比反复复述定义更省读者力气。
- **无法实测就先声明**：Astra 演示汇总文章在开头连写两句——「我们现在还用不上」与「所以这篇文章暂时做不了实测」。先用不上产品时，这两句是必须的，它决定了后面所有内容该被当作什么读。
- **案例按能力层级组织**：该篇分成「能交付完整可玩的产品 → 空间理解与视觉判断提升 → 开始走进专家工作台」三层，而不是按时间或厂商罗列。层级能让读者看出变化的方向。
- **拒绝用精选演示下胜负结论**：作者列出三条理由——结果互相矛盾、条件未公开、展示选择会影响结论，因此「在自己真正用上以前，我不太想凭几段精心挑选的视频宣布谁赢了」。这个处理方式可直接迁移到任何只有演示没有实测的题材。
- **把收益差翻译成具体数字**：海外收益「普遍比国内高四到五成」被写成「在国内挣一万的片子，搬到海外能挣一万五」。抽象比例换成可想象的钱数，读者立刻能感受到差别。
- **同一素材换市场再跑一遍**：美国版做完后，作者拿同一条源片做日本版，用来检验「它对不同市场的理解到底有多深，还是只换个语言和人脸」。同一素材的二次对照比换新素材更能暴露差异。
- **把大白话解释做成固定动作（卡兹克）**：该篇几乎每节都先翻译专业概念再上数据——OSWorld 是「把 AI 扔进一台真实电脑让它自己干活」，ARC-AGI-3 是「没有说明书、没有规则，自己玩着搞懂规律」，无思维链数学指标是「不给模型写长思维链的机会」。这与个别处翻译不同，是贯穿全文的习惯。
- **用人类工作经验解释模型能力（卡兹克）**：把「主动性」翻译成好同事的处理方式——无关紧要的自己判断，影响方向的才问你；再补一句「带过人就知道这个能力非常珍贵」。
- **先承认过去的短板（卡兹克）**：讲审美时先说「过去 GPT 的审美就是一坨屎」，再讲这次变化。先承认旧问题，读者才更容易相信后面的提升不是吹捧。
- **编号小节到底（卡兹克）**：全文用「一.」到「八.」编号，加一节「写在最后」。编号适合资料密集的长文，读者能按序号跳读；代价是段落之间的过渡较弱。

这条推进方式的具体测试问题、调整技巧与提示词片段见 [[topics/测评问题与实战技巧库]]。

## 观点与结尾

一篇案例文至少把**看到了什么 → 据此能判断什么 → 仍不能判断什么**分开。百度搭子文章结尾回到交付标准，保留用户自己的验收权；GPT-6 Astra 文章承认案例不能证明 AGI 已到来，但后续安全议题与前文测试联系较弱。选结尾时，应优先回答开头提出的问题，再决定是否延伸到更大的议题。

Qwen-Image-3.0 文章的结尾把开头的强烈惊喜拆成「中文字和信息密度较好，审美和语义严谨度仍有限」。这种**先展示情绪、最后分维度校准**值得借鉴；「国内最强平替」等排名话语仍需更充分比较。

WorkBuddy 教程从两个任务收束到「任务本身由人提出」。这是教程的价值判断，但对零基础读者还可进一步补一个当天能做的最小任务，形成明确下一步。

Qwen3.8-27B 的结尾承认速度慢、部署踩坑，把结论落在部署门槛与硬件成本，并写明「未必全面超过 Opus 4.6，也不需要如此」。这种**用成本与门槛收束、不把它写成全面胜出**的方式，比单纯罗列能力更经得起追问。

Buzz 文章结尾把协作问题归因到分工与把关，提出「多 Agent 协作的核心在人的管理」，再用取经团队作比喻，最后向读者征集「给 Agent 立的一条规矩」。这种**把方法上升为人的能力、再用提问收尾**的方式适合教程与观点混合的文章；比喻承担的是降低理解成本，不承担证据。

Pixmax 文章的结尾先明确「《凡人修仙传》那种量级，我们暂时做不到」，再把成本可算、账目可查、续费可预期三件事定义为「才叫生产」。这种**先划掉做不到的部分，再把可控条件说成生产标准**的收尾，比直接宣称产能提升更容易被接受；其中只有成本与记账有文中数据支撑。

Image2.5 文章的结尾按「官方说法 → 个人体验 → 推荐尝试」排列，性能三项均标注为官方口径，个人结论只落在「快」与画板新颖；末尾再补一段把猫图发到群里的插曲，并写「这可不是水军」。把厂商口径与个人体验分开放，是首发评测里值得照做的收尾结构。

DeepSeek Harness 的结尾直接说耗时比接其他成熟 Harness 多、产品还在公测、自己有些失望，并给出一个具体原因（期望被模型能力拉高）。不达预期时给出归因，比笼统说「期待正式版」更有信息量。

天才机甲师文章的结尾先承认「爆款无法复制，但生产方法可以」，再给三条可迁移经验，最后用对照句式收束：「让AI生成一台机甲，已经不难。让这台机甲出现在一个完整世界里……才是AI内容工业化真正要解决的问题。」这种**用对比句抬高真正的难点**的收尾适合方法总结类文章；结尾仍带产品推荐，读者需要自行分辨。

豆包爱学文章的结尾在给出价值判断（从提供工具走向搭建环境）之后，主动列出三个自己无法回答的问题：看得有趣是否等于真正学会、AI 生成的意境画面会不会限制想象空间、这些体验能否转化成记忆与知识迁移。**体验类文章在结尾列出未验证项**，比替产品下效果结论更可信。

updream 文章的结尾把行业竞争总结为「画质基本被模型解决了，开始比的是控制力」，并把差别落在能否把脑子里的画面精确交给模型。用一句行业阶段判断收尾，适合方法类实测；条件是正文确有三组递进的证据支撑。

美图文章的结尾先在正文里列出三点无法回答的质疑（试错成本、用户分流、壁垒厚度），再给出总结判断与一句可复用的话：「时代不一定奖励技术最领先的人，但一定会奖励把用户问题解决得最清楚的人。」**先承认风险再给判断**，在商业类文章里比直接下结论更稳。

Qoder 文章的结尾把定位说成「适合有想法、能看出成品好坏但不太会写代码的人」，也说明对专业开发者的价值（保留足够的 coding 过程证据供查验）。**按读者类型分别说明适用性**，比笼统说「人人可用」更有用。

Seed-Evolving 文章的结尾先给结论（能打且好用），再说明最强的长程任务能力，随后列短板（多 Agent 并行会中断变慢、3D 材质光影不足），最后收在适用项目类型上。**结论、强项、短板、适用条件四项齐全**，是模型评测收尾的稳妥结构。

UU远程文章的结尾把最常用的三个功能与完整流程串起来，界定适合人群后，坦承自己长时间写代码时仍愿意坐回电脑前。**推荐工具时主动划出自己仍会用旧方式的场景**，比全篇说好用更容易被相信。

长视频 Skill 文章的结尾承认「AI视频现在依然很看运气……这个Skill也做不到让每一次结果完全照着预想来」，只用「少抽很多次卡」界定功效。开头说「彻底解决同类的问题」，结尾降级为「明显减少」——结尾的严谨版本才是应该采用的表述。

DSH 插件文章的结尾先泼冷水（预览版、插件不兼容与安全性存疑），再抬到理念（一切皆插件意味着用户也在参与决定 AI 长什么样），最后用历史对照收束（敢把「核心可换」当理念的产品不多，上一个这么做的是 Emacs）。**先讲风险再讲愿景**，让愿景不至于像宣传。

配件设计文章的结尾用自嘲收束，并明确「这些只是概念方案，成品好不好用要等打样」。**脑洞类文章的结尾必须交代交付物处于哪个阶段**，否则读者的期待会停在实物上。

火锅店全案文章的结尾在给出能力边界后收在一句反差上：「Miora能帮你把店做得像个品牌，却不能帮你把味道做好。真正决定人们会不会再来的，还是味道。」**把工具能把什么、不能把什么各说一句**，是展示型文章避免变成软文的关键一步。

Astra 演示汇总文章的结尾先给趋势判断（交给模型的任务已经进化），再明确「AGI 是否到来还太早」，并把验证方式落到自己真正用上之后——「看它能不能连续几个小时把事情做完，这个答案会更具体」。**把结论的验证条件写清楚**，比直接站队更有信息量。

出海转绘文章的结尾把价值落在门槛性质的变化上：出海以前是资源门槛（找海外团队重拍几十万起步），现在变成工具门槛（会用就能试）。**用「门槛类型变了」概括工具带来的变化**，比列举功能更能说明意义。

卡兹克这篇的结尾是**观点升华＋固定互动模板**：先把 AGI 说成「一道渐变的灰色旅程」，再用「也许没有降临的那一天，只有某一天我们突然发现它已经在我们身边很久了」收束，随后接点赞在看转发星标的三连请求与署名邮箱。这种收尾依赖账号既有规模；新账号更适合路人甲TM 那种「能力边界＋下一步建议」。

## 写作时如何调用

先到 [[topics/选题问题库]] 确定读者问题，再到 [[topics/AI写作案例库]] 找真实可做的任务。按任务性质选钩子和推进方式，最后用 [[topics/观点与表达库]] 与 [[topics/证据与边界库]] 检查判断是否有根据。现有 [[concepts/公众号写作风格DNA]] 是本账号的写作规范；本页是外部文章的观察素材，不能自动覆盖规范。
