## 这批样本怎样写

六篇署名时间从 2026 年 2 月到 9 月，跨度半年，题材从桌面 Agent 到多 Agent 框架再到 3D 网站，差别很大，但结构习惯稳定。

### 标题与开头

标题常把产品与成品并置，制造具体画面感：“桌面端 Agent 强势来袭，自动做 PPT，视频”“用 GPT6 + Hyper3D MCP 搓 3D 个人网站”“万字保姆级教程”。也用数量与合集做承诺：“8 种神仙用法（建议收藏）”。开头固定是“这是苍何的第 N 篇原创”加自我介绍，随后用一句场景把工具拉进读者处境：整理下载文件夹、给个人网站换个玩法、想给自己的需求做个看板。“第 N 篇”既是栏目，也是作者长期连载的信誉标记。

### 案例如何推进

六篇都偏横向铺开：同一款工具连着做七八件小事，每件给结果截图，读者一次看到能力面（CH-01、CH-06），或者把一条长链路分成建能力、装工具、跑流程、给机制四段（CH-02）。喜欢先给结果再补过程：CH-02 先放竞品价格监控看板成品，CH-05 先逛一遍 3D 小宇宙。

### 解释与判断

作者习惯把“不满意的具体点”写出来当迭代钩子：角色“眼神有点呆”、移动“像幽灵一样在星球表面漂移”、PPT“改完还不如之前”。这类观察比“效果很好”更有信息量。涉及模型与框架时倾向引用官方介绍（本地安全运行、缓存命中率、MiMo Code 框架），属于转述，需要与自己的观察分开。

### 结尾

两段式：先给一条可复述的能力判断（“AI 工具值不值钱，不看它能聊什么，看它能交什么活”“框架负责协调，模型负责执行”），再抬到技术应当解放人、夺回时间的价值判断，最后留互动或名额引导。这类收束与正文的证据密度不匹配，迁移时只留前半句。

## 值得迁移的编辑动作

- 开头用具体场景切入产品，比直接讲参数更容易让读者对号入座。
- 能力不明确时，用“先接一个低成本测试物验证链路，再做正题”的顺序降低教程门槛（CH-05 用头盔测试 MCP）。
- 每次返工都写清具体现象（哪一处不对、哪里没对上），读者才知道该检查什么。
- 教程类文章先说自己的限制，再铺案例，读者更容易判断值不值得跟（CH-06 承认只有教程类视频做得好）。
- 官方数字与免费权益一定要带条件，模型评价要标成作者体感。

## 证据与迁移边界

- 蓝皮书浏览量 280.37 万、GEO 诊断 9.91 万次使用，是作者自有项目数据，不作为教程质量或产品能力的外部证明。
- 官方介绍的能力（本地运行、缓存命中率、模型框架）属转述，文章没有独立验证。
- 演示视频、模型预览与页面效果本次未核看，只能按作者描述记录。
- 30 分钟、40 分钟、5 分钟、10 分钟等耗时是作者本机个案，不能当速度基准。
- 邀测名额、免费模型、Credits 与会员折扣是活动信息，有时效。
- 结尾的“解放人、夺回时间”“一人公司”是价值判断，不作结论迁移。

## 与已有对标的关系

与路人甲TM的差别在于选材：路人甲多以单个作品或项目贯穿，苍何偏向能力面横切与教程合集。与洛洛AI说、小林coding那种以模型更新为节奏的账号相比，苍何的更新对象更多是桌面 Agent、连接器与工作流。技术解释的密度高于大鼻哥嘚巴嘚这类合集型作者，但同样大量依赖截图，文字解释有时让位于演示。
