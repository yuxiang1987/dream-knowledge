# 公众号文章切入点方法

## 本次补充的编辑建议

依据是用户在 2026-10-01 本会话提出的偏好与助手推导，尚无对应 raw 原始资料；不是对标文章的已证实规律，也不记录为已验证模型成绩。

- 节日与季节：提供当下使用场景。十一北京宣传页测呈现与滚动；行程规划器测资料与约束。节日不是具体新闻，不能编活动或拥堵。
- 人物/品牌/赛事：先核实具体事件，再选择海报、原创涂装、参照图三维展示或官方数据分析。「张雪机车」只作为用户给的线索，不在本页断言战绩。
- 名称隐喻：如太空兔与月球基地，提供创意记忆点；看图、驾驶和碰撞分别才对应具体能力，不根据名称猜身份。
- 视觉玩法：滚动叙事、果冻回弹、落沙，把抽象感觉改写为操作与规则。
- 常青痛点：没有合适热点时测试真正的失败或旧任务，不强蹭。

推荐时优先能力匹配、素材可得、成败可验、展示价值和成本。避免反复推荐公众号素材整理。未测用计划口吻；已测用真实结果，允许保留失败。

## 2026-10-16：最新60篇的切入点归纳

已有单篇拆解记录了开头钩子、读者问题和案例结构；此前没有把它们归并为一套便于每天策划的入口。本节对照最新60篇研究台账，选取代表文章，将切入点归纳为**8类**。这是本知识库的编辑归纳，不是路人甲本人宣布的固定分类；类别不互斥，未给60篇逐一标记这8类，也不统计占比、传播效果或成交效果。

### 先区分三个层次

- **文章类型**：整篇文章怎样完成目的，如实战、解决问题、整合、教程。类型主要回答怎么展开。
- **选题切入点**：为什么现在想做这件事，读者为什么愿意看。可以出现在首段，也可以在案例引入处，不能把案例动机一律当成原文首段。
- **开头表达手法**：先放成果、吐槽、自嘲、设问、比喻、低预期反转等，负责把切入点写出来。同一个切入点可以换手法。

### 他怎么把入口接到产品

这批样本里可以提炼的连接顺序是：**一个读者能理解的事 → 想做的作品或想解决的疑问 → 选择适合的产品能力 → 过程与结果 → 适用判断或使用引导**。这是写出来的叙事顺序，不代表作者真实接单时也是先有需求再选产品；商单策划也可以从产品能力反向寻找合适案例。

三个代表例子：

1. **MVLAND**：听歌有画面 → 想拍旧居告别的动作 → 使用音乐视频工具 → 展示从分镜到修改的过程。兴趣和情感本身就能支撑案例，不必加上老板催稿、客户需求或节省工时。
2. **WeaveFox**：熟悉验证码 → 产生机器审问人的荒诞疑问 → 把想法写成游戏规则 → 实际试玩并追加戏剧转折。这里的吸引力来自想法与互动，游戏规则不是可靠的人类识别实验。
3. **豆包工作**：产品有何不同的疑问 → 拿父母旅行这个具体使用对象试 → 发现长文不适合阅读 → 改交付形态。不能把作者的父母、经历或产品权限移植成自己的事实，历史入口也需按当前客户端核对。

另一个容易误读的例子是 [[sources/Miora火锅店品牌全案文章拆解]]：**原文开头先问同类设计Agent这么多，Miora有何不同；随后才用虚构火锅品牌，把多种设计物料连成完整项目。**它同时有产品差异疑问与自设项目，不能简化成作者真的想开店。

### 混合入口、线索来源与开头手法

- 同一篇可以混合：iPhone配件是新品热点＋对方案不满＋概念设计；OiiOii是节日需求＋虚构品牌项目；updream是创作兴趣＋已有卡点。
- 读者留言、朋友推荐、作者旧文是发现题目的**线索来源**，可以引出以上多种入口，不硬塞为第九种同层切口。本批没有采集完整评论区，不能说已验证评论需求频率。
- 先给成品是**开头手法**。它可以配热点、兴趣、项目或痛点；有趣、实用、反差、情绪也不等于互斥的文章类型。
- 原文出现产品、使用引导或作者账号级商单自述，不足以验证该篇付款方；也不能据这些案例断言哪类最赚钱。

### 用于程序员拾梦次日选题

不要把选题默认收窄成整理文件或检查Agent错误。先围绕当前能用的产品，分别问：有没有自己想做的作品、真实生活或工作任务、值得回答的能力疑问、可以继续推进的旧项目？再看哪一个读者容易理解、产物值得展示、当晚与次日上午能完成。

此前准备的豆包读书会资料包属于任务场景候选，是明确标注合成的测试材料；并非用户已确认的真实需求、已锁定题目或已完成实测。它只覆盖八类中的一类，不能因此认定它最优。可与兴趣作品、旧项目延伸等入口比较后再锁题，参见 [[topics/公众号每日选题决策]]。

2026-10-16后续反馈：用户认为该题不够好，希望结合双11。已将读书会降为备选，在每日决策页比较消费者选择、商家上新准备和互动桌面改造三种切口；未将任一候选写成用户已确认或产品已完成。此处暴露的流程缺口是此前没有充分比较当前节点与阅读动机，不能仅用素材易得替代选题价值判断。

## 外部资料与Skill的分工

以下是2026-10-16针对用户提问的流程设计建议，依据本页样本与当前已安装Skill的检查，不是原作者口述，也不是已实现的采集系统。

**优先完善案例策划与按需检索，再根据实际缺口接外部数据源。**八类入口不等于八套数据接口；外部资料提供线索与事实，Skill负责把线索转成适合本账号的读者问题、具体案例和实操安排。外部资料可以由用户提供、人工阅读或普通检索取得，不必先开发API或自动采集。

| 入口 | 是否依赖新外部线索 | 优先输入与核实动作 |
| --- | --- | --- |
| 热点与熟悉的IP | 通常需要核实当下事件；熟悉IP本身不必是新热点 | 原始发布与具体作品；对标文章只作发现线索，不证明当前热度 |
| 节日与业务节点 | 固定节日可直接策划；具体活动需核实 | 日历、实际业务安排、官方活动规则；不编造优惠 |
| 生活与工作中的麻烦 | 可以不依赖新外部线索 | 用户真实任务、截图和现有资料；任务涉及的时效事实仍需核实 |
| 个人兴趣与情感表达 | 可以不依赖新外部线索 | 用户明确的兴趣、自己的素材或想表达的画面；第三方素材另核来源与使用条件 |
| 荒诞脑洞与自设项目 | 可以不依赖新外部线索 | 明确标注的原创设定与可展示的原型；能否实现要试跑，不凭设想承诺 |
| 新品变化与能力反差 | 需要现行能力依据 | 官方更新说明、帮助文档与实际客户端；会员和权限按用户当前状态核对 |
| 选择困惑与认知疑问 | 视问题而定，产品横评通常需要 | 现行版本、条件和自己的同题记录；历史榜单不替代当前比较 |
| 旧项目卡点与继续迭代 | 优先本地记录；涉及新能力时再补查 | 已发文章、源文件、失败记录、评论和真实实操；每篇需要新增问题与证据 |

### 策划能力应补什么

- **读取上下文**：产品权限与素材、对标案例库、账号已发作品与用户偏好。已有60篇是案例结构样本，不能自动充当最新产品说明或当前客户预算。
- **从不同入口产生少量候选**：例如3个具体案例，而非同一整理文件任务换3个标题；无需把8类每天各做一遍。
- **按候选补查**：只有需要最新事件、功能、价格或活动规则的题才补查对应资料；记录来源、发生/发布日期、检索日期与待核字段。没有可靠来源时换用本地素材候选或写明未知，不把未知当零、编造评论或伪装热点。
- **按可执行性筛选**：同时看读者兴趣、能力匹配、可展示成果、与旧文的新增价值及时间成本；商业关联看能体现什么产品价值，不将出现品牌视为商单确认。不预设精确分数或收益。
- **交给实操**：推荐题、具体切口、最小案例、所需素材和待验证问题。真实结果回来后再确定标题与写作主线，不预写成功或节时。

少量重点产品的官方变化、定位相近账号的新文及用户真实评论，可作为后续优先补充的三类外部线索。先观察人工/按需检索是否反复遇到遗漏、频率或规模问题，再决定是否建设自动采集；本建议不代表已接通任何来源、已采评论或已安排持续监控。
