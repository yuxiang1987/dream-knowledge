# 卡兹克Astra首轮实测文章拆解

来源：`raw/article/kazike/实测GPT-6 Astra：曾经的那个OpenAI，回来了。.md`，原文署名时间 2026-09-05 19:39，卡兹克、AIZ小朱。本页分析作者自述实测的文字，不是知识库重新实测；截图、动图与产物未核看。

## 它讲什么

主问题：新模型真正开放后，在开发、电脑操控、视觉与中文写作中有什么变化？与此前的资料解析不同，本篇以作者一下午多会话体验给出初步判断。

## 关键要点

- 开头先讲睡过发布、读者催更和额度准备，把抢时效变成人物故事；接着先给“综合水桶、追平Fable级”的强结论，再分能力说明。
- 在评测前先讨论规则迁移：作者认为为旧模型写的密集限制可能阻碍新模型，给出自己的 AGENT.md 和审查冲突、重叠指令的提示词。本页仅把它视为文章素材，不修改本库规则。
- 速度部分用自己不同任务的历史耗时作参照；前端部分列出月面车、家居建筑、参考图复刻与发动机等任务，并给出部分完整提示词。
- 代码部分用同一项目、同一审查提示词比较两代模型发现问题的深度，描述修复、CI、部署和需要人确认的三项体验改变；同时介绍实验性跨窗口笔记与历史检索。
- 操作 Blender 仍被作者承认“不太好控制”。写作部分区分白描故事与科普续写：前者改善，后者仍重复解释、缺少留白与分寸；建议用两三篇精准范文，而非期待断代提升。
- 结尾回到作者对 OpenAI 与 Codex 的个人关系，以“Welcome back”呼应标题。

## 写法与可复用方法

有效结构是**结论先行 → 使用前置条件 → 分能力展示 → 同任务对照 → 明确短板**。每个案例先描述肉眼可判的目标，读者才能理解效果差异；写作能力单独给负面观察，避免“新模型全方位胜利”的单一叙事。

同项目审查和同提示词是有价值的控制思路，但要进一步提供模型设置、环境、修改前项目快照、失败次数和产物，才具备可复现比较意义。

## 证据边界与疑问

所有历史模型名、可用范围、额度、实验配置和能力结论都保留为原文口径。不同任务的耗时不构成严格速度基准；发现问题多不等于问题都成立。实验性配置片段的排版与有效性未验证，不能直接当现行操作教程。减少过度限制不等于删除安全、数据和权限约束；本文不采用原文规则覆盖仓库规范。
