## 标题承诺与正文兑现

标题承诺“升级实测”和“字节基模的后劲”。正文确实给出两条创作链路和两道办公题，覆盖面较宽，也诚实指出建模细节与修补色差问题，基本兑现“实测”。但“升级”缺少 Seed 2.1 旧版、其他模型或固定基准的同题对照，无法量化 0915 增益；“后劲来了”主要依据当前版本多场景表现及持续更新叙事，证据强度低于标题语气。没有阅读量、转发率或同口径历史基线，因此不认定爆文，也不把传播归因于产品热度或案例视觉冲击。

## 开头钩子与结构

开头以飞书大会见到企业 Agent 切入，从“豆包工作接手的活越来越具体”转到背后基模，再用版本发布制造时效钩子。随后明确两条主测试方向，并补充办公题，读者很快知道要看什么。转场依次是“一句话小游戏→参考资料复刻复杂游戏→参考图建模→完整场景白模运镜→Seedance 成片→办公 Agent”，难度和工作距离逐步增加。关键承诺句是“**所以，我想动手实测一下，这几个月的进步**”，位于开头版本介绍后；但正文没有真正做跨月对照。第二个关键边界句“**人要花多少时间盯着、纠错**”位于结尾 Agent 讨论段，点中了评估维度，却没有在案例中记录该数据。

## 案例逐项拆解

1. **Flappy Bird，作者亲测**：目标是一句话产出可运行小游戏；输入含控制、计分、碰撞、重开、代码生成素材和单 HTML 限制；操作为 Claude Code 接 Seed-2.1-pro；结果约 16 分钟得到约 55KB 文件并可玩。人工成本只披露发一条初始需求，未说明环境配置、运行验收、修复轮次、token/API 费用和跨浏览器测试。

2. **黄油猫复刻，作者亲测**：目标从截图、录屏和玩法说明复刻玩法并扩成八关；模型生成素材、自动看图核对并修改绘制代码；结果包含八关、选关、教学、存档、结算。缺少总耗时、提示轮次、作者手动设计关卡的比例、失败版本、素材版权处理与可玩性测试人数，因而不能判断“一路补到八关”的自动化程度。

3. **地下通道异常游戏，作者亲测**：输入为参考资料及“无异常前进、有异常掉头、连续八次正确”的规则；操作包含先复刻环境细节，再每轮改一处；结果称有 13 种异常、其中 8 种较细微。缺失异常清单、随机机制、误判率、玩家测试、开发时间和人工修正。

4. **RTS 单位建模，作者亲测**：目标是按经典 RTS 参考图建立磁暴线圈、坦克等模型；模型写 Blender 脚本并渲染；结果是主要结构、位置和比例可对上，作者估计还原七八成，同时承认细节密度和旧化不足。这里“七八成”是主观评分，没有几何误差、面数、材质质量或盲评依据。

5. **白模运镜到 Seedance，作者亲测 + 产品生成链路**：目标测试空间构图、布局、人物动作、镜头控制和变速；先搭简材质 3D 场景并做两段白模，再交 Seedance 2.5 生成不同风格视频；作者称构图运镜可在白模阶段迭代，且保留卡顿感更像实机。未给生成次数、废片率、时长、成本、运动一致性或人工后期。

6. **立讯产业链报告，作者亲测**：输入是年报中收入、客户、供应商截图；操作为 OCR、分析上下游、生成产业链图和风险清单；结果有四张交互图和一张全景图，作者认为可作底稿。未核对数据准确率、推断出处、风险项事实性，也未披露人工复核时间；“可直接作为底稿交付”不等于可直接对外发布。

7. **小米价格页转可编辑 PPT，作者亲测**：输入是现场拍摄且有遮挡的价格页；结果初版含九个真实文本框，能读回核对文字位置，并扩展到七页；局部仍有修补色差。缺少文字识别正确率、版式误差、制作时长、手工修图比例与源文件检查标准。

## 观点、语言、图文与结尾

核心观点是基模持续迭代可提高 Agent 交付复杂任务的可信度。现有案例支持“能完成若干具体任务”和“可形成工作底稿”，不能证明普遍稳定、省人或优于竞品；样本均由作者挑选，且缺少重复运行。语言短句密集，以“先搓几款”“顺手把活干了”降低技术门槛，章节英文字标增强节奏。文字中的 REC VIDEO、参考图与结果图承担可运行性和前后对照的证据入口；本分析只读文字、未查看媒体，因此不验证实际画面质量。结尾从体验回扣 Seed-Evolving，再提出监督与纠错成本，方向正确但没有将该指标纳入测试表。

## 可迁移动作与待实操方案

可迁移的不是“多测几个炫酷案例”，而是把同一模型按**低约束生成—参考资料复刻—跨工具链—办公交付**递进测试，并逐项记录人工监督。

- 目标读者：需要评估模型是否能进入团队流程的产品与自动化负责人。
- 自己的输入：一份固定小游戏规格、三张参考图、一段白模视频、一页财报截图和一张遮挡价格页。
- 第一步：锁定模型版本和环境，先让旧版与新版各跑三次完全相同的 Flappy Bird 单文件任务。
- 观察点：首次运行成功率、需求覆盖率、修复轮次、人工分钟数、成本、重复运行方差；再扩展到建模和办公任务。
- 所需证据：原始提示与素材、完整日志、全部成功及失败输出、人工操作计时、统一评分表和第三方盲评。只有补上这些，才能验证“升级”与“省事”，而不只证明作者能做出成品。
