## 定位、主问题与证据身份

读者是游戏 AI、Agent 执行层和结构化调用的开发者，也包括需要低延迟意图识别的产品团队。主问题是：持续运行的 AI 世界中，能否把高频小决策从通用大模型转给专用意图模型，以降低成本并提高动作落地的确定性。类型为**模型介绍＋64 条基础测试＋四个游戏集成实验**。

证据须逐项区分：作者自建 64 条指令及四个游戏接入属于作者报告的亲测；Maple Hill、OpenRA、宝可梦模拟器是已有系统上的改造，不是模型原生能力；61 个数据集、275.3 万条、19 领域、52 种语言、EMNLP 2026、各项分数及 150ms 延迟均为星辰实验室官方主张；Aivilization 成本说法来自此前第三方采访。数字均未由本库复测。

## 标题承诺、钩子与结构

标题说“AI 小镇太烧钱，这个新开源模型给了解法”。正文确实展示“通用模型规划＋专用模型转动作”的架构，并给出合法动作率，但没有给接入前后 token、GPU、单居民日成本或总成本，因此只兑现“潜在架构解法”，没有证明“更省钱”。开头以实时小镇每个居民不断决策的成本压力切入，再指出现有轻量模型只能判意图、参数仍需开发者补，顺势引出 Xing4.0-29B-Intent 的“分类＋槽位＋JSON”。接着依次是官方能力、64 条测试、算力账推论、四游戏集成、接入注意事项与开源/API 入口，论证路径完整。

## 基础测试与案例拆解

- **64 条中文指令｜作者亲测**：目标是验证意图分类、参数抽取、多轮改口和否定；输入为作者自建、游戏语境的 64 条中文指令，并随请求提供用户话语、可选意图及字段；操作是按固定模板调用并读取 JSON；结果为 57 条意图正确、42 条意图与参数全对，22 条未全对中有 15 条分类对而字段不全。人工成本包括自行编题、定义意图与字段，但未给数据集全文、判分规则、重复次数、对照模型同题结果和耗时分布，难以复现或排除样本偏向。
- **改口与缺字段｜作者亲测**：购买回春散的多轮输入中，数量由三瓶改为两瓶，其余字段保留；缺失信息会留空而非猜测。结果展示了结构化输出的产品价值，但只是个例，未给这两类在 64 条中的分项准确率。
- **AI 小镇｜作者亲测集成**：目标是让居民想法落到已有动作；输入为大模型生成的想法、角色与店铺状态、功能表；操作是 Intent 模型映射“去哪、找谁、办什么”，原引擎处理商家回复与扣款。Walter 07:30 报漏水、08:00 获 90 币报价、10:00 完成，余额 450 降到 360；三居民六游戏小时中 18 次决策有 16 次成为合法并执行的动作。首次失败因功能表未写清，需求被错误填充，修订后跑通。缺少与纯大模型方案的成本、准确率和延迟对照，也没给人工改表耗时。
- **修仙世界｜作者亲测集成**：目标是在长期计划之外插入受伤后的即时判断；输入为当前血量与原计划；操作是在继续或疗伤等有限动作中选择；结果展示旧思考与新状态冲突，并插入小判断。未说明最终选择、后续疗效、样本次数和误判率。
- **OpenRA｜作者亲测集成**：目标是在 RTS 不停机的情况下根据侦察调整目标；输入为战场状态和预设目标；操作是在原计划与候选目标间重排；结果是发现重坦后提高突击目标优先级。缺少胜率、决策次数、延迟实测和基线 AI 对战。
- **宝可梦对战｜作者亲测集成**：目标是把大模型提出的换人或招式映射为当回合合法指令；输入是大模型方案、可用动作与局面状态；操作是校验并结构化后交模拟器；结果声称避免不存在动作且可快速重决策。缺少场次数、非法动作拦截率、胜率和成本。

## 观点边界、语言图文与结尾

核心观点可以概括为“**把一句话变成系统能执行的一张单子**”，该原句在结尾总结中，准确描述了模型角色，而非让模型直接掌控系统。文章也明确指出“**意图和字段要定义清楚**”，位于接入注意事项，且首次失败证实 schema 质量是关键。因而成功不只来自模型，功能表、候选动作、原引擎规则及确认机制都是人工工程投入。

作者由分类比作“选择题”、槽位比作“填空题”，降低理解门槛；时间线和金额让小镇案例具体。图示、截图、滑动区承担返回 JSON 和游戏过程证明，但这里只读文字，无法核对界面或动图。结尾没有夸成通用智能，而是限定于功能固定、需要填参数的系统，并指出否定句风险及不可逆操作二次确认，边界较稳妥。

商业产品入口明确：GitHub 提供语料、权重、SDK 和镜像；天翼 AI 开放平台提供 API，并称有 3 个月、1 亿 tokens 免费额度。卖点是开源、结构化输出、低延迟与槽位能力。正文未明确披露赞助、付费合作或 API 权益来源，合作未知。没有同口径阅读与传播基线，不认定爆文，不把传播归因于“开源”或游戏演示。

## 可迁移动作与待实操

候选是：**在通用模型与业务系统之间加入 schema 约束的意图执行层，并让缺字段触发追问、不可逆动作触发确认**。实操五要素：目标读者为已有工单或设备 API 的 Agent 团队；自己的输入为 10 个真实接口、每个接口必填字段、100 条历史用户表达；第一步先定义意图表、字段、空值和否定规则，只接一个可撤销接口；观察点为意图准确率、字段全对率、追问率、非法调用率、端到端延迟；所需证据为逐条金标、错误分类、调用日志、人工修订时间，以及与纯大模型同任务的 token、硬件和费用对照。没有这些成本数据，不宣称省钱。
