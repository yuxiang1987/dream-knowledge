# 苍何：会用 AI 做图，已经不够了（分享 3 个牛逼设计 skill）文章拆解

### 读者主问题
文章瞄准的不是“哪个模型更会画”，而是非专业设计者如何把模糊想法稳定地变成可交付作品。开头先复述作者过去对 AI 设计的误判：追模型、找 Prompt、期待一句话出图；继而把问题拆成找参考、定风格、修改、交付四段。这一改写有效，因为它把读者的显性诉求“做张好看的图”升级为更真实的流程痛点“怎样反复做、怎样真正使用”。目标读者主要是做公众号、海报、产品原型或轻量品牌物料的内容创作者和程序员，而非已经熟悉 Figma、Illustrator 的专业设计师。

### 标题兑现与钩子
标题用“会做图已经不够”制造能力焦虑，再以“3 个牛逼设计 skill”承诺具体资源。正文确实展示了主题皮肤、动态海报、极简抽象 Logo 等 Skill，但并没有用明确编号逐个说明三者的输入、参数和完整输出，也没有形成严格的“三招教程”。所以标题兑现了一半：兑现了三个可调用方向和大量效果场景，却更像 Lovart 新版工作流体验，而不是三份可以脱离平台复刻的 Skill 教程。开头用“视频号封面被夸、后台有人询问开源网站设计”作为社会证明，但没有留言原文、前后版本或客观审美评价，证据只能支持“作者收到反馈”，不能外推设计质量。

文中 GitHub 项目“登顶趋势榜第一、25.5k star”是作者自述的结果指标，可增强作者有真实项目的可信度，却不能证明 Lovart 是 star 增长的原因。排名为 28 也没有曝光、阅读、分享、增长基线，因此不能称为爆文。

### 结构与转场
整体采用“观念升级—Skill 复用—灵感检索—多种产物—矢量交付—完整海报案例—价值观收束”的演示型结构。前半段连续铺陈封面、Codex 皮肤、旅行海报、动态海报、公众号配图、APP 设计、Logo，优点是场景密度高，读者容易找到自己的用途；缺点是图片承担了主要证明责任，而输入、失败版本和修改轮次缺失，纯文字读者难比较质量。转到“一键转矢量”时，文章从审美效果自然进入生产交付，并明确指出 SVG 暂不能在 Lovart 画布内编辑，这是少见且有价值的限制说明。

后半段用“调用 Skill 前更高频的问题：参考从哪里来”完成关键转场，再以 AI 音乐烧烤海报串起 Pinterest/Google 搜索、浏览器采集、Reference 上传、Agent 阅读活动方案及最终生成。这里最接近一条完整流程。遗憾是文章先展示大量零散案例，再解释核心方法，若把“烧烤海报”提前做成主案例，其他案例作为扩展，方法会更聚焦。

### 案例的输入、操作、结果与人力成本
作者亲测可确认的输入包括文章主旨、开源项目案例提示词、实物照片、海报参考图、活动方案以及一句“根据参考……”的指令；操作包括调用 Skill、采集参考、上传 Reference、生成、改图、转 SVG、导入 Codex Theme/Figma/Illustrator。结果覆盖封面、主题皮肤、水彩拼贴海报、动态海报、手帐插画、APP 设计图和抽象 Logo。作者多次使用“快速”“丝滑”“很快”，但没有记录生成耗时、版本数、返工次数、订阅价格、积分消耗、人工筛选时间，也没有展示失败案例。故只能判断作者亲自使用过这些链路，不能据此比较它与其他工具的效率或成本。

Pinterest、Google 图片搜索、插件采集、支持多种产物、一键转 SVG、国内版开放等属于作者对产品能力的描述；“向所有用户开放”更接近官方状态信息，但原文没有附公告或版本文档，仍应视为未经本文独立核验。文章未说明是否受邀、付费、含推广合作或链接分成，商业关系为未知，不能擅自判定广告或非广告。

### 解释语言与可读性
语言以口语、自我经历和连续举例降低门槛，“设计经验终于可以重复调用”是全文最清楚的抽象：Skill 不是神奇 Prompt，而是风格、流程与交付要求的封装。文章也把“找参考”解释为把难以言说的氛围外化，这比罗列功能更有方法价值。不过“Agent 会自行查看”“理解色彩、构图和氛围”等拟人化说法没有展示它具体读取了哪些元素，容易让读者高估稳定性。编辑时可补一张文字表：参考图贡献什么、必须保留什么、必须避免什么、输出规格是什么。

### 结尾、边界与可迁移编辑动作
结尾从工具功能回到“表达、审美、判断与取舍”，与开头的“一句话出图”形成闭环，也避免把设计能力完全归功于工具。边界方面，文中只明确了 SVG 不能在画布编辑；还应补充素材版权、参考图授权、字体商用、Logo 独创性、动态海报音乐授权、SVG 路径质量、复杂 UI 的可实现性，以及多人使用同一 Skill 后的同质化风险。

可迁移的编辑动作：一是把“3 个 Skill”做成编号卡，每个都固定写读者任务、最小输入、操作步骤、输出格式、一次失败与修正；二是给一个项目做前后对照，而不是仅说“挺满意”；三是量化找参考、生成、修改、导出的时间和人工参与；四是把官方功能、作者亲测结果和作者判断分别标注；五是对任何产品推荐补商业关系声明；六是给出可复制的 Skill 字段，而不只给平台入口。

### 自己的待测方向（待实操）
**待实操：测试“参考检索＋Skill”是否真的比单轮提示词稳定。**读者是每周需要制作 3—5 张公众号封面的非设计专业创作者；自己的输入为同一篇 1500 字文章、同一品牌色与尺寸要求，并准备三张有明确授权的参考图；第一步是在 Lovart 中分别建立 A 组“单轮 Prompt”、B 组“参考图＋普通生成”、C 组“参考图＋封装 Skill”，每组独立生成五次；观察点包括首轮可用率、文字错误率、风格一致性、修改轮次、总耗时、导出 SVG 后的可编辑性和人工筛选负担；所需证据是完整提示词、Skill 配置、屏幕计时、十五份原始输出、修改记录、盲评表和 SVG 导入 Figma 后的节点检查。没有这些证据前，只能把“更丝滑、更可复用”视为作者体验，不能视为普遍结论。

### 本批原文定位锚点

- 定位：正文中段，介绍一键转矢量之后、转入参考来源问题之前

> Skill 最有价值的地方，是把已经验证过的设计方法保存下来。

- 定位：结尾价值判断段

> AI 可以降低创作门槛，但作品的标准不该跟着降低。

### 维度候选（供汇总，不是已验证结论）

待实操维度：设计工作流的“可复用性增益”。面向高频公众号封面创作者，以同一内容和品牌约束，对比单轮 Prompt、参考图辅助、参考图加 Skill 三条链路；第一步固定尺寸与验收标准并各生成五次；观察首轮可用率、跨次风格一致性、修改轮次、总人工时间、SVG 可编辑质量；证据需包含原始输入、全量输出、计时、修改日志及盲评，才能判断 Skill 是减少劳动还是只转移配置成本。
