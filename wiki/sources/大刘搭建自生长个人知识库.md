## 主问题

如何让 WorkBuddy、Claude Code、Codex 等 Agent 与 Obsidian 共用本地文件夹，把网页和本地文件持续编译成带双链、目录、来源与日志的个人知识库，并通过定时任务完成增量更新和健康检查？

## 目标读者

读者需要至少会安装桌面软件、浏览器扩展，理解文件夹与 Markdown，并能判断哪些资料适合交给所用 Agent 处理。最适合已有持续收藏习惯、希望把资料变成可检索写作素材的内容创作者、研究者和知识工作者；完全不愿维护分类规则、来源和冲突裁决的人，即使完成安装也可能很快退化为收藏夹。

## 主研究对象

主要面向已安装 WorkBuddy、希望管理长期资料但不熟悉代码和知识库工程的个人用户；文章也提到企业资料场景，但实际演示主体仍是作者个人电脑上的「书房」仓库，不能据此覆盖企业权限、审计、合规和多人协作需求。

## 证据身份与分项边界

核心证据是作者亲测流程：新建 Obsidian vault，将 WorkBuddy 工作空间指向同一文件夹，生成 raw、wiki、AGENTS.md、index.md、log.md 等结构，再剪藏或拖入资料，要求 Agent 编译并用 index 查询、用定时任务检查。作者报告整套流程含模型运行约 15 分钟，并明确给出自己首次把 raw/ 错填到「保管库」导致剪藏失败的纠错经历。PDF、图片、Markdown 可打开、编译后出现概念页、实体页、来源页、双链、目录和日志，也属于作者描述的亲测结果。Karpathy 的 LLM Wiki 思路、WorkBuddy 新用户 2100 积分、Obsidian 和插件免费等属于文中转述或产品信息，未在本文独立验证。文中关于本地文件夹“不经过任何人的服务器”以及“企业场景，数据也完全安全”的结论证据不足：本地文件存储不等于 Agent 推理、联网剪藏、日志或遥测全程不出端。媒体未看，因此图谱、生长过程和界面截图效果无法核验。

## 标题承诺与开头

标题承诺“WorkBuddy/Claude/Codex + Obsidian”“自生长自学习个人知识库”和“附PDF教程”。正文充分兑现了 WorkBuddy + Obsidian 的搭建、增量编译、查询与定时检查，也说明 Claude、Codex 可沿用同一文件夹逻辑；但没有分别展示 Claude 或 Codex 的真实操作，正文所给全文中也未出现 PDF 获取入口，因此“附PDF教程”在给定全文里没有兑现。开头先以“15 分钟”和写提纲、比对材料、回答新人问题、每日归档、每周查错等结果钩住读者，再把流程压缩为“存资料、编译、查询、检查”四步，能迅速建立收益预期。

## 结构与转场

先给结果、用时和四步总览；随后用“工作空间”章节准备 WorkBuddy、Obsidian、Web Clipper，并让两款软件共用 vault。接着解释目录结构和 LLM Wiki 来源，以完整 AGENTS.md 模板把抽象方法落成规则。正式实操按“存资料—编译—查询—检查”顺序展开，每节都先解释目的，再给具体操作或可复制指令，转场清楚。最后从自动更新和体检回扣“自生长”，再把主题从工具使用提升到“收藏不等于掌握”。不足是数据安全判断插入准备环节且下结论过满，文章也没有专门的故障排查、成本统计或效果验收表。

## 案例：目标、输入、操作、结果与人工成本

案例一为作者亲测搭建「书房」：目标是让 WorkBuddy 与 Obsidian 共用知识库；输入是一个新建 vault 和建目录指令；操作是把 WorkBuddy 工作空间指向该文件夹，创建 raw、wiki/concepts、wiki/entities、wiki/sources、AGENTS.md、index.md、log.md；结果是两端可读写同一批文件；人工修正未报告；作者称整套流程含模型运行约 15 分钟，但未拆分此步耗时与积分消耗。案例二为作者亲测网页剪藏：目标是把网页正文保存到 raw/；输入是网页和 Web Clipper；首次把 raw/ 填到“保管库”字段，结果无法剪藏；人工修正为“保管库”填写 vault 名「书房」，raw/ 填保存路径；修正耗时未给，插件免费，其他成本未给。案例三为作者亲测本地资料导入：目标是把已有文件加入原始资料区；输入包括 PDF、图片、Markdown；操作是拖入 raw/；结果是作者称在 Obsidian 中均可点开；未报告 OCR 准确度、复杂 PDF 解析、失败文件、数量、耗时和模型费用。案例四为作者亲测编译：目标是把原始资料整理为可查知识页；输入是 raw/ 新增文章、AGENTS.md 规则和编译提示词；Agent 逐篇读取，归入 concepts、entities、sources，添加双链并更新 index.md、log.md；作者报告 Obsidian 中可看到结果和逐步生长的关系图谱；未给文章数量、页数、事实准确率、重复页比例、人工修改次数和此步耗时成本。案例五为作者亲测查询：目标是回答“新手学 Openclaw 最容易卡在哪几步”；输入是该问题；操作是先读 index.md，再选两三页细读；结果是分层回答并列来源页；未展示完整答案，也未与普通 RAG、全库检索或人工查找做同口径对照，人工修正和耗时未给。案例六为方案演示式定时检查：目标是每周发现空双链、孤立知识和冲突说法；输入是每周六 21:30 的任务指令；操作要求先列问题、用户确认后再改并记日志；预期结果是定期体检，但正文没有提供一次真实定时执行的检查报告、修复结果或失败记录。案例七为方案演示式每日编译：目标是每天 7:30 扫描 raw/ 并增量编译；结果被描述为系统自动运转，但未给连续多日运行证据、重复编译控制结果、电脑休眠或软件退出时的行为。

## 解释、语言与图文作用

解释方式以生活化比喻降低门槛，例如把 vault 解释成“专门放知识库的文件夹”，把 Agent 定义为“图书管理员”，把 Obsidian、LLM、wiki 对应为工作台、程序员和代码库；同时用目录树和整段提示词承接具体操作。语言节奏是短句、口语强调和步骤推进，“最关键”“不能出错”“先别急”等提示能引导新手注意操作节点。对“编译”“双链”都有即时释义，教学友好；但“这些线实际上就是 AI 把文章所有内容读了，关联起来了”“这是知识库的智能所在”等表达把图谱可视化与理解质量近似等同，解释上略有跳跃。

## 结尾收束

结尾先确认四步跑通并祝贺读者，再从工具层转向“存下来不等于拥有，能调取、连网、使用才是自己的”，随后三次强调学习，最后借「仓库」与「书房」的对比完成情绪收束。之后是点赞、在看、转发、星标和作者身份介绍，属于标准公众号互动召回，没有新的实操证据。

## 可迁移的编辑动作

可执行的编辑动作是：保留“四步总览—准备—逐步实操—维护”的骨架，但在每一步后增加统一验收框，明确“输入文件数、生成页数、引用来源、人工修改、耗时、积分”；把 AGENTS.md 拆成最小可运行版和进阶版，避免新手一次接受过多规则；单设“故障排查”小节，收录 vault 名与 raw 路径混填、文件解析失败、空双链、重复页面、定时任务未触发等问题；把“本地保存”和“模型处理是否出端”分开表述，并给出核查插件权限、Agent 网络请求和企业合规要求的清单。适用条件是作者能提供真实文件样本和运行日志，且不把尚未验证的安全结论写成绝对事实。

## 自己的待测方向（待实操，非已执行）

面向已有 30—100 篇行业资料、不会编程但能维护文件夹的研究型读者，我会用自己的输入做一次七天复测：20 篇网页、5 份可复制文字的 PDF、3 份扫描 PDF、2 张信息图，并预埋两组互相冲突的数据。第一步是在隔离 vault 中按文中目录和 AGENTS.md 原样搭建，再记录每次模型调用。观察点包括剪藏完整率、不同格式解析率、来源引用准确率、重复页比例、冲突召回率、一次查询耗时、人工修正分钟数、定时任务在休眠和断网后的表现。所需证据是原始文件哈希、生成前后目录快照、完整提示词与回答、index/log 变更记录、模型调用或积分账单、逐条人工核验表以及七天任务日志。
