# 路人甲TM：千问办公首轮交付与按用途选模型

## 主问题与证据身份

- 原题《别折腾了，千问办公已经实现模型自由了》，署名路人甲，账号路人甲TM（`gh_d516081071ec`），2026-11-18 12:50，[微信原文](https://mp.weixin.qq.com/s?__biz=MzIzMDQyMjcxOA%3D%3D&mid=2247524668&idx=1&sn=d87f95b5898b049a4a5a51a0f18e1657)。按原链接、原题和三任务指纹未发现已有同作品；同批电商文是浏览器教程，不合并。
- 通读 raw 可提取正文 P1—P93（按非空 HTML 文本块编号，跳过脚本、样式、SVG）；图片、动图、视频和外链未看，产品、代码、账单未核。
- 读者是需要为办公 Agent 按任务挑模型的人。主问题：只看首轮时，提取、规则计算和查证分别该看什么，而非都选最贵？主分类实操测评，研究对象是千问办公内的多模型交付。实操为作者亲测自述，产品信息和推论另列。

## 标题与开头

标题“模型自由”承诺可选性而非免费或不限额；开头报模型上新后迅速改问“怎么用才最划算”。正文用三个用途兑现选型讨论，但没实扣明细，不能兑现普遍最低成本或企业规则实证。

## 结构推进

先亮首轮规则和预设检查点，再从七句聊天的字段正确性进到计算器边界用例，最后比较简报的一手来源和查证深度。只有 Qwen4-Max 三题都出场，不能把 3+4+3 次交付当全矩阵。结尾才讨论共享额度与权限，不让厂商故事替代用例验收。

## 原文定位锚点

- P13，首轮边界：“同一句指令原封不动地发出去，只看第一次交付”。
- P24，细小违约：“指令要四列，它自己加了个序号列，变成五列”。
- P49，计费区别：“模型旁边标的身价是单价，不是这份活的账单总价”。
- P79，简报验收：“链接是一手还是二手、数字要不要复核”。

## 结尾怎样收束

从模型名次回到结果的使用对象，将自用扫读、给别人汇报分开，再上升到办公 Agent 的选择权；后者是作者评价，不是额外验收。

## 失败、限制与不宜照搬处

保留多列、相对日期、转述来源与未核标注等偏差。首轮不允许修复，无复跑分布、统一预算、全输出、版本及账单；模型只走各题子集，排名不能横推。真实聊天须脱敏或自造。互动单时点不证明标题或结构导致传播。

## 可迁移写法与自己的待测方向

- 先定义结果给谁用，再把格式、正确性、等待和实扣分栏；把产品自检和人工金标准分开，给未核内容留明确状态。
- **待实操**：给需要周报的独立创作者，用自编七句群聊和可手算的报价边界表。先固定基准日期、四列表头与预期账单；观察首轮字段偏差、返工与等待，保留逐轮输出、边界算例、计时、版本和实扣。没有本账号读者效果实证。
