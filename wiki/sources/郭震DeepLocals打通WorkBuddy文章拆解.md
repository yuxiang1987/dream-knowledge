# 郭震DeepLocals打通WorkBuddy文章拆解

原题：终于有知识库打通了WorkBuddy，能查询你电脑里的上万文件，非常方便！。作者：郭震AI，发布时间 2026-10-26 14:23。[原文链接](https://mp.weixin.qq.com/s?__biz=MzI3NTkyMjA4NA%3D%3D&mid=2247525763&idx=1&sn=7a3dfccfb105b81f2bc234e307a45f93)

阅读范围：全文文字已读；36 张配图与界面截图未核看，未安装 DeepLocals、未连 WorkBuddy、未验证检索效果。文件数量、格式数、Skill 个数、功能开关与「只读」承诺均为作者陈述。

## 主问题

通用 Agent 看不到本地文件、只能现读，能不能先让一个本地知识库把几万个文件学完，再让 WorkBuddy、豆包等直接按意思检索并带出处回答？

## 目标读者

电脑里堆着上万份资料、又已经在用豆包或 WorkBuddy 的个人用户与知识工作者。不适合：不愿把文件索引交给本地工具的人、需要企业级权限审计的团队、以及文件量很少、直接丢给通用 Agent 就够用的场景。

## 证据身份与分项边界

作者亲测陈述为主：本地已导入 3.6 万多个文件、覆盖 69 种格式，文中展示了在 WorkBuddy 里列知识库、检索定位并读取全文要点的对话截图，按「讲了什么→怎么做的→效果如何→我的分析」组织回复。产品能力与机制（RAG、只读检索、默认关闭）属产品说明与作者转述，没有官方文档链接、没有检索准确率、召回率、耗时或失败样本。Skill 列表与「副业军师」为产品自带与团队自研描述，效果未验证。

## 标题承诺与开头

标题承诺「打通 WorkBuddy」「能查上万文件」「非常方便」。正文确实给出接入设置、密钥复制与在 WorkBuddy 中调用检索的流程，也给了文件与格式数量，兑现路径清楚。但「非常方便」没有设置耗时、失败排查或权限配置的代价，也没有与「直接把文件丢给通用 Agent」的同任务对照。开头先交代这是 V3.6.0 升级汇报，再用一句话定位产品（自动学习你电脑文件的 AI），并抛出 3.6 万文件、69 种格式两个数字，属于**版本通报＋数字背书＋一句话定位**。

## 结构与转场

通篇按「这是什么→为什么要用→六项更新→能力清单→总结判断」推进：先解释通用 Agent 只能现读、所以需要预学习；再依次给 AI 助手接入、精选 Skill、三维知识库云图、@ 提问、历史生成物、导图导出；最后回到「资料多且离不开豆包/WorkBuddy 的朋友值得升级」。转场以「更新1/更新2」编号为主，是产品发布文的标准结构，不是任务链推进；六项更新之间没有难度或问题递进关系。

## 案例逐项拆解

1. **WorkBuddy 接入检索（作者亲测自述）**：目标是让 WorkBuddy 用上本地知识库；输入是文件索引与生成的密钥；操作是设置里开启「允许 AI 助手访问」、勾选知识库、复制密钥到 WorkBuddy；结果据作者称连接成功、能列出知识库、能检索定位并读全文要点；人工成本、失败重试、索引建立耗时均未提供。
2. **3.6 万文件、69 种格式（作者自述的数量）**：作为「海量」的证据，但没有说明索引时间、占用空间、更新机制与错检情况。
3. **「副业军师」Skill（产品能力描述）**：按行业、工具、时间与预算给副业方向，属于推荐型输出；无任何可核验的规划质量证据，也没给失败或不适用的例子。
4. **三维知识库云图（界面功能）**：把资料片段按相似度聚簇，支持旋转缩放与引用定位；只读到文字描述与截图存在，画面本身未核看。

## 解释、语言与图文作用

解释集中在两点：为什么需要预学习（通用 Agent 现读，做不到从几千文件里找一句话）、以及只读与默认关闭带来的安全边界。语言是产品通报口吻，短句多、编号清楚、结尾给「一句话判断」。36 张图承担大部分操作说明，文字里没有逐张解释，因此不看图只能知道有这一步、不知道界面细节。

## 结尾怎样收束

先给一句话判断（资料多、又离不开豆包和 WorkBuddy 的朋友值得升级），再列四大会话模式、四大场景与音视频分析，最后回归三项核心更新与三连引导。承诺范围基本限于「本地文件查询总结分析」，没有扩展到企业治理或多用户协作，这一点克制。

## 失败、限制与不宜照搬处

- **没有失败样本**：未提供接入失败、密钥失效、索引错检、大文件超时或权限勾错的排查记录。
- **只读是产品声明**：文字里说只读、不改资料，但未给权限验证方法与日志；不能当作已审计结论。
- **数量未独立核实**：3.6 万文件、69 种格式、16 个默认技能均为作者陈述。
- **没有对照**：未与「通用 Agent 现场读文件」「其他本地知识库」做同任务对照，无法判断「按意思秒查」相对现读省了多少。
- **媒体未看**：36 张截图未核看，界面与三维云图效果不能引用为已验证画面。

## 可迁移的编辑动作

版本通报文可以改成「先立一个问题，再给一个最小验证」：先写清通用 Agent 为什么读不了本地文件（现读、无索引），再挑一份自己真实的资料做两轮——第一轮直接问 Agent，第二轮走本地知识库再问同一问题，比较答案是否带出处、是否漏项、耗时多少。产品六项更新不必逐条讲，只保留与主问题相关的那一项，其余列成清单即可。

## 自己的待测方向（待实操，非已执行）

面向电脑里有 1 万份以上资料、日常用 WorkBuddy 的知识工作者，我会用自己的一批脱敏资料（约 300 份文档 + 20 份表格）做一次对照：第一轮把同一问题直接交给 WorkBuddy；第二轮接入本地知识库后再问同一问题。第一步是固定问题清单（10 个答案已知的事实题 + 5 个需要跨文件汇总的问题），观察点包括引用是否可点到原文、漏项与错引、回答耗时、索引建立时间与占用、权限勾错后的行为。所需证据：问题与标准答案、两轮完整对话、引用定位截图、索引与耗时记录、权限与删除说明。**待实操，未开始。**
