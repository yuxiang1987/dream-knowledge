# 飞书 Skill 进阶实操第三阶段

来源：`raw/公众号方法论/飞书Skill进阶实操第三阶段.md`，原始出处是用户提供的飞书文档
「第三阶段：Skill进阶实操（选学）」（作者「拾梦」，空间「公众号」）。
这份材料本身没有内部链接关系，只记录了一套公众号生产线的阶段划分与调度思路。

## 主问题

一套公众号生产线怎么拆成多个 Skill，又怎么让这些 Skill 串成一条能跑的流水线？

## 阶段划分

文档把流程拆成 Step 0 至 Step 5，再加两节关于工程化的说明：

- Step 0 定赛道：写一份 `00_style.md` 作为全流程基准，含人设卡、风格 DNA、往期文章库、
  受众定位、聚焦领域和常青备胎。
- Step 1 自动选题：采集、生成、评审三件套，5 维打分，70 分及格线。TOP1 直接进入创作，
  TOP3 存档，不及格的降级到常青题。
- Step 2 创作：三版并行、A+C 合并、40 个备选标题，加 AI 味四层自检。
- Step 3 制图：1 张开篇人设图加 4 张小黑手绘正文图，先出 shot list 再生成，
  用 qa-checklist 闭环，串行生成以避免限流。
- Step 4 排版：用确定性脚本做「格式翻译」，三套主题参数 warm / tech / mono，不用 AI。
- Step 5 分发：8 个平台各自改写，只换风格不删内容、严禁杜撰、图文数量一一对应，
  同步到公众号后台，输出执行报告和人工待办。

第九节讲把整套流程固化成自己的总调度 Skill，提到开源版 `gzh-daily-pipeline-open`
和占位符全局替换，附 Skill SOP 模板与验收方法。第十节讲定时任务、断点续跑、批量矩阵、
跨 Skill 联动和风格迭代。

## 三条主张

1. 多个 Skill 像水管接起来，环环有交接、环环有验收。
2. 观察重复劳动，用 Skill 替代。
3. 用自然语言把流程讲清楚，让 Agent 固化成新 Skill；一句「跑今日流水线」就能触发。

## 证据边界

- 只读到约八成：Step 0 至 Step 5 正文和完整目录树。Step 5 尾部细节、第九节与第十节正文未读。
- 文中提到的 Skill 名称来自作者的方案，本机没有安装这些同名 Skill，
  无法核对它们的实际实现、提示词和验收标准。
- 分数量化规则（5 维 70 分、三版、40 个标题、4 张手绘图、8 个平台）是作者的方案选择，
  没有给出对照实验，不能当成普适结论。
- 状态标为待核实：本文只记录结构，没有对流程有效性做实测。
