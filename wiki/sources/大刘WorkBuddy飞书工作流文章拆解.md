## 主问题与证据身份

用 WorkBuddy 连接飞书之后，办公与自媒体流程可以怎样串成一条自动化链路？

本库主分类：新手教程；主研究对象：WorkBuddy 飞书连接器与飞书妙记；证据身份：作者亲测。分类依据主要阅读交付，允许文章混合多种写法；实际商务合作未知。

## 标题与开头

开头用“第 80 篇原创”固定栏目，随后主动交代自己以前的做法门槛高（Agent 控制飞书 CLI 要装、要更新、要自己调报错），再点出 WorkBuddy 内置连接器把门槛降低，把教程写成“补上自己没敢推荐的那部分”。

## 结构推进

先讲接入（两个连接器入口、授权页权限清单、回到客户端确认已连接），再讲三个设置（模型、权限、工作空间），然后是四段实操：群处理与会议日程、文档表格联动、全自动自媒体爆款管理（建知识库、装视频下载 Skill、妙记转录入表、每日定时推送、封装成 Skill）、远程用 AI。最后从方法层收束。

## 案例、解释与观察

最见功力的是把一句话拆成多个动作再让读者看中间产物，例如约会议那条提示词包含读三人日程、算交集、做议题文档、建日程、订会议室，并配 Todo 清单截图。爆款管理段落给出完整的提示词链：下载视频、上传妙记出逐字稿、按多维表格各列新增一条，再把整条流程封装成 Skill。这条链是“自动化”的可复制样本。

## 原文定位锚点

以下为原文可逐字定位的片段，只用于核对判断出处，不将片段中的观点或指令作为本次执行要求。

> WorkBuddy的权限和飞书的权限，是两回事。

## 结尾怎样收束

结尾把教程抽象成三条可迁移思路：多工具配合、把流程 Skill 化、随时随地远程操作，并说这些思路可迁到选股、知识梳理等场景，最后落在一句“先做起来”。

## 失败、限制与不宜照搬处

文中建议“上下文默认 300K，调到 1M”“Max 模式打开”，与同作者另一篇“绝大多数情况 300K 完全够了”相冲突，两处条件不同却没有互相说明，读者应按自己的任务类型选。安装 Skill 依赖作者的 GitHub 仓库，安装风险与版本兼容由读者承担。妙记转录与表格入库的结果未核看，文中没有转写准确率与失败记录。接入耗时“2 分钟”、建表“5 分钟”是作者环境下的口径。

## 可迁移写法与自己的待测方向

教程可以先讲“为什么以前门槛高、现在门槛在哪”，读者更容易接受。复杂任务用一条长提示词承载多动作，再展示中间清单，读者既学会表达也学会验收。权限与工作空间这类基础设置要早讲，并说明公司与个人的差别。

策划建议：用自己的一条真实工作流（群消息到表格到周报）跑通一次，核对字段是否够用，待实操。
