## 主问题

Claude Code/Codex 用户如何安装并组合 Academic-Research-Skills（ARS），完成查文献、论文规划与写作、模拟审稿、修改、格式转换和诚信核验；不同命令、模式及人工确认点分别是什么？

## 目标读者

核心读者是已经能使用 Claude Code、正在写论文或准备投稿，但不清楚 ARS 各命令如何分工的人；也照顾刚入门的研究生，尤其强调苏格拉底提问、先规划再写、先 coach 再 revision。对只用 Codex、需要逐步安装排错的人帮助有限，因为作者明确把正文范围限定在 Claude Code 版。

## 主研究对象

主要面向使用 Claude Code 做论文工作的研究生、科研人员和投稿作者，解释 ARS 的四个底层 skill、13 条快捷命令及四类推荐工作流。Codex 版只提示存在姐妹仓库，正文实际讲解和命令以 Claude Code 版为主。

## 证据身份与分项边界

证据以作者对仓库功能、命令和设计机制的整理说明为主，夹有笼统的个人使用判断，但没有展示一次完整亲测任务的输入、终端过程、生成文档、报错或前后对比。作者称自己“用它做科研这段时间”，并给出自己的 SOP，这属于使用经验陈述；13 条命令、四个 skill、agent 数量、模式、字数范围、评分阈值、API 交叉验证、PRISMA 及诚信关卡等，更接近项目功能说明或仓库口径，文中未逐项提供独立测试证据。诸如“须 100% 通过才能定稿”“全文 ≤3 个破折号”“约 15 分钟快评”等数字均只是作者报告，本文没有复现实测。

## 标题承诺与开头

标题承诺“Claude / Codex + 全方位科研工具 Skills 实操教程”。正文对 Claude Code 版兑现较充分：给出安装命令、13 条命令表、四个核心模块和按场景组合的 SOP；但对 Codex 只给出姐妹仓库名称并让读者按仓库说明安装，因此“Claude / Codex”并非同等深度的双平台实操。开头先用作者科研经历建立推荐资格，再用“研究→撰写→审稿→修改→定稿”全链路和“四个 skill、二十多个工作模式、近四十个 agent”制造规模感，随后以“全网最全”抬高信息完整性的预期。

## 结构与转场

正文按“安装入口—命令地图—底层能力—组合工作流—价值判断”推进。第一节用两行命令降低启动门槛；第二节先给13条命令总表，作为后文导航，并用“下一节回到源头”转入架构解释；第三节依科研顺序拆 deep-research、academic-paper、reviewer、pipeline，每块内部再用模式列表、角色表或阶段表展开，同时穿插容易混淆的概念辨析，如两种 lit-review、revision 与 revision-coach；第四节把前述零件重组为从零写作、已有草稿、收到大修、只做综述四套 SOP；结尾从功能罗列转回作者的时间与精力分配。结构清楚，但“速查表”和后面的模式表存在一定重复。

## 案例：目标、输入、操作、结果与人工成本

案例一是“从零写完整论文”的推荐流程：目标是由模糊选题走到投稿材料；输入仅写成论文主题和后续大纲，未提供具体学科、题目或文献；操作为 /ars-plan、/ars-outline、人工确认证据地图、/ars-full、/ars-citation-check、/ars-abstract、/ars-disclosure；结果只列预期产物，没有实际稿件、核验率或投稿结果；人工修正点是确认大纲和证据地图；耗时、调用成本、模型版本均未给。案例二是已有草稿投稿：输入是一篇未展示的草稿，依次评审、查引用、补摘要、转格式、生成声明；均为建议流程，不是呈现出来的亲测结果，人工修改次数、期刊适配结果、耗时成本未给。案例三是大修：输入为稿件和审稿意见，先 coach 生成路线图，人工确认后 revision，再 re-review；作者明确保留人工确认，但没有真实审稿意见、修改前后文本和复审分数。案例四是文献综述：先在 deep-research 搜索，再用 /ars-lit-review 整理，并以 /ars-mark-read 标记亲自核实的文献；没有给出真实检索式、纳排标准、文献数量或假引用拦截实例。文中关于系统综述、五人评审团和十阶段流水线属于功能说明，并非完成后的第三方案例或本文实测。

## 解释、语言与图文作用

解释方式以“先总表、再拆模块、最后拼工作流”为主，技术名词保留英文 mode 和命令，紧跟中文用途，方便读者建立映射。作者频繁用“先查、再写、再审”“先用 coach…再用 revision”等对举来澄清边界，也用“一票否决”“替你挨一顿打”“堵在那里”等口语化表达解释审稿和诚信机制。句子多为短段落，命令、表格和编号密集，阅读节奏快；强调词如“最重”“特别狠”“铁律”增强记忆，但也带有明显评价色彩，不能替代实际效果验证。

## 结尾收束

结尾不再增加功能，而是把价值收束为替作者处理翻文献、核引用、核数据一致性和格式转换等耗时工作，让人把精力留给选题、方法和解释结果；同时明确“不会替你变聪明，也接管不了你的判断”，形成必要的人机边界。最后接公众号常规点赞、在看、转发、星标和作者身份介绍。

## 限制与不可照搬处

正文没有展示任何完整运行记录、真实论文、错误日志、生成质量样本、假文献被拦截的具体条目或与不用 ARS 的同口径对照，因而无法核实“全流程”“防假文献”和节省时间的实际程度。Codex 版没有实操步骤。系统综述、GRADE、森林图、三重 API 验证、评分映射和 100% 诚信通过等技术机制未独立核实；模型版本、插件版本、依赖环境、上下文限制、API 可用性、隐私与未发表数据风险、费用均未说明。也没有报告失败案例，例如检索遗漏、错误判定、格式转换损坏或审稿评分失准。不能把模拟评审决策等同真实期刊接受概率。

## 可迁移的编辑动作

可执行的编辑动作是：介绍复杂工具时，先给一张“入口命令—底层模块—适用阶段—预期产物”的总表，再按真实任务顺序拆解；对易混功能用成对辨析，并把人工确认点直接写进 SOP。若要提高可信度，应补一条贯穿全文的真实论文样例：固定题目、数据库范围和模型版本，展示检索结果、被判定为不可核实的引用、人工纠错、修改前后段落、耗时和费用。适用条件是读者确实使用 Claude Code/Codex，且愿意亲自核查文献与研究判断，不能把流水线输出直接当作学术事实。

## 自己的待测方向（待实操，非已执行）

面向准备写中文综述的研究生，我会用一个范围明确的公开主题作为自己的输入，例如“2023—2025年生成式AI辅助同行评审研究”，第一步在隔离项目中记录插件版本并运行 /ars-plan，再用预先人工核验过的10篇 DOI 文献测试 /ars-lit-review 和 /ars-citation-check。重点观察命令是否正确触发、是否新增不存在的文献、DOI与题名匹配率、证据是否被放到合适论点、coach 与 revision 是否越权改写，以及人工修正时长。所需证据包括完整终端日志、原始文献清单、输出文件、逐条引用核验表、错误分类、时间与调用费用，并与不使用 ARS 的同一输入流程做同口径比较。
