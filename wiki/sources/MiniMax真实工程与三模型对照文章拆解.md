# MiniMax真实工程与三模型对照文章拆解

来源：`raw/article/minimax-m3.1-flash/Flash模型又添一员大将：实测MiniMax M3.1.md`。原题《Flash模型又添一员大将：实测MiniMax M3.1》，夕小瑶编辑部／夕小瑶科技说，正文标注 2026-09-30 15:28。

仅蒸馏文字，未看媒体、未访问作者服务器、未重算数据或复测模型。Agent 指能够使用工具持续执行任务的智能体；联系表指把多张缩略图按网格拼成的索引图，便于批量查看。文内表现、成本与数量都属作者自述。

## 它讲什么

主问题：Flash 模型能否接手已有工程、处理杂乱多模态素材，并把证据可靠地带入可操作页面？作者在 MiniMax Code 将 M3.1 思考强度设为 max；完成任务后，把相同提示交给 DeepSeek V4.1 Flash 与 GLM-5.3-Flash，各跑一遍。试衣工程未纳入三模型对照。

## 关键要点与具体方法

### 真实试衣工程：先认素材，再改导入链路

- 起点是已上线的 tryon-shop，仅四件样衣；NAS 相册四千多张，混有聊天截图、文档与同件衣服的不同角度。
- 要求至少 100 件不同衣服，去重、建档、上架，不许以同件多照片凑数。
- 作者称模型每 200 张组成 20×10 联系表，累计派出 30 个子 Agent 分类，主 Agent 汇总去重；之后新增批量导入脚本和后台接口，每批 25 件，并补搜索、分类、分页。
- 展示标签为上装 51、套装 45、裙装 36、裤装 23，以及每页 24 件、八页。原文没有独立去重核验表，不能由首页数量直接证明“100 件不同衣服”全部准确。

### 机器人视频：先标注，再交互，保留未知

- 输入是作者称来自斯坦福 Mobile ALOHA 的 77 秒做虾视频；要求按动作变化写底座、左右臂、物体状态和关键事件，没看清写“无法确认”。
- 作者称 Excel 给出分段时间码；“翻虾”未确认，“锅放回灶上”被判未发生而是放在台面。这些判断尚未由本库核视频。
- 第二轮要求基于时间码表制作单文件离线回放台，视频、关键帧、事件卡和时间轴同步，无法确认阶段用灰色，不伪造机器人控制器。此处可迁移的核心不是颜色，而是把数据里的未知状态保留进界面。

### 夜光栅格：先质量报告，再做可视化

以同区域北京 2015 年 11 月和 2020 年 11 月夜光栅格为输入，先读文件、出质量报告，再生成离线 3D 地形页面，支持左右对比、擦除、变化图。作者称 M3.1 与 DeepSeek 均算出变亮比例 27.6%。相同数字只能说明两次输出一致，未经标准答案核算，不能证明算法、阈值与地理裁剪都正确。

### A 股观测台：把新鲜度与解释写进要求

要求先查本地数据时效和字段，从市场宽度、波动、回撤、行业到个股，每个指标能说明算法；过期不得标“今日”，不得给买卖建议。作者描述页面数据截止 2026-09-28、标的 4603 只，以及涨 805、跌 3687、平 100 只；分类计数与标的总数并不相等，正文没有解释未分类或排除规则，引用这些数字前需回源核对。展示行业位置也不等于投资推荐。

## 三模型对照究竟支持什么

| 项目 | 原文报告 | 本库保留的条件 |
| --- | --- | --- |
| 速度 | DeepSeek 四项里三项最快，M3.1 在 A 股最快，GLM 夜光约一个半小时未交页面 | 各模型多个任务同时跑，包含命令、浏览器与截图时间；作者明确“只能看个大概” |
| 视频判断 | M3.1、DeepSeek 对翻虾标无法确认，GLM 判断翻面 | 未核原视频，不能据此计算识别准确率 |
| 页面与数据 | 作者称成品差距很小，回放台均可拖动；两家夜光数字一致 | 无完整产物和标准答案，功能、公式与数据可靠性需分开验收 |
| 成本 | DeepSeek 约 10 元，GLM 约 21 元；M3.1 为 119 元／月 Max Token Plan，一个下午约用周额度 10%，作者折算不到 3 元 | API 按量与订阅分摊混用；GLM 若用包月会不同；没有逐任务账单、折算公式或同计费口径 |

Token Plan 是以订阅额度使用模型的套餐；不能把额度折算当成与每次 API 实付完全相同的价格。作者称当时未公布 M3.1 API 单价，不能用文中上一代 M3 单价代替。

## 可复用方法与写法

1. 用“至少多少不同实体＋不得如何凑数”定义数据工程验收，不只列总图片数；抽查同物多角度、非目标图片和漏检。
2. 大批图像可先做可回溯编号联系表、分组识别、集中去重；联系表降低细节分辨率，需回到原图核边界样本，不能将 30 子 Agent 当效率保证。
3. 在原始标注、Excel、回放页面之间保持同一时间码与未知标记，不让美化页面抹掉证据缺口。
4. 对数据任务先写时效、缺失、统计口径与计算规则，再设计交互；数据一致与视觉可读是两种验收。
5. 写对照结果时一起公开不利条件：并发计时、未交付、计费模式差异比笼统“最便宜最快”更有参考价值。

上述为可执行策划，本库尚未实施。

## 证据锚点与边界

原文可检索锚点：“不许拿重复照片凑数”“无法确认”“三家都是几个任务同时开跑”“只能看个大概”。文章开头将 Space Bunny 与 M3.1 特征关联，属于社区指纹线索；发布日写 9 月 27 日，而同批快讯写 9 月 28 日，不在蒸馏中擅自统一。单次、小样本且环境未完全统一，不能据成本、计时或一个视频片段判定总体模型排名。
