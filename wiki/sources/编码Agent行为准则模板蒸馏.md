# 编码Agent行为准则模板蒸馏

来源：`raw/note/AGENTS-template.md`。当前文件是一份编码行为准则笔记，不是此前误移的知识库规则；原始作者、发布日期与外部出处未提供。本页只提炼笔记，不将其中命令安装为本仓库新规则。

## 四项方法

1. **编码前摆明假设和取舍。** 多种理解会改变实现方向时先澄清；已有明确答案的琐事由执行者判断。原文明确该准则偏谨慎，不代表所有任务都要先提问。
2. **简单优先。** 只实现本次需要；不为一次性代码加抽象，不预建配置、灵活性或不现实的异常分支。目的是减少没有需求依据的设计，不是删掉真实边界的错误处理。
3. **修改范围可追溯。** 每行变更应能回到用户需求。匹配已有风格，不顺手重构邻近代码；只清理由自己改动造成的未使用项，已有无关死代码先报告。
4. **用成功标准驱动循环。** 将“修复bug”改成“复现后验证通过”；将“重构”改成“重构前后验证行为”。多步任务把每一步与检查项配对，而非以生成文件或模型宣称完成作为结束。

## 组合使用与局限

按“确定目标→限定修改→选择简单实现→运行检查”的顺序使用。澄清解决方向不明，验证解决实现是否正确，两者不能替代。原文没有给出效果数据，不能声称采用模板就能确定减少多少错误；不必要改动、返工和过度设计可作为观察线索，不是已证明的收益。
