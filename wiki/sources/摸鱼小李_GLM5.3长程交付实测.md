开头先把 Agent Loop 翻译成“AI 自己把一件大事拆成很多步”，降低术语门槛，随后立即“开测”。结构依次是：概念解释→多案例结果→暴露单模态限制→总结 Loop 提示词→综合结论。第二节从 7 轮《传奇》复刻扩展到六轮闯关游戏、放置游戏和红蓝攻防，强调任务广度；第三节用“没有视觉”主动反转赞美，解释为何 Claude Code 场景还需 GLM 4.6V 充当眼睛；第四节把体验转化为可执行规则。

## 方法观点及证据边界

五条 Loop 建议具备工程可操作性：每轮将进度写文件；显式记录当前轮数；预设完成、最大轮数和人工停止条件；保留报错并在下一轮换策略；压缩上下文时保留决策、未决问题与下一步。其本质是外部化状态和验收机制，而非单纯依赖模型记忆。作者建议“一般 15 到 25 轮就够”没有任务规模、模型和预算条件，只能视为经验范围。

文章承认 GLM-5.3 为纯文本模型，视觉检查依赖 GLM 4.6V；这意味着展示结果不能全部归于 5.3 单模型。在 Claude Code 与 ZCode Harness 不同环境下，工具、视觉模型和执行器也可能影响表现。作者又说复杂工程的后端和数据库要人工把关，合理收窄了“自主交付”边界。

## 可迁移动作与待实操方案

候选维度是：**用可恢复状态文件、停止条件和错误账本，对比有无 Loop 轨道时的长程项目完成率。**

- **目标读者**：用代码 Agent 搭建中型 Web 应用的独立开发者。
- **自己的输入**：同一需求文档、空仓库、测试套件和 20 轮上限；模型与工具权限固定。
- **第一步**：设计 A/B 两组，A 只给目标，B 强制每轮读取/更新 `state.md`、`errors.md` 和验收清单。
- **观察点**：测试通过率、重复报错次数、目标漂移、崩溃后恢复轮数、无效 token、人工介入分钟数。
- **所需证据**：完整提示词、代码提交历史、每轮日志和状态文件、自动测试结果、token/费用/时长及人工干预记录。只有同环境复跑，才能判断“靠谱”来自模型还是 Loop 设计。
