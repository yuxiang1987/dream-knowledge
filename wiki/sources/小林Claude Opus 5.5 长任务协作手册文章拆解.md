**主问题**：怎样把 Anthropic 的 Opus 5.5 使用建议转成一套可执行的人机协作流程，使需求更可验收、长任务少无意义暂停、交付结果更容易核查，同时正确处理模型切换与速度成本设置？

**主分类**：新手教程

**主要证据身份（各例身份见下）**：官方主张整理

### 标题承诺与开头

标题以“重磅发布”和“最佳使用手册”制造权威性与紧迫感，正文开头立即交代信息来源是 Anthropic 的《如何在 Claude 和 Claude Code 中用好 Opus 5.5》，随后用反常识建议“删掉仔细思考”作为钩子。文章确实覆盖提示词、长任务、结果审查、应用设置和快速模式，基本兑现“使用手册”的内容承诺；但“最佳”没有通过作者对照测试或多来源比较得到证明，更准确地说是对官方手册的中文重组与场景化解释。开头连续提出“长任务怎么交”“为什么中途停”“最后怎么看”三个问题，也提前建立了需求、执行、验收三阶段框架。

### 结构推进

全文先用短信 SDK 迁移说明需求应包含任务、完成标准和人工介入条件，再转到删除思考叮嘱、effort 设置及执行中追加要求；第二部分讨论长任务持续推进，通过 CLAUDE.md 约定继续与暂停边界，并扩展到子 Agent 分工、主 Agent 核查和 TASKS.md 持久化；第三部分把视角从执行切到验收，建议汇报优先展示“待你处理”，并要求代码审查和调研结论附位置、触发条件及证据；第四部分转向 Claude 应用中的图表、长文档和文件交付；第五部分解释安全检查导致的模型切换及设置入口；第六部分介绍 /fast 的速度与费用取舍；最后用四项清单压缩全文，并邀请读者拿一个经常需要催“继续”的真实任务做对照。转场多用预判式问句，如“看到这里，你可能会问”，把官方条目改写为连续问题链。

### 逐例证据与人工成本

- 短信 SDK 迁移属于作者构造的教学示例：目标是迁移项目内全部短信发送功能；输入是任务范围、清理旧依赖、现有测试通过及不兼容时先询问；操作是让 Claude Code 自行判断文件和入口；结果仅说明这种写法能明确完成标准，没有提供真实仓库、执行日志、测试结果、人工修改、耗时或成本。证据身份为官方建议基础上的作者示例，不是作者亲测成败案例。

- 多服务重试排查是提示词材料：目标是检查订单、库存、支付服务是否超过重试上限；输入要求每个子 Agent 返回重试上限、调用路径、触发条件，主 Agent 核查后汇总；没有实际运行结果，也没有说明发现了哪些缺陷。人工修正、耗时、成本均未提供，证据身份为官方工作流的场景化整理。

- 代码审查示例要求对照 main 分支，只列必须修复后才能合并的问题，并给出文件名、行号、触发场景、原因和复现方法。它交付的是可复用提示词，不是完整审查案例；没有仓库输入、缺陷结果、人工复核记录、耗时和费用。

- 文档日期冲突、图表问答、Excel 整理均是使用场景说明。文章没有附完整原文档、模型输出和人工核验，因此只能确认作者建议如何提要求，不能确认 Opus 5.5 在这些任务上的实际准确率。

### 解释、观点与可证范围

作者把效果主要归因于三点：一是可检查的完成标准减少模型猜测；二是 CLAUDE.md 与 TASKS.md 将协作规则、待办和人工决策点外置，降低长对话压缩导致的信息损失；三是结果必须附证据和复现路径，避免只收结论。这些是合理的流程解释，但正文没有作者控制变量测试。关于“Opus 5.5 每次回复前就会思考”“删掉叮嘱后更早回复且质量没有明显下降”“图表理解有所改进”“/fast 仍是同一模型”等，均来自手册或官方试验的转述；文章未锁定具体客户端版本、套餐、平台配置及独立核验，不能据此推定所有账户和任务都有相同表现。安全触发与模型切换同样是规则说明，不代表每次切换原因都能由用户自行确定。

### 语言、图文与结尾

语言口语化，频繁使用“当然继续啊”“活还没干完呢”等短句，把抽象规则翻成开发现场中的冲突。章节按编号推进，示例提示词使用短行列出，便于读者复制和改写。正文多次出现图片说明文字，但本分析未观看图片，只能确认这些位置承担了阶段总结或示例索引作用，不能判断图中界面、效果和准确性。结尾不是简单号召收藏，而是要求选择一个反复催继续的任务，补写完成标准和暂停条件后再跑一轮，并观察停顿次数和检查难度，形成小型验证闭环；不过文章没有展示作者自己完成该对照的结果。

### 可迁移的编辑动作

可执行的编辑动作是把产品手册从功能罗列改成“交任务—跑任务—验结果—调设置”的用户流程；每节先设置一个真实冲突，再给最小提示词模板，并紧接风险边界。写教程时把模糊形容词改为可验收字段，例如范围、完成条件、暂停条件、证据格式和危险操作确认。对官方能力统一使用“手册称”“官方试过”等来源限定，并在段尾补一项读者可自行对照的观察指标。结尾可压缩成一页检查清单，但应避免把未测试建议写成已证明效果。
