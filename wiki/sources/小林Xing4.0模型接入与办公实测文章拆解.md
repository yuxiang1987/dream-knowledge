## 标题兑现与开头钩子

标题用“刚刚”“纯血国产”“29B”“首批实测”叠加时效、国产化与验证钩子。正文先交代开源与 MoE、上下文、Coding/Agent 定位，再明确区分官方跑分和作者测试：跑分、显存需求、国产化链路属于官方信息整理；作者因显存不足没有本地部署，而是“直接走 API，接入到 Claude Code 来实测一波”。标题承诺的“实测”由四轮任务兑现，但“纯血国产”只是文章对训练算力、框架和推理适配的转述，正文没有给出独立供应链核验。

## 结构与转场

开头按“发布消息—参数与官方跑分—本地部署价值及作者限制”建立背景；随后用“先给大家看个成果”前置展示 AI 表格，再进入接入教程：申请天翼 AI 开放平台 API Key、修改 ~/.claude/settings.json、重启并确认模型名。主体按 01 至 04 递进：先做 AI 表格并逐项验证，再做多格式文档问答及缺失答案测试，再读 171 页财报并抽查数字，最后处理六份格式不统一的报表。每轮都采用任务设定、输入障碍、结果展示、人工核对的闭环。结尾从个人测试上升到中国电信客服落地与国产化评价，再给五个开源入口。

## 案例输入、操作、结果与人力成本

- 作者亲测案例一：目标是开发可用自然语言修改数据的 AI 表格；输入包括一份数码门店库存表，以及新增“进货金额”、按库存阈值生成补货提醒、按商品名修改单格的指令；操作为通过 Claude Code 调用 Xing4.0-29B 开发页面并执行表格变更，结果是作者称 12 行乘法及合计均正确、四行补货标记无漏错、模型定位 E9 且导出 xlsx 后可重新打开。人工修正未提供；作者进行了逐行、条件标记、单格和导出复核；耗时仅称页面“很快”跑起，成本未提供。

- 作者亲测案例二：目标是搭建带引用的文档问答助手；输入为 171 页半年报 PDF、天翼云产品说明 docx、md 和 csv，操作为先用 BM25 检索段落，再由模型回答并显示引用。四份文件均被作者称为解析成功；对象存储问题回答“100 PB，12 个 9”，作者称与 docx 一致；对于材料不存在的 2027 年营收目标，模型回答未提及。另有两个追问仅称“回答也都没问题”，问题和核验过程未完整提供。人工修正、耗时、成本未提供。

- 作者亲测案例三：目标是让模型阅读 171 页中国电信半年报并写经营分析；输入来自中国电信官网下载的 2026 年上半年 A 股半年报，要求每个数字标出处。结果据作者描述在“一分钟出头”生成三十多项指标；作者抽查其中 18 项，称均可回到原文找到，且没有把行业用户数误算为公司数据。这里只能支持该份材料、该次抽查范围，不能推出全部指标恒定正确。人工修改和 API 成本未提供。

- 作者亲测案例四：目标是汇总六个省分公司、六种格式的上半年经营报表；输入故意包含单位不一、数字文本化、合计行、缺报月份、多工作表等问题。操作中要求超过两个数的加法正向逐步累加并反向复核；结果据作者称单位统一为万元、避免浙江合计重复、四川 5 月标为待补报、湖北两个 sheet 合并，各月各省与六省已报合计复核“一个不差”。人工修正未提供，耗时与成本未提供。

## 解释方式与归因

作者把效果归因于模型面向 Coding 和 Agent 优化、长上下文能力、工具调用，以及任务设计中的预览确认、引用溯源和双向加总复核。表格的“先预览、后确认”、问答的 BM25 检索、财报的来源标记，实际上是应用层方案与模型共同作用，不能把全部效果归为基础模型能力。MoE 29B/A4B、256K/512K、4-bit 约 15GB、3090/4090 可部署、官方跑分及客服秒级响应均属官方主张或作者转述；作者没有本地部署，也未独立复现跑分和客服生产指标。

## 语言、媒体与结尾

语言口语化，频繁用“你看”“那就查”“哎，你还别说”制造陪测感；短问句承担转场，蓝色加粗句承担结论。正文图片、GIF在文字层面被用于展示配置、界面、结果和对照，但本分析未观看，不能确认其视觉内容或是否完整证明结论。结尾先给总体满意评价，再写企业客服场景和国产化价值，最后列出 GitHub、Hugging Face、魔搭、Gitee、魔乐入口，以“期待国模越走越远！”收束。

## 边界与待核实

测试为作者单次或少量任务，不是标准化横评；没有固定温度、API 版本、Claude Code 版本、提示词全文、重复次数、失败样本、吞吐、token 用量与费用。AI 表格的详细需求主要放在未观看图片中，无法完整复现。财报只抽查 18 项，不等于三十多项全部正确；文档问答的后两个问题未展开。本地隐私、无限 token 不等于零成本，仍涉及硬件、电力和维护。客服落地、秒级响应与敏感数据保障没有独立核验。文章无传播基线，不能称爆款或归因传播效果。

## 商业产品与行动入口

核心产品为中国电信星辰实验室 Xing4.0-29B-A4B、天翼 AI 开放平台 API，并借 Claude Code 承载测试。读者任务是接入模型并处理代码、表格、文档和报表。卖点导入依次为国产化链路、同量级官方跑分、较小激活参数、本地部署可能性、Coding/Agent 与办公能力。入口行动包括天翼 AI 控制台、GitHub、Hugging Face、魔搭、Gitee、魔乐链接。正文未见“广告”“合作”“赞助”等明确披露，因此合作关系未知，不能确认商单。

## 可迁移编辑动作

可复用的编辑动作：先把“官方信息”和“作者实测”分栏或显式标注；教程先给最短接入路径，再以界面模型名和正常回复完成连通性验收；每个案例固定写目标、原始输入、故意设置的坑、执行指令、人工核验范围；把可逆操作设计成“预览—确认—落盘”；对长文档要求逐条引用，对数字任务采用样本抽查或独立计算器复核；结论必须写成“本次、该材料、抽查范围内”，避免从一次成功泛化为稳定能力。

## 自己的待测方向（待实操）

待实操。目标读者：需要私有化办公自动化的中小团队技术负责人。自己的输入：一套脱敏后的 20 份混合格式报表、标准答案、异常清单及固定提示词。第一步：锁定模型/API、Claude Code、解析库版本与参数，记录 token 和费用后，先完成连通性与文件解析测试。观察点：任务完成率、字段读取准确率、引用可追溯率、结果未知与失败类型、首字延迟、总耗时、人工修正量。所需证据：原始文件哈希、完整提示词和日志、逐项标准答案、至少三次重复结果、失败截图或日志、成本账单及人工计时。
