# Miora火锅店品牌全案文章拆解

来源：`raw/article/lurenjiaTM/我让腾讯Miora帮我开了家火锅店，做到最后，我有点膨胀了.md`，署名时间 2026-07-27。图片与视频未在本页核看；官方定位、生成效果与耗时均为原文转述或自述，未独立核实。文章结尾给出新用户积分引导，并以「内容含AI生成图片」标注素材来源——这是本库第一篇做此类标注的样本。

## 定位、标题与开头

这是**品牌全案设计实测＋产品能力展示**。读者问题是：一个设计类 Agent 能不能把「随口说的一个品牌」推进成一整套可延续的视觉方案。

标题「我让腾讯Miora帮我开了家火锅店，做到最后，我有点膨胀了」由**夸张叙事＋自嘲**组成。正文结尾自己也说「餐饮店我没开过」，实际交付的是 Logo、品牌规范、包装、空间、海报、视频与小程序设计。夸张在前、自嘲在后，读者不会误会成真开店；这种写法适合脑洞类选题，但仍要有一句把交付物说清的表达。

开头先做产品线铺垫（此前评测过该公司多个 Agent，自己的工作流也在慢慢切换），再引出新产品并提出疑问（市面设计 Agent 这么多，为什么它还要再出一个、跟别人什么区别）。随后给出自己的答案：通常的设计 Agent 完成单一任务，而它更像做一个完整项目——能顺着 Logo 往下确定风格，再做海报、视频、界面与店铺装修。接着引官方定位（自然语言描述需求后协调不同专业能力，生成图片、视频、3D 元素与界面，并维持视觉一致性），并**主动承认官方说法拗口、改用完整项目来体验**。

开头还有一个值得单独记的动作：设定测试对象时明确写「**声明下这个河底捞和海底捞没有任何关系**」，并说明选餐饮门店做测试的理由（设计场景最全、最考验能力），最后先给最终效果、再提出可回答的问题。

钩子类型是**产品线铺垫＋提问对比＋官方定位＋承认拗口改用实例＋自设对象并免责＋先给效果＋提出可回答的问题**。

## 结构与推进

1. **铺垫、定位与测试设计**（含免责声明与先给效果）。
2. **Logo**：调用自带生成能力，从一句模糊需求开始；模型识别到需求模糊并给出选项引导定调性与风格；选定方案后立刻补一套基础视觉，为后续统一。
3. **门店装修与包装**：沿用已确定的 Logo、配色与字体，先做门头与店内空间，再出餐盒、手提袋与饮品杯。
4. **宣传物料**：两张竖版海报，以及两版宣传视频。
5. **点单小程序**：参考常见结构列四个板块，给出一段完整界面需求。
6. **打包与沉淀**：把确认过的整套视觉规范固化成专属能力，之后再做新物料可直接调用；并提到可发布到市场。
7. **结尾**：承认自己没开过餐饮店，给出能力边界，并以幽默收尾。

结构上的关键动作是**每一步都为下一步铺好视觉依据**：Logo 定完立刻补基础视觉，后面所有物料都写「沿用已确定的 Logo、配色和字体」。这让「一整套」不是把产物堆在一起，而是真的形成链条。

## 可复用的提示词与做法

| 内容 | 原文做法 | 可复用的价值 |
| --- | --- | --- |
| 门店与包装提示词 | 「沿用已经确定的 Logo、配色和字体，继续做门店 VI 和食品包装。先设计门头和店内空间，再出外卖餐盒、手提袋和饮品杯，风格保持一致。」 | 结构清晰：先声明继承的规范，再排定顺序，最后强调一致性 |
| 海报提示词 | 指定唯一品牌标识、画面比例 3:4、高清广告质感、视觉风格（现代东方、留白克制但有烟火气）、使用规范中的颜色、食材保持自然色、版式与文案由其自定义，并说明适用场景（形象海报、门店橱窗、社交平台传播） | 「唯一标识＋比例＋风格＋色彩规则＋适用场景」是可复用的海报提示词骨架 |
| 十秒宣传视频提示词 | 指定 16:9、电影级中式餐饮广告风格、色彩规范、禁止修改附件 Logo，并按秒写出六个镜头的画面与转场（0—1.5 秒河面推进、1.5—3 秒水纹转成汤底、3—6.5 秒三段食材特写、6.5—8 秒夹起鱼片滴汁、8—10 秒拉升俯拍收在 Logo 与文案），末尾列出避免项（空锅、清水感、食材变形、塑料质感、浓雾、乱码、其他品牌标识）与声音设计 | 与本库第七篇的逐秒提示词、第十七篇的节点拆分属同一方法：把连续效果转成时间轴约束。避免项与声音要求一并写出，能显著减少返工 |
| 小程序界面提示词 | 要求高保真、严格延续基础视觉、每次只生成一个页面、列出四个板块各自的职责、其余按成熟产品标准自行补充、使用真实完整内容而非占位素材、达到可直接评审与开发落地的完成度 | 「限定单页 + 板块职责 + 不许用占位素材 + 明确完成度」是界面类需求的实用骨架 |
| 局部重生成 | 包装袋刚生成时局部文字崩掉，作者在画布上框出问题区域直接改字或局部重生成，不用整张推倒 | 与 [[topics/测评问题与实战技巧库]] 中「局部返修而非整段重做」一致 |
| 同画布跨模态 | 做视频不用重新开项目，可以直接在同一块画布上做各种形态的设计，风格不会各走各的 | 跨模态项目的真正难点是风格漂移；同一画布是有价值的机制 |
| 沉淀为专属能力 | 把确认过的整套视觉规范固化成专属能力，之后新物料直接调用，「不用每次都把品牌背景从头讲一遍」 | 把一次性项目的定稿转成可复用资产，是这套流程最有复用价值的一步 |
| 不会写提示词时的替代路径 | 先跟目标工具沟通清楚，或跟其他模型沟通，或找一个做得好的宣传视频喂给大模型反向拆解，再形成自己的提示词 | 给不会写提示词的读者一条可执行路径，而不是只要求「提示词写好一点」 |

## 失败、边界与归因

作者记录了两处明确失败并各自归因。包装袋生成的局部文字崩掉，属于常见的生图缺陷，靠画布框选局部重生成解决。小程序的页面信息密度过高、「我的」页面把功能全堆上来；作者把原因归到自己身上——「因为我本身是想测试，所以对功能的描述不是很清晰」，并给出建议：如果真想要效果很好的页面，自己需要在信息层级与交互逻辑上认真做一遍，再用工具生成。

关于「需求模糊时给选项引导」，作者的评价值得记下来：对不太懂设计的人来说这种追问很有用，「至少不用一上来就面对『请详细描述你的视觉偏好』这种灵魂拷问」。这与本库第十八篇「先出方案再动手」、第六篇「先讨论需求再执行」属同一类做法，都指向一点——**把选择拆成小问题，比要求用户一次说清更好用**。

需要区分清楚的是交付物性质：全部为设计稿与生成素材，文末已标注「内容含AI生成图片」；作者也承认没有实际开店，门店与包装未打样、未施工。「比市面上大部分的点单小程序都强」属个人比较判断，无依据。结尾给新用户积分引导，带推广成分，但同时也给出了能力边界——「能帮你把店做得像个品牌，却不能帮你把味道做好」，这一句有效抵消了夸张标题带来的期待落差。

## 结尾与写作卡片

结尾先讲背景（AI 设计此前多停留在门头与海报，每次新需求都要重新来过，没有整套延续方案），再对比现在可以延续一套完整视觉方案；随后给出边界声明（做得像品牌，但决定复购的是味道），用「省下来的钱、时间和反复沟通的心力，或许真能让开店的人多花点心思回到好不好吃」收束，最后以幽默提问作结。

**写作卡片**：适合全流程设计类实测 → 先交代产品线并提问差异 → 引官方定位并承认拗口 → 自设一个可控的测试对象并加免责声明 → 先给整套效果 → 每步都声明继承哪套规范 → 给可复制的完整提示词 → 记录失败并归因 → 把定稿沉淀成可复用资产 → 结尾声明能力边界并标注素材来源。
