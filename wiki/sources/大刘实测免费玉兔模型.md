## 主问题

神秘免费模型 Space Bunny 如何通过 OpenCode 或 OpenRouter 接入，其在 3D 网页、交互游戏和长程研究任务中的表现，是否足以成为 DeepSeek V4.1 Flash 的同档竞争者？

## 目标读者

适合已有终端或 Agent 基础、希望低成本试用新模型的开发者、Vibe Coder，以及想用 AI 制作交互网页、小游戏或研究看板的读者。纯新手可以照着 OpenRouter 配置，但文章没有解释命令行环境、API 安全、代码运行与部署细节；需要严格基准测试、金融事实核验或生产稳定性承诺的专业读者不能只依赖本文结论。

## 主研究对象

主要评测对象是 OpenRouter 上处于免费预览阶段的 stealth/space-bunny-alpha，作者称其具有 1M 上下文、多模态输入和 reasoning 能力，并把它视为 Flash 模型；对照对象为 DeepSeek V4.1 Flash。接入载体包括 OpenCode CLI 和 WorkBuddy，测试任务覆盖 Three.js 3D 街景、天文信息网页、Crossy Road 式小游戏及 Anthropic 估值研究看板。

## 证据身份与分项边界

证据以作者亲测为主，但完整度不一。接入部分给出了 OpenCode 安装命令、模型名称、OpenRouter 接口地址与 API Key 创建入口，并报告 WorkBuddy 测试连接成功。横向测评中，作者称 3D 街景两模型均为一次直出，Space Bunny 用时30分钟、比 DeepSeek V4.1 Flash 快15分钟；这是作者报告，未交代设备、网络、生成代码量、计时起止点和重复次数。街景、小游戏的质量结论主要来自作者肉眼判断，原文媒体未提供给本次分析，无法复核画面。赏月页报告模型会搜索资料并呈现月相变化，但没有展示来源、算法、误差或独立天文校验。估值看板被评价为像正式研报，同时作者明确承认存在内容不全。关于模型身份、原生多模态预训练和厂商归属均没有官方确认；引用 OpenCode 联合创始人 Dax 的看法也只是外部观点，不是性能验证。

## 标题承诺与开头

标题用“神秘玉兔模型炸榜”“Deepseek V4.1 Flash的对手”和“附免费调用方法”制造三重承诺：身份悬念、性能对标、立即可用。正文兑现了免费调用步骤，也确实安排了四类任务与 DeepSeek 对照，但“炸榜”只由“上线三天，冲上了榜首”支撑，没有说明具体榜单、统计口径和时间截面；“真正对手”主要是作者体感而非标准化评测。开头先用“够强还免费”和假期玩 AI 的场景降低尝试门槛，再以无发布会、无厂商名、无跑分强化神秘感，迅速转入安装配置。

## 结构与转场

正文先交代模型突然出现、免费和参数信息，再以“先带大家用上它”转入两条接入路径：OpenCode CLI 与 OpenRouter API。完成配置后，作者先给出四点总体体感，再用四个 CASE 展开：3D 日系街景负责直观展示和与 DeepSeek 的速度、细节对比；赏月页测试联网事实、推理和页面呈现；送月饼游戏测试连续地形、碰撞与交互机制；Anthropic 估值看板测试长程研究。案例之后回收为“最高一档”和“速度快”两点结论，再转向厂商身份猜测，最后以免费预览和假期动手尝试收束。转场总体按“能否接入—效果如何—是谁做的—为什么现在值得用”推进，但参数判断、模型来源猜测与实测结论混在一起，证据层级没有始终明确标注。

## 案例：目标、输入、操作、结果与人工成本

案例1为作者亲测的 3D Coding 对照。真实目标是制作可步行、可转头、可自由观察的夏末傍晚日本郊区 Three.js 场景；输入是包含铁路道口、坡路、杂货店、售货机、自行车、住宅、电线、远山、动画和控制方式的完整提示词；操作是分别让 Space Bunny 与 DeepSeek V4.1 Flash 生成；结果据作者观察，两者都有日漫感，Space Bunny 在房屋纹理和街道细节上略好，Space Bunny 用时30分钟且比对照快15分钟，两者一次直出；作者报告没有人工修正；成本称当前模型免费，但未给 token、OpenRouter 限额、运行环境与电力成本。案例2为作者亲测的网页 Coding。目标是制作单文件 HTML 赏月页，按北京时间显示2026年9月月相、农历、照亮比例及满月跳转；输入明确要求可靠天文规律、注明方法和精度；操作中模型据称自行搜索今年满月与中秋关系；结果显示中秋并非满月、约到27日才满月，拖动日期月面会变化；未给人工修正、生成耗时、数据来源、算法精度和成本。案例3为作者亲测的交互游戏对照。目标是用 Three.js r160 制作中秋版 Crossy Road，包含逐格移动、车辆碰撞、浮木、落水、程序化地形、计分与本地最高分；同一输入分别交给两模型；结果据作者称两者玩法机制都完成，画面均较简陋，Space Bunny 在兔子建模、纹理和场景细节上略胜；未给耗时、代码错误、人工修正、运行设备、帧率与成本。案例4为作者亲测的长程研究任务。目标是制作单 HTML 的 Anthropic 两万亿美元估值研究看板，核实融资、IPO、收入并建立三种情景、估值反推和敏感性表；结果据作者观察，页面像正式研报、排版舒适、内容有条理，可作为后续研究底稿，但存在内容不全；未展示来源清单、计算结果、公式核验、事实错误、耗时、人工修正与成本。另有第三方观点：作者提到 OpenCode 联合创始人 Dax 对 Space Bunny 等开源模型多模态表现的期待，这不是本文作者的实测结果，也不是官方性能证明。

## 解释、语言与图文作用

解释方式偏体验驱动：先用“日漫小街”“中秋月亮”“送月饼”等易感知任务展示能力，再把观察归纳为视觉、知识和长程思考优势。语言口语化且节奏快，常用“薅起来”“可劲儿薅”“你品品”“小胜一丢丢”降低技术门槛；提示词则非常具体，用可验收条件约束空间布局、交互和事实性。弱点是“从 token 速度看是 Flash”“从参数看应该是大厂之作”“原生多模态预训练”等解释缺乏可追溯技术证据，主观画质判断也未转化为统一评分表。

## 结尾收束

结尾先承认模型仍处免费预览阶段、厂商和未来价格未知，再列出 Kimi、Grok、MiniMax 三种归属猜测，随后把价值落到普通人尝试想法的成本下降。最终行动号召分两层：先让读者趁免费拿自己的小需求测试，再请求点赞、在看、转发和星标，并附作者身份介绍。

## 限制与不可照搬处

作者没有确认 Space Bunny 的开发者、正式型号、许可、数据政策、免费期限、调用限额和未来价格；所谓榜首未给榜单名称与口径。1M 上下文、多模态、reasoning、Flash 属性及“首个在多模态数据上原生预训练”等说法未在文中提供官方文档验证。四个案例缺少可下载代码、固定环境、重复运行、盲评和统一评分标准，除街景外基本未给耗时，全部未给 token 用量；原文中的视觉媒体本次未看，无法独立检查画面、交互与一次直出情况。金融看板明确有内容不全，事实和公式也未独立核实。厂商猜测不能当成结论，所有速度和质量数字仅是作者报告。

## 可迁移的编辑动作

编辑同类新模型测评时，可保留“先给可复制接入步骤，再做由直观到复杂的任务梯度”的框架，但应把事实、作者亲测、第三方观点和猜测分栏。横评需固定同一提示词、模型参数、工具版本、运行环境和计时起止点，至少重复三次；每个案例公开原始输出、人工修改记录、失败日志、token 与费用。视觉任务可建立需求清单，逐项检查物体完整性、交互正确性、帧率和跨视角稳定性；研究任务则应抽样核对来源日期、数字口径和公式。标题若使用“炸榜”或“真正对手”，正文必须给出明确榜单和可重复基准，否则改成“免费预览实测”更准确。

面向想低成本制作交互网页的独立开发者，我会用同一份“可交互社区地图”需求测试 Space Bunny 与一个已知 Flash 模型。自己的输入将包含20项验收条件、三张参考图、指定 Three.js 版本和移动端性能要求；第一步是在全新项目中固定温度、思考强度与最大输出，分别运行三次并保存完整对话和代码。观察点包括首轮可运行率、需求完成率、视觉相似度、交互错误数、平均耗时、token、人工修复分钟数及移动端帧率。所需证据是屏幕录像、Git diff、控制台日志、Lighthouse 报告、逐项验收表、API 用量账单和第三方盲评结果。
