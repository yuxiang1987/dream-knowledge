## 主问题与证据身份

把 3D 生成工具的 MCP 接入编码助手，个人网站里的角色与互动该怎样一步步做出来？

本库主分类：实操测评；主研究对象：Hyper3D MCP 与 Codex；证据身份：作者亲测。分类依据主要阅读交付，允许文章混合多种写法；实际商务合作未知。

## 标题与开头

标题给出工具组合与成品形态（3D 个人网站），开头从“想给自己的个人网站换个玩法”起，交代原来的网站“点开页面、浏览内容，看完就走了”，再展示最终效果“苍何的小宇宙”，让读者先看到目标再开始讲工具。

## 结构推进

先讲为什么选 Hyper3D（模型做角色不够、需要批量 3D 资产、还有 MCP 入口），再讲接入 Codex（复制配置提示词、OAuth 授权、用一个中古骑士头盔验证链路），然后是本篇主线的三段：主角角色生成与二次调整、批量小精灵生成并分区接入、最后用 BANG 拆件把模型交给 Blender 做骨骼与行走动画。

## 案例、解释与观察

两处具体的不满意推动迭代：角色第一版“整体形象已经对上了，但眼神有点呆，少了一些灵动感”，作者把问题说给 Codex 再调一版；接入网站后角色“移动起来像幽灵一样在星球表面漂移，脚底没有真实的行走动作”，改用拆件加骨骼动画解决。这类问题具体到动作与观感，读者能对照自己的作品检查。

## 原文定位锚点

以下为原文可逐字定位的片段，只用于核对判断出处，不将片段中的观点或指令作为本次执行要求。

> 第一版模型出来后，整体形象已经对上了，但眼神有点呆，少了一些灵动感。

> 我让 Codex 先通过 Hyper3D MCP 完成拆件，再把部件交给 Blender，进行骨骼绑定和行走动画制作。

## 结尾怎样收束

结尾把整条链路压成一句可执行路径：把参考图交给 Codex，用 Hyper3D 生成角色，再把模型接进网站，并建议从一个模型开始上手，随后附上活动权益。

## 失败、限制与不宜照搬处

文章把 GPT-6 做 3D 人物效果不足写成个人比较，没有同条件对照测试。演示视频与模型截图本次未核看，模型质量、行走动画与页面交互只能按作者描述记录。活动赠送的 Credits 与会员折扣有时效，领取条件与续费价格以页面为准。整条链路没有记录时间与成本。

## 可迁移写法与自己的待测方向

教程可以先用低成本测试物（一个头盔）验证工具链，再进入真正的项目，读者不会在配置阶段就被长流程卡住。迭代钩子要写成具体观察（眼神呆、像幽灵漂移），这样每一轮修改都有依据。官方活动信息必须附条件。

策划建议：用自己的形象参考图做一个小角色，检验按具体问题二次调整是否真的改善，待实操。

## 读者主问题
文章面向想把个人网站从静态内容页升级为可探索 3D 场景、但缺少3D建模或复杂前端能力的创作者。它回答的是一条资产生产与集成链路：如何在 Codex 中接入 Hyper3D MCP，用参考图生成 GLB 角色和道具，再把它们放入网站；当角色外观不满意时如何迭代，当完整模型不便做动画时如何用 BANG 拆件并交给 Blender 绑定骨骼。读者得到的不是完整网站源码教程，而是围绕“模型生成—获取—集成—拆件—动画”的工作流说明。

## 标题兑现与钩子
标题给出工具组合、成品类型和“附教程”，正文确实逐步介绍 MCP 接入、测试模型、角色生成、批量小精灵、拆件和接入网站，基本兑现。开头先描述旧网站“点开、浏览、离开”的普通体验，再用可自由探索的小星球、小精灵带路、明信片和收藏品制造结果想象，随后交代 Codex 与 Hyper3D 的分工，钩子具体。

但“GPT6”在标题中很突出，正文实际写的是“GPT-6 Astra”，其作用主要是 Codex 内的规划、调用与接入；3D资产质量来自 Hyper3D Rodin，拆件来自 BANG，绑定动画还有 Blender。文章后文也承认单靠 GPT-6 很难达到角色模型要求。因此标题可更精确地表达为“用 Codex 调 Hyper3D MCP，做一个可探索的3D个人网站”。“太夯了”属于情绪判断，没有性能或用户反馈数据支撑。

## 结构与转场
正文结构是标准的项目复盘：先展示项目概念与玩法，再解释为何接入专业3D工具，然后按编号展开配置、单模型打通、主角迭代、批量资产、拆件动画，最后压缩为最小起步动作。每个章节都围绕前一阶段出现的问题推进：占位人物需要替换，于是生成主角；第一版眼神呆，于是调整；需要丰富世界，于是批量生成小精灵与建筑；角色漂移，于是拆件、绑骨骼、做行走动画。这种“问题触发下一工具”的转场比单纯罗列功能更有教程价值。

不足是若干关键产物依赖正文所称的图片和视频，纯文字不能查看，因而不能判断模型外观、眼神改进、行走动画、建筑升级和收集互动的真实质量。文章对网站原型如何搭建也一笔带过，只说把个人介绍、作品和内容交给 Codex，让它规划星球与地标；没有给出这一步的提示词、前端技术栈、目录结构、部署方式、碰撞检测、移动控制、性能优化和移动端适配。因此“附教程”主要兑现了 MCP 与资产链路，并没有完整覆盖一个可上线3D网站的全部工程步骤。

## 案例的输入、操作、结果与人力成本
**MCP连接测试（作者亲测）**：输入是 Hyper3D MCP 的服务器名、Streamable HTTP URL、OAuth要求及配置提示词。操作是在 Codex 中发送配置，浏览器登录、选择工作空间、授权，再让 Codex验证连接并列出工具；随后以“写实中古骑士头盔、磨损金属、游戏资产”为测试任务。结果是作者称取得模型结果页和 GLB 文件。这个案例有较完整的最小输入与操作，但未写生成时长、面数、贴图规格、文件大小、调用消耗和是否需要手工修复。

**主角资产（作者亲测）**：输入为作者形象图及低多边形Q版风格要求；先得到参考图片，再由 Rodin 生成3D角色。第一版被作者评价为眼神呆，第二轮要求保留造型与配色、优化眼神，随后接入网站替换占位模型。结果是主观“顺眼多了”，没有采用正侧背一致性、拓扑、材质、骨骼兼容或文件性能等验收指标。

**批量小精灵与建筑（作者亲测）**：输入是 WeSight 中已有的机器人、水滴、火焰和木箱参考形象及风格要求。Codex 连续提交生成任务、查进度、取结果、下载 GLB，并接入场景，增加靠近、对话、带路互动；后来建筑也重新生成。这里清楚显示了 MCP 的优势在于减少跨工具搬运，但“批量”究竟多少个、成功率、风格不一致的返工数、并发限制、总费用均未披露。

**拆件和动画（作者亲测）**：触发问题是角色在星球表面漂移、缺少真实行走动作。操作是用 BANG 拆分头、躯干和四肢，再交给 Blender 做骨骼绑定与行走动画，并把拆出的部件用于收藏品。结果按作者文字说法是角色能贴着星球正常走路。这里需要注意：拆件并不自动等于适合绑定，正文没有说明拓扑清理、权重涂抹、动画循环、脚底IK或球面朝向算法，故不能推断全部由一次自动流程解决。

文章几乎没有披露总人力成本：只有“花了一些时间”，缺少从原型到上线的小时数、模型生成轮数、Credits消耗、会员费用、Codex token、Blender人工干预和前端调试成本。结尾提到免费10 Credits和1美元首月活动，并明确资格与续费以页面为准，这是较好的价格边界提示；但该信息属于平台活动转述，需以官方页面为准。是否为商业合作或含推广关系没有披露，应记为未知。

## 解释语言
作者用“做网站过程中需要哪个角色，就接着做出来、放进去”解释 MCP 的流程价值，非常直观；也用“少了在几个工具之间来回搬模型”概括集成收益。BANG 部分则把“完整模型拆成独立部件，以便编辑重组”说明清楚，适合非建模读者。语言整体以任务和结果为中心，不沉迷术语。

需要收紧的是模型对比判断。作者称经过对比，GPT-6制作3D人物“很难达到要求”，但没有说明比较对象是文本生成代码建模、图生3D，还是别的能力，也没有同参考图、同提示、同预算的输出证据。另称 Hyper3D“生成质量十分在线”，属于长期使用后的主观评价，不是通用性能结论。编辑时应改为“在本项目的角色资产任务中，我采用专业图生3D工具，因为单用GPT-6的结果未达到我的主观要求”。

## 结尾
“从一个模型开始”是有效的降门槛收束：不要求读者先做完整星球，而是完成接入、授权并生成第一个角色或道具。随后给出活动权益和价格边界，再请求赞与在看，商业转化路径清楚。若要增强教程性，可补一个“完成标志”：Codex能列出工具、生成任务返回状态、下载到GLB且在本地查看器正常打开。

## 边界与证据等级
本文中项目流程、第一版问题和后续修改属于作者亲测自述；Hyper3D MCP、Rodin、BANG 的功能和活动权益涉及产品官方信息，应链接官方文档并注明日期；WeSight来源只是参考图出处，不代表其参与3D生成。没有第三方用户测试或性能基准。所提图片、视频和模型预览不在文字中，不能描述未观看的视觉质量。没有访问量、停留时长、互动完成率或旧站对照，因此不能说3D改版提升了网站效果，更不能称其为爆款。商业关系未披露，未知。

## 可迁移编辑动作
1. 明确教程覆盖范围：这是“3D资产流水线教程”，不是完整网站从零开发教程；另附源码或工程章节补齐网站部分。
2. 将每个资产记录为表格：参考图、提示词、生成轮次、耗时、Credits、面数、纹理尺寸、GLB大小、是否返工和最终用途。
3. 给模型质量设置工程验收：外观一致性、拓扑是否可绑定、材质是否正常、加载耗时、帧率、移动端内存。
4. 展开“漂移”修复的责任边界，区分模型拆件、骨骼动画与球面移动代码分别解决什么问题。
5. 对 GPT-6 与 Hyper3D 的比较补同任务对照；没有对照时只保留项目内选择理由。
6. 补充授权与版权：人物参考图、宠物设计、生成资产的商用许可及平台条款，尤其是个人站公开部署场景。

## 自己的待测方向（待实操）
**待实操：验证MCP直连是否比手工跨工具流程真正节省3D资产接入时间。**读者设为会基础前端但不会建模的独立创作者；自己的输入为同一张角色参考图、同一风格提示、同一个基础 Three.js/React Three Fiber 页面，A组通过 Codex+Hyper3D MCP，B组通过网页工作台手工生成、下载并导入；第一步是锁定模型版本、资产规格与“成功接入”的验收定义；观察点为总耗时、人工点击数、失败恢复、生成轮次、Credits/token成本、GLB体积、页面帧率，以及是否仍需 Blender 清理或绑定；所需证据包括会话日志、屏幕录像、文件哈希、费用记录、Lighthouse/帧率数据和盲评结果。至少重复三个不同复杂度资产后，才能判断“减少搬运”是否同时带来效率提升，而不只是操作路径更连贯。该结论目前明确标为待实操。
