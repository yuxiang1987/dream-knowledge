### 主问题、读者与证据
文章讨论长任务里如何减少Token，并让Agent跨会话复用信息。目标读者是使用Hermes、OpenClaw处理代码分析、搜索、日志等长任务的个人开发者、OPC和多Agent团队。类型是开源插件安装教程、功能实测和产品推荐。核心证据是郭震自述的安装、L0-L3写入/召回、OpenClaw上下文卸载及Token前后对比；12.1K star、Memory Hub能力和分层机制也含项目官方描述。标题写“省了50%”，正文报告55.7%，数值方向兑现，但测量设计仍不足以证明普遍节省。

### 标题兑现与开头
开头准确抓住“长对话反复携带代码、日志”的成本痛点，立刻展示接入前后55.7%与逐轮曲线，再说明外部记忆和团队资产，吸引力强。随后给出机制解释：大内容放到外部文件，上下文保留Mermaid任务图。问题、结果、机制、教程的顺序有效。但标题同时写“Hermes和OpenClaw都支持”，正文只完整给Hermes命令，OpenClaw称方法类似，没有完整安装步骤，兑现不对称。

### 结构与转场
第一节安装Hermes并简述OpenClaw；第二节解释原生记忆不足及插件的三项作用；第三节依次验证L0-L3沉淀、跨会话召回、长任务Offload与Token压缩；结尾总结成本价值。由“为什么需要”过渡到“三大能力”合理；但三项能力实际上包含分层记忆、召回、卸载，缺少纠错准确率和对任务质量影响的独立验证。

### 逐例核对
1. **Hermes安装，作者亲测自述**：目标是接入外部记忆；输入为源码、本地目录、批处理命令、模型配置及`hermes config set memory.provider memory_tencentdb`；操作是安装、监听8420端口并设置provider；结果称界面出现、安装成功；安装耗时、操作系统版本、模型名、模型调用成本和排错人工成本未提供。
2. **偏好写入L0-L3，作者亲测自述**：目标是验证长期记忆分层；输入含“Project-47”“中文输出”“先结论、后证据”等要求；操作为连续多轮发送并查询记忆库；结果称L0保存原始对话，L1提取长期要求，L2形成Excel可视化与插件分析场景块，L3总结开发能力、协作方式和工具偏好；各层生成延迟、错误项、人工纠正次数未提供。
3. **新会话召回，作者亲测自述**：目标是验证跨会话复用；输入是让Hermes核对L0-L3；操作为重开会话并触发搜索工具；结果称四层均参与回答并自动注入场景、画像；没有展示盲测问题、召回率、错误记忆或无插件对照，人工成本未提供。
4. **OpenClaw长任务卸载，作者亲测自述**：目标是降低长任务上下文；输入所对应的具体任务、提示词正文未提供；操作为让工具结果写入`refs`，生成23KB Offload索引与Mermaid图，以`node_id`按需回查；结果称主上下文只留摘要和索引；是否遗漏关键细节、回查延迟和人工复核成本未提供。
5. **Token对比，作者亲测自述**：目标是量化节省；条件声称同一会话、同一模型、同一提示词；操作是在压缩前后观察调用；结果由32,935降至15,974 Token，并总结总体减少约55.7%，七轮中第六轮发生压缩。按这两个单次数字计算降幅约51.5%，55.7%应来自开头另一组总体对比，但原始逐轮数字在文字中未完整列出，不能混为同一口径。时间、模型、缓存、工具返回差异和输出质量控制未提供。
6. **Memory Hub与12.1K star，项目官方/公开指标主张**：目标是团队统一管理Chat Memory、Skill、Wiki、CodeGraph、版本和权限；本文未展示作者完整团队实测，不能当作已验证结果。
