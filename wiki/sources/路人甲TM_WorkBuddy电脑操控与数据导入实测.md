# 路人甲TM_WorkBuddy电脑操控与数据导入实测

- 原题《又一个神级功能，让WorkBuddy可以像真人一样接管你的电脑》，署名路人甲TM，账号路人甲TM（`gh_d516081071ec`），发布时间 `2026-11-24 20:43`，[微信原文](https://mp.weixin.qq.com/s?__biz=MzIzMDQyMjcxOA%3D%3D&mid=2247524841&idx=1&sn=ae4edef7d17ccdc6022cc29d4dbe04fa)。核对原链、原题与正文，未见同作品旧 source，独立新建 source 页（不同于先前 WorkBuddy 企微/原位改稿/日活观点等旧作）。
- 实际阅读范围：通读 raw 全部可提取正文文字 P1—P73；原文含 11 个图片/动图占位（其中 P1、P32、P49 为 GIF 动画），**图片与动图未核看**，未运行 WorkBuddy 5.11.0 客户端或 Blender / JS Paint。
- 读者：需要操作无 API 桌面专业软件（如三维建模）或重复桌面点击任务，同时担心多台电脑任务割裂的个人用户。主问题：WorkBuddy 新增的 Computer Use（电脑操控）在无接口桌面软件上的实际开启条件、后台运行边界是什么，数据导入解决了什么跨设备问题？
- 主分类：实操测评；主研究对象：WorkBuddy（客户端 5.11.0+，Computer Use 技能与跨电脑数据导入功能）。
- 逐项证据身份：
  - **产品功能与门槛信息**：客户端需更新至 5.11.0 及以上支持 Mac/Windows，Mac 需在隐私与安全性中开启“辅助功能”和“录屏与系统录音”，安装 `WorkBuddy-computer-use` 技能；另有设置内“数据导入”（含任务详情与定时任务）。
  - **作者亲测自述**（动图与截图未核看）：① 用 WorkBuddy 自动打开 JS Paint 绘制 PNG（P1—P2）；② 作者自述学三天 Blender 连立方体都没搞定，用一句话提示词“建一座极高细节的圣诞树”让 WorkBuddy 先出静帧再输出动画（P26—P34）；③ 升级提示词“操作blender软件，在Blender里建一座极高细节的宝塔并让它动起来”，作者边打一局王者荣耀边让其后台小窗运行并完成动画渲染（P37—P51）。
  - **机制与价值解释**（作者推测与体感）：归功于大模型视觉理解界面→判断点击→观察结果的循环；将交互历史总结为“命令行→图形界面让人学软件→AI 睁眼学界面”。

## 标题与开头

标题用“像真人一样接管你的电脑”定调，但正文并没有停在“全自动替代人”，而在 P46—P47 主动交代了独占冲突与敏感操作必须人确认的限制。开头 P1—P3 用“先看动图 + 我手放在桌上没碰鼠标”建立直观反差，引出 JS Paint 绘图和 Computer Use 新功能。

标题兑现情况：正文演示了 JS Paint 和 Blender 两次无接口桌面软件操控并附开启步骤，兑现了“接管电脑操作软件”的主题；但“像真人一样”未核看实际动图，且 Blender 仅靠一句话提示词产出效果的精度、渲染耗时和失败重试次数均未给出量化记录。

## 结构推进

JS Paint 动画结果先行 → 补全 WorkBuddy 能力版图（文档/连接器/浏览器之后补桌面端最后一块） → 开启步骤与 Mac 权限路径 → 个人学 Blender 挫败铺垫 → 一句话圣诞树测试（先静帧后动画） → 升级宝塔动画测试＋并行画中画与敏感操作人工确认边界 → 绕过软件门槛与重复碎活的价值判断 → 顺便介绍“数据导入”解决公司/家里两台电脑割裂 → “人机互迁”收尾。

推进特色在于**先拿“我学三天连立方体都没做出”做低起点自嘲，再用 Blender 圣诞树和宝塔两次递进验证**，并在等待渲染的空档自然带出“侧边栏画中画不占主屏 + 同一软件同时只能一方操作 + 支付/登录留给人确认”三条实用边界。

## 原文定位锚点

- P28，工程减负判断：`WorkBuddy先出了一张静帧。三维这东西，建模、材质、灯光、相机，哪一步崩了，最后都是一团糊，先看一张图最省事。`
- P46—P47，操作独占与高危边界：`它正在用的那个软件，同一时间只能有一方操作，我想进去点两下，得先让它停。` / `碰到登录、授权、支付这类敏感操作也一样。它负责把前面的准备都做完，最后一步由我确认，不会自己一路点到底。`
- P71，核心交互转向：`它不再要求我学它的语言，而是自己睁开眼，看软件界面，然后直接点鼠标动手，要知道，这些老古董软件，过去只有专业的人来了才能操作`

## 结尾怎样收束

先用“数据导入”补齐日常多端办公痛点，再在“写在最后”把 Computer Use 拔高到“人机互相迁就历史”的反转（从人学命令/图标变成工具看界面），最后落回“工具最好的归宿是被人忘记存在”“人负责想，AI负责干”。

## 失败、限制与不宜照搬处

- 失败与缺失记录：正文未记录 Computer Use 点错按钮、死循环、识别偏差等失败案例，按规则写“未提供失败过程”，不替作者补写失败。
- 权限与安全盲区：Mac 辅助功能＋录屏授权属于高系统权限，Windows 所需权限、隔离沙箱与误点非目标窗口的防护机制均未交代；文中也未说明 Blender 生成动画的具体耗时、token/积分成本及对电脑配置的要求。

## 可迁移写法与自己的待测方向

- 可迁移动作：介绍桌面操作类功能时，把“系统权限怎么开”“人机操作哪一刻会抢鼠标”“敏感确认卡在哪里”和“等待期间如何监督（画中画/静帧先验）”紧挨着成果写，用真实小步验收（先静帧后动画）代替只吹“全自动”。
- **待实操**：面向需要处理无 API 桌面软件重复点击任务的创作者，在独立测试账号或虚拟机环境下输入一款自己熟悉的轻量绘图/表格桌面软件及 1 个含 5 步菜单操作的脱敏任务。第一步先只授权单个测试窗口并记录屏幕与操作轨迹，让工具“先出静帧/首步预览再继续”，并刻意加入 1 个需确认的保存或弹窗步骤。观察鼠标点击准确率、中途接管是否卡死、误触外部窗口风险、总耗时与 Token 消耗。需保留录屏、操作日志、权限清单与账单，未验证本账号读者效果。
