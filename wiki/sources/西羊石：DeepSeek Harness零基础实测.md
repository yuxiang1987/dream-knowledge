## 逐案例与操作拆解
1. **AIPPT横评**：目标是让三种Harness环境中的DeepSeek复刻Harness官方风格并制作AIPPT工具；输入的完整需求、素材、模型参数未提供。WorkBuddy几分钟给第一版，可编辑且内嵌预览，但缓存命中不可见；DSH的Flash约10分钟、效果一般，作者报告缓存命中99%，再用V4 Pro优化后功能更全但无质变；Codex借自身多模态把视觉转成文字给DeepSeek，约半小时，产物可编辑、切换风格并接API润色。人工修正包括DSH换V4 Pro继续优化；各方案实际Token和总价格未给，重复测试次数未给，也没有统一盲评。因此只能说明作者在这一次任务中的体感，不能证明DSH长期必然最省。
2. **十分钟启动**：目标是让DSH网页端正常回复；输入为Node.js、DeepSeek API Key与余额；Windows运行`npx.cmd @deepseek-ai/dsh web`，Mac运行`npx @deepseek-ai/dsh web`，访问本地3080端口，终端保持开启；再填Key、选Flash/V4 Pro、标准模式和空工作区，发测试句。结果标准是正常回复。文章提供脚本限制、转圈、余额等排障。实际安装耗时、系统版本、失败记录未提供，“10分钟”不适用于下载慢或依赖报错环境。
3. **Kimi配置**：目标是让DSH使用其他模型；操作为设置—模型—添加提供方—kimi-coding—填Key—获取模型—保存，作者建议尽量Full access，同时提醒批量删除人工确认。是否实际跑任务、成本和兼容问题未提供。
4. **四种模式**：标准用于日常文件与规划，PTC用于文件多步骤多，极简用于研究评测，创造用于插件与预设。这里是功能分类，不是逐模式实测；文章未给四模式同任务对照。
5. **三个插件**：dsh-at-file用于@引用工作区路径；ModLens借外部视觉引擎把图像证据转成文字；dsh-genui将结果渲染成卡片、图表和表单。作者描述了用途和自己的“AI夜班研究员”需求，但未提供完整安装、版本、权限、错误和耗时。插件生态被明确评价为不成熟，可能遇到依赖问题，这是文章的重要负面记录。
