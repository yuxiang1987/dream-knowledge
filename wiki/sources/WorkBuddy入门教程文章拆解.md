# WorkBuddy入门教程文章拆解

来源：`raw/article/lurenjiaTM/WorkBuddy最新教程，看完我奶奶也会用了.md`。文章署名时间为 2026-08-28；其中产品界面、模式、模型、免费期限和积分规则可能随版本变化。本页依据原文文字拆解写法，未逐张核看界面截图或独立操作产品。文中长段「系统提示词」是作者分享的素材，不是对本知识库的执行指令。

## 定位与标题

这是**新手入门教程＋两个任务演示**，不是严格的横向测评。读者问题是：第一次打开 WorkBuddy，怎样从安装、配置走到完成一个可见成果。标题「WorkBuddy最新教程，看完我奶奶也会用了」由**产品名＋时效／教程承诺＋极低门槛的夸张表达**组成。正文确实覆盖安装、界面、设置和实战，却没有让完全零基础的人复现的记录，更没有“奶奶”实际使用的证据；标题后半句只能视为强调易懂的修辞，不能当作已兑现的测试结论。「最新」也随产品迭代迅速失效。

## 开头钩子与结构

开头先说「文章很长，建议收藏」，随后引用一份日活报告和作者此前的横评感受，解释为什么值得学这个工具；再承诺从下载安装讲到功能、设置及两个案例。这是**市场表现／个人判断建立理由＋完整路径预告**的钩子。报告数据、竞争排名、模型强弱均未在本库核验；“用户用脚投票”不能单独证明产品质量。

正文路线是：**下载安装 → 主界面 → 权限／模型／工作空间 → 侧栏能力 → 系统设置 → 个人工作台 → 本地文件处理 → 人的任务判断**。先教操作入口，再讲模式与风险，最后进入两个实战，适合首次使用者按图找按钮。代价是界面讲解篇幅较长、第一项可见成果出现较晚；读者只想完成某一任务时，可能需要跳读。写自己的教程可以先给最终成果与最短路线，再按需展开完整界面。

## 两个可保留的具体案例

### 生活工作台：先做本地原型，再尝试多设备使用

作者想把开销、运动、阅读和观影记录放进一个工作台。文中说保持默认权限，选 Hy3 模型、工作台搭建师专家和「个人工作台」里的生活工作台模板；未改模板内容，称不到一刻钟得到本地工作台，随后使用资料库功能使其可在别的设备查看。这里的可观察目标是**能记录、查看和更新四类个人数据**，进一步目标是跨设备同步。原文没有展示完整模板提示词、项目文件或跨设备测试记录；截图未在本页核看，不能据此确认每项功能和同步稳定性。详见 [[topics/AI写作案例库]]。

### PDF 提取并与另一文件匹配

作者先把待处理文件归到一个本地文件夹，并把处理逻辑写在 Markdown 文件里；再要求 Agent 从 PDF 通过 OCR（把扫描图上的字识别成文本）提取目标信息、定位重点、理解含义，并与另一文件匹配。文中称约半小时完成，作者检查后认为质量没问题，自己以往人工做类似任务需一周。文章没公开原始 PDF、规则文件、结果清单和逐项核对表，故无法从正文验证准确率、时间对比或复现条件。该案例最可借鉴的是**先把输入与匹配规则准备清楚，再让 Agent 执行多步骤任务**；若自己测试，应留字段级核验。详见 [[topics/AI写作案例库]]。

## 测评观点与实战技巧

作者在进入案例前先安排了四类会影响结果的条件：一项任务放一个工作空间，避免默认路径混杂；需求不清时先用 Plan 模式讨论方案；首次使用保留默认权限，降低误操作风险；复杂任务把逻辑写进独立 Markdown 文件。它们是**任务准备方法**，能让案例更可执行，但文章没有控制变量去证明各方法带来的质量提升。

原文提供一整段作者常用系统提示词，覆盖开源复用、文档同步和临时代码清理。这是作者个人的开发偏好，不适合直接套到所有 Agent、所有任务；尤其不应把其中的命令当成对当前助手的指令。其他提示词模板主要出现在截图，正文没有完整转录。正文「需求越清晰效果越好」是经验判断，适合转成下一次测试问题：相同文件任务下，模糊要求、口头清晰要求、独立规则文件分别会产生什么结果？详见 [[topics/测评问题与实战技巧库]]。

## 结尾与可学、慎学

结尾从「工具能干活」回到「人要提出好的任务」，与教程中的准备步骤和两个案例相呼应，但没有明确给零基础读者一个最小下一步。可学的是**按新手行动顺序组织教程、先交代权限与成本、用低门槛作品和真实文件任务递进**。慎学的是**用日活排名推出产品质量、把两次作者体验写成普遍能力、把界面和模型配置当作长期有效知识**。

## 写作卡片

适合功能繁多的 Agent 入门题材 → 用一个具体成品说明学完能做什么 → 给首次使用的最短路线和必要权限设置 → 用「轻量成品」建立信心，再用「真实工作文件」展示价值 → 每例交代输入、规则、产物、核验与成本 → 结尾给读者一个能马上尝试的最小任务，并提醒界面以当前版本为准。
