# 路人甲TM：WorkBuddy千万日活与多模型知识库观点

## 主问题与证据身份

- 原题《日活破千万，WorkBuddy比我想象中跑得更快》，署名路人甲，账号路人甲TM（`gh_d516081071ec`），2026-11-21 12:02，[微信原文](https://mp.weixin.qq.com/s?__biz=MzIzMDQyMjcxOA%3D%3D&mid=2247524718&idx=1&sn=b59233df580e248bd8a912711d648adf)。按原链、原题和六节产品复盘核重，未见同作品旧 source；与同账号此前 WorkBuddy 教程、原位改稿及活动篇不是同作品。
- 通读 raw 可提取正文 P1—P46（非空 HTML 文本块）；原文无嵌图、音视频或外链附件，未核第三方后台数据，未运行工具。
- 读者是关注办公 Agent 选型、好奇为什么身边人持续留存并付费的创作者或职场用户。主问题：WorkBuddy 凭什么从早期尝鲜走到高频留存，除了单点功能外还有哪些产品策略与生态配套？主分类：产品观点（结合身边用户见闻与作者使用习惯复盘）；研究对象是腾讯 WorkBuddy 及 ima、乐享知识库协同。

## 标题与开头

标题用“日活破千万”与“比我想象中跑得更快”组合外部体量冲击与第一人称预期差。开头四段连给日活 1000 万、3 天 ARR 5 亿美元（日均约 137 万美元）两组数字，并用自己跟朋友聊天的口径从“月活几千万”改到“日活已经千万”建立增长体感；上述日活与 ARR 均无官方财报或公告出处，属作者转述未经独立核实的市场传闻。

## 结构推进

数据冲击开场 → 1、身边朋友从怀疑到充会员的四类日常用途 → 2、为什么早期主推它（先发门槛低＋三个月高频迭代） → 3、支持多模型选择的底层产品策略与手机运营商类比 → 4、生态网络效应与 Skill 市场付费意愿 → 5、顺带引出 ima / 乐享知识库配合调用 → 6、自曝腾讯股东立场并顺嘴吐槽腾讯文档收尾。用数字编号串起六个短模块，从用户现象层层退到功能、模型策略、生态和知识库底座。

## 原文定位锚点

- P7，用户留存反差：“其实刚开始让他们用的时候，他们都是怀疑的态度，也不是特别愿意去用，结果我就一直催着他们用，前几天当我们聚餐的时候，我又问了一下，现在他们已经离不开WorkBuddy，而且都充成了会员。”
- P26—P27，多模型策略判断：“那么如果我用一个Harness，你只限定我是用一种模型，这就是很奇怪的事情。”“用什么模型，应该交给用户去选择。”
- P40—P41，知识库协同经验：“你可以把自己的资料都整理到ima，然后从WrokBuddy调用，效果很好，比你直接用WorkBuddy聪明多了，而且出来的效果也惊人。”“我们之前用AI写文章，没有知识库和有知识库出来完全是两回事。”
- P44，利益相关自白：“最后，不停的推荐WorkBuddy还有一些私心，毕竟我是腾讯坚定不移的股东，哈哈哈。”

## 结尾怎样收束

先用“我是腾讯坚定不移的股东”坦白推荐私心，化解整篇持续夸赞带来的推销防御；最后用浅灰色小字突然补一句“腾讯文档太难用了”，用同厂产品的真实槽点做反差收尾。

## 失败、限制与不宜照搬处

全文属于口语化随笔与产品观点，没有提供任何一项任务的具体提示词、操作步骤、前后输出对照或积分消耗账单，因此不立实测案例卡。日活千万与 ARR 数字、朋友节省排期和财务工程化效果均不可直接引用为事实；股东自白和顺嘴吐槽属于作者个人身份与风格，不能移植为自己的经历。本轮单篇阅读快照 6705（含系统推荐，单样本中位数 6705），不构成日常基线，也不把阅读或转发写成写法因果。

## 可迁移写法与自己的待测方向

- 可迁移写法：写产品长期复盘或观点文时，先用“我没充会员但当年催着用的人全充了会员”引出不同角色拿它干什么，再把功能迭代提升到“Harness 不该绑定单一模型（如手机不绑死单一运营商）”与“通用 Agent + 个人知识库”两层产品逻辑，最后主动交代个人偏好立场并留一个真实槽点。
- **待实操**：面向用 AI 辅助写稿的内容创作者，用本库已脱敏的 10 篇历史拆解笔记作为本地知识库输入。第一步在同一写作任务下分别跑“直接让办公 Agent 写提纲”与“挂载知识库后再写提纲”两组首轮输出；观察是否真实引用库内结构规则、有几处编造事实以及人工返修耗时，保存两侧原始输入、完整输出与修改记录。未验证本账号读者效果。
