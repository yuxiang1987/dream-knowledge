通过聊天我发现，大多数朋友还停留在「装好就用」这一步。打开对话框，交代任务，至于设置里有哪些选项，却没怎么关注过。

## 先看存储路径，别让 C 盘越用越满

这个设置我放到第一个说，因为我觉得很多小伙伴一定没注意过这个问题，我也是在使用了一段时间后才发现的。

因为我电脑的磁盘只有 512G，C盘更是只有可怜的125G。再用了 WorkBuddy 一段时间后，发现C盘动不动就满了。搞得我不得不过几天就清理一下C盘。

后来，我还赶上硬盘涨价，忍痛加了一块 1TB 的固态硬盘，真是肝疼！

折腾了一段时间后，我才发现，虽然我把 WorkBuddy 安装到了D盘，但它的系统缓存目录还在 C 盘。

==你再用 WorkBuddy 写代码、处理日常办公任务的时候，它就会把大量的缓存文件写到C盘。所以我建议 Windows 的用户一定要注意一下这个设置（使用Mac的小伙伴可以忽略）。==

**打开「设置」，选择「通用」，找到存储 更改 WorkBuddy 默认工作空间存储路径。**
![[file-20261116214902068.png]]
==这里提醒一下，刚开始用 WorkBuddy 的小伙伴一定要改一下缓存路径。已经有自己的工作流或者使用时间很久的小伙伴，可以让 WorkBuddy 写一个脚本帮助自己迁移数据，迁移之前一定要做好备份哈。==

## 自定义指令，把常用要求提前说清楚

我在使用新的 Agent 工具前，都会先设置一下这个自定义指令的配置。==所谓自定义指令，就是提前给 Agent 定好一些约束规则，之后的对话和任务都会默认参考这些要求，省得每次都重复交代。==

用过 Claude Code、Codex 或 OpenCode 的朋友，一定知道 CLAUDE.md、AGENTS.md 这样的规则文件。WorkBuddy 则可以直接在设置里填写。

**打开「设置」，选择「个性化」，找到「给 WorkBuddy 的指令」，点击右侧的「编辑」，填入内容后保存。**
![[file-20261116225021232.png]]
下面这份是我常用的指令，大家可以直接使用，也可以根据自己的需求做调整。

```自定义指令
# 行为准则  
减少常见 LLM 编码错误的行为准则。可根据需要与项目特定说明合并使用。  
权衡：这些准则偏向谨慎而非速度。对于琐碎任务，请自行判断。  
  
1. 编码前先思考  
不要假设。不要隐藏困惑。要摆出权衡。  
在实现之前：  
明确陈述你的假设。如果不确定，就提问。  
如果存在多种理解方式，把它们都列出来——不要默默选择一种。  
如果有更简单的方案，就说出来。该反对时就反对。  
如果有不清楚的地方，停下来。指出困惑点。提问。  
  
2. 简单优先  
用最少的代码解决问题。不做任何投机性设计。  
不添加未被要求的功能。  
不为一次性代码做抽象。  
不添加未被要求的“灵活性”或“可配置性”。  
不为不可能发生的场景写错误处理。  
如果你写了 200 行而其实 50 行就够，重写它。  
问自己：“资深工程师会觉得这过度复杂吗？”如果会，就简化。  
  
3. 外科手术式修改  
只动你必须动的地方。只清理你自己造成的混乱。  
编辑现有代码时：  
不要“改进”相邻的代码、注释或格式。  
不要重构没坏的东西。  
匹配现有风格，即使你自己会写得不一样。  
如果发现无关的死代码，提一下——不要删除。  
当你的改动产生孤儿代码时：  
移除因你的改动而变得未使用的导入/变量/函数。  
不要移除预先存在的死代码，除非被要求。  
检验标准：每一行改动都应能直接追溯到用户的需求。  
  
4. 目标驱动执行  
定义成功标准。循环直到验证通过。  
把任务转化为可验证的目标：  
“添加验证” → “为非法输入写测试，然后让它们通过”  
“修复 bug” → “写一个能复现它的测试，然后让它通过”  
“重构 X” → “确保重构前后测试都通过”  
对于多步骤任务，先说明简要计划：  
[步骤] → 验证：[检查项]  
[步骤] → 验证：[检查项]  
[步骤] → 验证：[检查项]  
强的成功标准能让你独立循环推进。弱的标准（“让它能跑”）则需要不断澄清。  
  
如果出现以下情况，说明这些准则正在起作用：diff 中不必要的改动更少、因过度复杂而重写的情况更少、澄清性问题出现在实现之前而不是犯错之后。
```

如果你仔细都这个 prompt会发现，这个指令主要是针对写代码时容易出现的问题，要求它在写代码时先想清楚、少加没必要的功能、只改相关部分，并在完成后检查结果。
## 回复风格，选一个你聊着舒服的

你是不是在和 WorkBuddy 聊天的时候，发现有时候他很啰嗦，或者他的语句你不是很喜欢，又或者需求还没说清楚，它就急着给答案。其实 WorkBuddy 在设置中给提供了多种回复风格。

![[file-20261117214549904.png]]

**小伙伴们可以打开「设置」，选择「个性化」，找到「回复风格」。** 这里我选几个重要的给大家介绍一下。

- 专业严谨：像个认真做汇报的同事，讲究条理，解释也比较细。想把一个问题掰开讲清楚，可以选它。
- 高效务实：主打一个说重点。少点铺垫，尽快给结论，适合需求明确、只想赶紧把活干完的时候。
- 启发引导：偏向通过提问帮你想清楚。特别适合那种「我有个想法，但一时半会儿说不明白」的情况。

我平常用得最多的是「高效务实」，回答言简意赅，比较合我的习惯。大家可以根据自己的喜好和习惯自行调整。

另外 在这个设置的上面还可以改你和 WorkBuddy 互相的昵称，我给 WorkBuddy 设置的大黄，它跟我叫boss，这个也比较有意思，大家可以根据自己的喜好更改。
