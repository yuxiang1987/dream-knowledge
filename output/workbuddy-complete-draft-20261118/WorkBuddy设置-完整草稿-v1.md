# WorkBuddy 做好这几个设置，让 WorkBuddy 越来越懂你

![[file-20261116212958406.png]]

最近，用 WorkBuddy 的人真是越来越多了，连地铁广告牌上都挂上了一整排「WorkBuddy 我帮你」。

更有意思的是，连我家孩子小伙伴的家长，也来打听 WorkBuddy 怎么用。

![[file-20261116213620465.png]]

和朋友聊下来，我发现不少人还停留在「装好就用」这一步。打开对话框，交代任务，至于设置里有哪些选项，却没怎么关注过。

这样当然也能用。但有些要求反复交代，有些麻烦总是遇到，就值得回头看看设置了。

所以，这篇就聊聊 WorkBuddy 值得了解的七处设置。你可以按自己的情况调整，让它更适合你的工作习惯，用起来也更顺手。

## 01 先看存储路径，别让 C 盘越用越满

这一项放在最前面，是因为我自己就在 C 盘空间上折腾过一阵。

我的电脑原来只有一块 512GB 的硬盘，C 盘更是只有可怜的 125GB。用了 WorkBuddy 一段时间后，C 盘动不动就满，搞得我隔几天就得清理一次。

后来，我还赶上硬盘涨价，忍痛加了一块 1TB 的固态硬盘，真是肝疼！

折腾了一阵才留意到，虽然 WorkBuddy 安装在 D 盘，设置里的「系统缓存目录」仍然显示在 C 盘。

**打开「设置」，选择「通用」，找到「存储」。**下面这张图是加盘之后截的，和前面说的旧硬盘配置不同。

![[file-20261116214902068.png]]

这里有两个位置，先分清楚再改。

上面的「系统缓存目录」，存放对话记录、运行缓存和临时文件。下面的「默认工作空间存储路径」，决定之后新建任务和分组的存放位置。

==点击「更改」，调整的是默认工作空间，不会把已有的系统缓存和数据一起搬走。==

刚开始用 Windows 版 WorkBuddy，可以先检查工作空间的位置，按需要选到空间充足、自己也容易找到的盘里。以后做出来的文件，就不用满电脑找了。

如果想迁移已经存在的系统缓存，需要另外检查目录和占用，先备份，再操作。之前做过目录联接的，界面仍显示 C 盘地址，也不代表数据实际还放在 C 盘，不能只看地址就判断搬没搬成功。

## 02 自定义指令，把常用要求提前说清楚

我在使用新的 Agent 工具前，都会先设置一下自定义指令。

==所谓自定义指令，就是提前给 Agent 定好一些约束规则，之后的对话和任务都会默认参考这些要求，省得每次都重复交代。==

用过 Claude Code、Codex 或 OpenCode 的朋友，可能见过 CLAUDE.md、AGENTS.md 这样的规则文件。WorkBuddy 则可以直接在设置里填写。

**打开「设置」，选择「个性化」，找到「给 WorkBuddy 的指令」，点击右侧的「编辑」，填入内容后保存。**

![[file-20261116225021232.png]]

下面这份是我常用的指令，大家可以参考，也可以根据自己的需求调整。

```自定义指令
# 行为准则  
减少常见 LLM 编码错误的行为准则。可根据需要与项目特定说明合并使用。  
权衡：这些准则偏向谨慎而非速度。对于琐碎任务，请自行判断。  
  
1. 编码前先思考  
不要假设。不要隐藏困惑。要摆出权衡。  
在实现之前：  
明确陈述你的假设。如果不确定，就提问。  
如果存在多种理解方式，把它们都列出来——不要默默选择一种。  
如果有更简单的方案，就说出来。该反对时就反对。  
如果有不清楚的地方，停下来。指出困惑点。提问。  
  
2. 简单优先  
用最少的代码解决问题。不做任何投机性设计。  
不添加未被要求的功能。  
不为一次性代码做抽象。  
不添加未被要求的“灵活性”或“可配置性”。  
不为不可能发生的场景写错误处理。  
如果你写了 200 行而其实 50 行就够，重写它。  
问自己：“资深工程师会觉得这过度复杂吗？”如果会，就简化。  
  
3. 外科手术式修改  
只动你必须动的地方。只清理你自己造成的混乱。  
编辑现有代码时：  
不要“改进”相邻的代码、注释或格式。  
不要重构没坏的东西。  
匹配现有风格，即使你自己会写得不一样。  
如果发现无关的死代码，提一下——不要删除。  
当你的改动产生孤儿代码时：  
移除因你的改动而变得未使用的导入/变量/函数。  
不要移除预先存在的死代码，除非被要求。  
检验标准：每一行改动都应能直接追溯到用户的需求。  
  
4. 目标驱动执行  
定义成功标准。循环直到验证通过。  
把任务转化为可验证的目标：  
“添加验证” → “为非法输入写测试，然后让它们通过”  
“修复 bug” → “写一个能复现它的测试，然后让它通过”  
“重构 X” → “确保重构前后测试都通过”  
对于多步骤任务，先说明简要计划：  
[步骤] → 验证：[检查项]  
[步骤] → 验证：[检查项]  
[步骤] → 验证：[检查项]  
强的成功标准能让你独立循环推进。弱的标准（“让它能跑”）则需要不断澄清。  
  
如果出现以下情况，说明这些准则正在起作用：diff 中不必要的改动更少、因过度复杂而重写的情况更少、澄清性问题出现在实现之前而不是犯错之后。
```

仔细读一下就会发现，这份指令主要针对写代码时容易出现的问题，要求它先想清楚、少加没必要的功能、只改相关部分，并在完成后检查结果。

平时主要处理文档和表格的朋友，也可以保留「不确定先确认」「只改相关内容」「完成后检查」这些通用要求，再补上自己经常提醒它的话。

同一页还有「人设设定」，主要调整 WorkBuddy 的身份、性格和表达方式。做事时要遵守的规则，优先在「给 WorkBuddy 的指令」里写清楚；不用把同一大段话到处复制一遍。

写了规则，也不能保证它每次都完全照做。重要的修改，还是得打开结果看一眼。

## 03 回复风格，选一个你聊着舒服的

和 WorkBuddy 聊天时，如果觉得它回答太啰嗦，说话方式不合自己的习惯，或者需求还没讲清楚，它就急着给答案，可以看看「回复风格」。

**打开「设置」，选择「个性化」，找到「回复风格」。**

![[file-20261117214549904.png]]

几个常用选项，简单理解就是下面这几种。

- **专业严谨** 像个认真做汇报的同事，讲究条理，解释也比较细。想把一个问题掰开讲清楚，可以选它。
- **高效务实** 主打一个「说重点」。少点铺垫，尽快给结论，适合需求明确、只想赶紧把活干完的时候。
- **启发引导** 偏向通过提问帮你理清思路，适合那种「我有个想法，但一时半会儿说不明白」的情况。

我平常用得最多的是「高效务实」，回答言简意赅，比较合我的习惯。大家可以根据自己的喜好调整，也可以随着任务换一换。

这里改变的是默认回复方式。选了「专业严谨」，也不代表回答就一定更准确，数字和事实还是得核对。

同一页上面还可以改 WorkBuddy 的名字，以及它对你的称呼。我给 WorkBuddy 起名叫「大黄」，让它叫我「boss」，两个输入框分别填好就行。

## 04 记忆要留，也要定期翻一翻

自定义指令写的是你希望它怎么做，记忆里保存的则可能是它了解到的背景、习惯和已经确认的约定。

这部分先看本地设置。

**打开「设置」，进入「记忆与进化」，找到「本地记忆与技能」。**它会记录有长期价值的项目成果和约定，支持用户级和项目级。经常围绕同一类工作使用 WorkBuddy，可以按需要开启。

![[memory-and-skills.png]]

比如，默认用中文、喜欢先看结论，这类要求可以跨任务使用。某个项目的配色、文件目录和交付格式，则应该留在对应项目里，别影响下一份工作。

接着，回到「个性化」，往下找到「长期记忆」，看看里面已经写了什么。

![[personalization-memory.png]]

最值得检查的是，那些看起来很像你的习惯、其实只在某一次任务里成立的内容。

比如，你赶时间说了一句「这次不用解释」，不代表以后都不想听原因。上次做的网页要深色背景，也不代表以后每个网页都要黑漆漆的。

已经结束的项目、过时的工具信息、总结错的偏好，都可以按实际情况修改。准备删除时先看清楚，不要为了整理记忆，顺手把还要用的约定也清掉。

下面这份是建议的记忆规则，可以按需要选用。

```text
长期保留我反复确认的偏好、背景和约定。
不要把一次性任务要求、临时报错和短期待办当作长期习惯。
只适用于某个项目的内容，保留在对应项目中。
同一件事出现冲突或需要覆盖旧记录时，先向我确认。
不要保存密码、密钥等敏感凭据。
```

规则能表达你希望它怎么记，但不能代替后续检查。以后感觉它总带着某个奇怪的习惯做事，除了看当前提示词，也可以回头翻翻记忆，看看是不是旧要求还留在里面。

## 05 跑顺的流程，保存成自己的 Skill

把记忆整理好之后，还可以进一步，把反复使用的做法保存下来。

Skill 可以理解成一份给 AI 使用的任务说明，必要时也带着处理任务的脚本和资源。它记录的是某一类事情具体怎么做，方便下一次复用。

比如，每周都要整理同一种订单表。字段怎么统一、缺失金额怎么标记、结果保存成什么格式，这些已经固定下来，就适合整理成一个 Skill。

先拿一份表把流程跑通，打开结果确认没问题，再让 WorkBuddy 保存。不要刚做出第一版，还不知道对不对，就急着把整套做法固定下来。

流程确认之后，可以在刚才的对话里这样说。

```text
把刚才已经确认可用的订单表处理流程整理成一个 Skill。

写清输入要求、处理步骤、输出格式和检查方法。
缺失的金额不要猜填，保留原文件，处理结果另存。
不要写入本次任务的临时文件名和路径。
先给我看内容，确认后再保存。
```

创建完成后，到技能列表里查看，再换一份同类表格，新开一个对话试一下。原来能处理的列有没有漏，遇到缺少字段的材料，会不会说明问题，都值得顺手检查。[官方自建技能说明](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Practice-Cases/Practice-Eight)

【待补图：一个实际跑通的任务、保存的 Skill，以及换材料复用的结果。】

以后流程变了，也要更新对应技能。先把一件经常做的事整理好，比装一长串暂时用不上的技能，更容易知道它到底帮上了什么忙。

## 06 模型和上下文，按任务来选

模型和思考强度，要看这次准备做什么，不用一直挂在最高档。

如果当前界面提供「快速」「均衡」「极致」这类档位，小修改、简单问答可以先用快速；日常文档、表格分析，拿不准时从均衡开始；跨多个文件、需要反复推理的复杂任务，再考虑极致。

思考强度先保留当前模型的默认值就行。需要分析得更深时再调整，也看看多花的时间和消耗，有没有换来对你有用的结果。

更容易让人误解的是上下文窗口。它可以理解成，这次对话里能同时放下多少任务要求、资料和聊天记录。

窗口上限调大，能放进去的内容更多，但它不会因此就更懂你的需求。实际传给模型的内容越多，长对话里的消耗也可能增加。日常先保持默认，确实需要处理超长资料，再考虑调大。

当前官方说明的入口是输入框里的上下文用量圆环，能切哪些档位取决于所选模型，不用照着旧教程找固定的 300K 或 1M。[官方模型说明](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Model)

【待补图：当前使用模型的选择面板与上下文档位。】

另外，**「设置」里的「智能体」有一个「经济模式」**。开启后，会在合适的时机压缩上下文，减少长对话里重复传输的内容，日常可以先保持开启。

![[agent-economy.png]]

聊了很多轮、需求又改来改去，发现它开始遗漏要求时，先让它整理当前目标、已经确认的决定和下一步要做的事。自己检查后，保存成一份简短记录，再决定继续当前对话还是另开任务。

特别重要的要求，单独写进项目文件里，比指望它从几十轮聊天里一直记准，更方便自己维护。

## 07 权限与备份，先知道改错了怎么找回

WorkBuddy 能直接修改文件，这一项值得认真看一遍。

**输入框底部可以查看当前权限，备份和删除保护则在「设置」的「安全中心」。**

日常整理文档、修改表格，可以先保留默认权限，把需要处理的文件副本放进一个独立文件夹。

完全访问能减少确认步骤，也会放开更多操作。用它之前，先确认任务范围明确、文件有备份，不要只是嫌弹窗烦，就把重要目录全交给它。

**安全中心里的「自动备份」「删除保护」，建议检查一下是否开启。**

![[safety-backup.png]]

自动备份会在修改已有文件前保存快照。同一个文件在一轮对话里，只在首次修改前备份，不能理解为每改一次都留一个版本。删除保护则优先尝试把删除的文件移到回收站，也不能替代独立备份。[官方权限与备份说明](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Permission-Modes)

你看到的截图里，备份总上限是 3000MB，单文件大小上限是 100MB，批量删除审批数量是 50。这是当前配置，不是所有文件都一定能备份、所有删除都一定能找回。

尤其经常处理视频、压缩包或大文件的朋友，要看看单文件上限是否适合自己的任务。

想知道恢复到底怎么做，先拿一个不重要的测试文件试一次。让 WorkBuddy 改动其中一处，然后从自动备份里的「打开备份目录」找到修改前的版本，先复制出来检查，再尝试恢复测试文件。

【待补图：测试文件修改前后、找到备份及恢复后重新打开的结果。】

确认这一步能跑通，以后遇到改错文件，才知道该去哪里找。重要资料仍然自己另留一份，别把开了备份理解成可以放心随便改。

## 写在最后

这几项不用一次全部改完。

先挑一个自己正在遇到的麻烦处理。总是重复交代要求，就先看自定义指令；它带着旧习惯做事，就翻翻长期记忆；C 盘空间紧张，就先查清存储位置。

设置好以后，拿一个真实任务试一下。哪里还不合适，再调整对应的要求。慢慢把自己的习惯、常用流程和检查方法整理清楚，WorkBuddy 才更容易成为一个用着顺手的帮手。
