## 一块会随风摆动的布

第一个案例，我做的是一个==布料模拟器==。

场景很简单，一块布晾在绳子上，风吹过来，布料会跟着摆动。我想看看 Kimi 能不能用 Three.js 把布料的褶皱、运动和光影做出来。

先来看一下成品。

![[织布模拟器.mp4]]

从视频中可以看出来，做的还是挺细腻的，==风吹过来时，布料会跟着摆动，表面的褶皱也在不断变化。==

==不知道你们注意没有，地上的阴影也会跟着布料一起晃动，看起来真的很真实。==

==画面背景可以切换，风速和视角也可以调节。点击重置后，布料下坠的效果也做得挺有感觉。==

这是提示词：



```prompt
使用threejs制作一个布料模拟器，一块布晾在绳子上，展示真实的物料效果。
所有的素材和生成的文件，都放在kimi-code/fabric-simulator文件夹下
```

第一版布料上没有任何图案，我觉得稍微有点单调。

我就又给它发了一张图片，让它把图片加到布料中间，再把图片里电脑屏幕上的文字改成「K3.1 PRO」。

而且，屏幕上的字要慢慢展现出来，最后再闪动一下。

![[Pasted image 20261028095336.png]]

==最终效果里，布料在飘动，图片里的文字也在逐渐显示、闪动。而且布料动起来的时候，画面里的动画没有糊掉，这个细节我挺喜欢的，给 Kimi 点个赞👍。==

不过，这个项目的额度消耗也多少让我有点肉疼。做完这个项目时，5 小时用量已经到了 76.29% 😄。

## 把云海中的古城做成 3D 场景

第二个案例，我给了 Kimi 四张参考图，想让它用 Blender 把图中的古城做成一个可以从不同角度查看的 3D 场景。

主参考图里是一座被云海包围的浮岛，岛上有中式建筑群，后方还有一座巨大的雕像。

另外三张图分别用来参考建筑细节、雕像与城市的比例，以及云层和光线。

![[水月景观_四张参考图.jpg]]

先来看一下成品

![[shuiyuejingguan_showcase.mp4]]

视频里可以看到浮岛的整体轮廓、建筑群和后方的巨像，镜头也靠近展示了部分建筑细节。

整体上，参考图中的主要元素基本都做出来了。不过和原图相比，云海没有那么大气磅礴。

我猜可能也和我给的第四张云层参考图有关。

这次的提示词比布料模拟器长不少，完整提示词放在下面。



```prompt
用 Blender Python 创建一个可重新生成、可编辑、可导出的三维场景，并完成最终静帧渲染。整体效果严格服从主参考图：高空俯视、右侧浮岛、北缘巨像、左侧云海、冷灰蓝光照。最终成果必须来自真实三维场景，不得用参考图贴片或二维生成图冒充三维渲染。采用展示模式，提供主视角、建筑、雕像和顶部检查相机，可旋转查看与缩放检查，不要求实时交互。

参考图是唯一整体效果依据（机位、构图、岛形、雕像位置、建筑范围、云海遮挡与明暗）；其余三张引导图分别只提取中式古建细节、巨像与城市的尺度逻辑、体积云层次与冷灰蓝光照，不得引用其构图或机位。发生冲突时一律以主参考为准。

画面硬约束：输出 1920×1080 主画面及 2 倍图。高空近垂直俯视（俯角约 55°–70°）、长焦、全画面深焦。岛屿投影为略倾斜的横向椭圆，位于画面右侧；左侧约一半画面为连续云海，不出现地平线或整片天空。巨型浅色风化石像位于岛屿北缘，以背部或侧背面为主，高冠饰与衣褶清晰，下部被云半掩。暗色密集建筑群集中在岛体下半部，屋脊轮廓清晰可读。主画面不露出完整悬空岛底；白色区域是体积云，全场景禁止积雪与冰雪材质。

建筑采用"标准构件 → 参数化模板 → 院落组合 → 群落实例"流程，全部放入独立集合：先实现瓦垄、斗拱、柱梁开间、脊兽、栏杆、城墙段等标准构件，再组合出十类建筑模板（门厅、主殿、厢房、楼阁、凉亭、门楼、高台殿、十字脊抱厦殿、钟鼓楼、连廊院）。岛缘布置随岛形变化的闭合城墙带，中环以 Poisson Disk 布置 12–16 个院落单元，核心为高台对称区与少量楼阁，中央北缘为雕像留空。材质低饱和：青灰瓦、灰黑梁架、暗红柱、灰石墙。记录随机 seed，保证同一次生成可复现。

岛体为直径约 200m 的不规则浮岛，偏暗青灰风化石；雕像为浅色风化石灰岩，保留冠饰、肩臂、衣褶与雕刻起伏，不得洁白或塑料化。云海使用真正的三维体积材质与多层 Noise：连续云海填满左侧，贴岛云流吞没岛缘并半掩雕像下部，局部低云打断城市内部；禁止平面云贴图与均匀白地毯。光照为左上方大面积柔和主光加低强度冷环境填充，最终用 Cycles 渲染并降噪；预览阶段可降低采样与体积步进，但不得删减建筑或改变主相机构图。

按"环境检查 → 岛体 blockout → 雕像对齐 → 建筑生成 → 云海与光材 → 渲染检查"的顺序推进，每步通过后进入下一步；每轮主要渲染必须生成与主参考的并排比较图、叠加图和差分图，实际查看后继续修正，不得只凭日志或数值宣布完成。
```

这个场景不是一遍生成的。制作过程中先搭建岛体，再补上雕像、建筑和云层；生成预览后，又对照参考图调整了雕像位置、建筑和云海。

## 让 AI 做一款卡丁车竞速游戏

第三个案例，我做的是一款卡丁车游戏，想看看 AI 能不能把赛道、车辆和竞速玩法组合起来。

![[bandicam 2026-10-29 09-11-43-935 1.mp4]]

比赛需要跑完三圈环形赛道，还有五个电脑对手一起跑。画面上可以看到圈数、排名和小地图。

操作也比较简单，方向键或者 WASD 负责驾驶，按住空格可以漂移，松开后释放蓄力加速，直道上还可以按 Shift 使用氮气。

我实际玩下来，驾驶手感比较顺，加速和漂移都能用。跑完比赛后，也会给出排名和分数。

这个案例整体中规中矩，赛道、对手、驾驶和结算都做出来了，也能正常跑完一场比赛。

## 给一首歌做纯代码 MV

最近用Agent做动画真的太火了，这次换个方向，让 Kimi 给一首歌做一支 MV。

我选的是 Mili 的《world.execute(me)》，这首歌本身就有很多和程序有关的表达，所以我想试试，Kimi 能不能用各种图形表达音乐的律动。

我把音乐文件放进项目目录，然后给了 Kimi 这段提示词。



 ```prompt
发挥你对world.excute(me)的理解，为这首歌配一个MV ，音乐已放在项目文件夹根目录 kimi-code/MV/world.execute.me..-Mili#21qz3.mp3，视频使用纯代码实现，要求尽可能表现出来歌词含义，要足够震撼！
生成的所有素材都放在kimi-code/MV 下
 ```

最终生成了一支约 3 分 32 秒的 MV。

![[world.execute.me-code-mv.mp4]]

这个案例画面使用深色背景，搭配红白色的几何图形、文字和字幕。

项目里还保留了镜头表和动画代码，整体随着音乐的律动，切换各种图形，还是比较丝滑，但是不得不说跟 Opus5.5 做还有一些差距。

## 最后

这次 Kimi K3.1 Pro 测试下来，除了额度消耗让我有点肉疼，整体体验还是不错的。

我最喜欢的案例是布料模拟器。

布料随风摆动时，褶皱和地面阴影都跟着变化。

Kimi 那个小电脑的动态文字，在布料飘动的时候也没有糊。几个细节放在一起，看着确实挺细腻。

古城建模的结果也让我看到了复杂场景制作的能力。

现在的 Kimi 确实越来越强了，额度要是再宽松一点，体验就更好了。
