调研日期：2026-11-16；计划发文日期：2026-11-17。当前仅完成资料核验，作者尚未实测，不据此锁定标题或效果结论。

## 核心判断

这次发布重点是把视觉理解、长上下文与工具调用做得更快、更便宜，面向日常 Agent 任务。官方将 Hy4 flash 定位为日常主力，复杂长程软件工程仍推荐 Hy4。视觉理解和 1M 上下文是保留能力，不是相对 Hy4 新增。

## 已确认的特性

| 特性 | 本次发布信息 | 对案例的意义 |
| --- | --- | --- |
| 参数规模 | 总参数224B，其中64B为Engram参数；每token激活12B | 小于Hy4的770B/49B，但参数少不直接等于效果差或更好 |
| 多模态 | 支持图片理解 | 可做截图、图表、图文资料识别；不能写成原生生成图片和视频 |
| 长上下文 | 1M token；腾讯云最大输入960k、最大输出64k | 适合多份资料；不代表能输出100万token，也不是永久记忆 |
| Agent 接入 | 深度思考（保留式思考）、结构化输出、Function Calling、Cache | 可接收工具结果、调用外部工具完成任务；具体操作能力也取决于WorkBuddy等承载产品 |
| 速度 | 官方称解码速度超过150 tokens/s | 需实测从发出需求到得到可用文件的总时长，不能直接换算任务耗时 |
| 输出效率 | 官方称强化学习使端到端任务输出长度降低50% | 不等于答案必然少一半，也不等于准确率或每任务费用固定变化 |
| 推理资源 | 混合注意力、LatentMoE、Engram；KV cache为Hy3的1/24、Hy4的1/6；采用megakernel、4bit量化等优化 | 这是服务成本与部署效率的背景，不能当用户电脑内存需求或本地部署已可用的证据 |

术语说明：token是模型处理文本等内容的计量单位；Engram为模型引入的参数模块；KV cache是推理时用于复用上下文信息的缓存；Function Calling指模型请求调用外部工具。本文只保留官方给出的架构名称，不额外推断内部机制。

## 怎样读官方评测

**WorkIndex**是厂商基于WorkBuddy典型任务构建的内部评测，涵盖PPT制作/修改/人机双写、Markdown人机双写、文档编辑、表格修复、音视频处理、视觉理解，共8类评测集。官方称：

- 综合效果略优于Hy4 preview；比较对象是preview，不是Hy4正式版。
- 平均单任务成本为Hy4 preview的1/13、Hy4的1/20、DeepSeek-V4.1-Flash-1017的1/8。
- DeepSeek对比限定为**max档位、忙时价格**，不能扩写为所有档位、所有时段或所有任务都便宜8倍。

另一组为85位WorkBuddy内部用户、27类259个任务的盲测。官方称满意度接近Claude Haiku 5.5，且在该轮参测模型中任务时长最短、单任务成本显著更低。不能写成全面追平Claude，或最快模型。

官网WorkBuddy团队证言还给出了“较Hy4平均耗时降低70%、平均成本约1/15”的另一组口径。任务集与测算不同，不能同WorkIndex的1/20合并成同一组数据。正式文章优先保留一套口径并注明范围。

## 今天的案例准备建议（待试）

本轮是发布特性调研，不是正式选题确认。按本账号[定位](../../../wiki/entities/程序员拾梦.md)与[已发内容](../../../wiki/sources/拾梦七篇已发布文章内容蒸馏.md)，案例应展示可用成果及修改，不重复写WorkBuddy安装教程，也避开公众号选题、写作和排版作为WorkBuddy演示场景。

**优先小试：把一份有问题的订单表，整理成可核对的经营报告。** 面向独立经营者和AI工作流爱好者，观察低价模型处理日常任务能否兼顾速度与准确性。需求为策划假设，不虚构读者反馈。

- 素材：自拟、明确标为演示数据的20—30行订单表；含重复订单、日期格式混用、已退款记录、空值；另给一张有补充规则的截图。先人工算好订单数、净收入与品类合计。
- 第一步：在WorkBuddy选定Hy4 flash，只要求识别问题、按截图规则生成清洗表与核对报告；先不追加PPT。
- 观察：是否误删正常订单、是否正确扣除退款、缺值是否标注、截图规则是否生效、文件能否打开。通过后再加一页可视化，最后才考虑PPT。
- 留证：模型选择、完整输入、首版与修正版、错误点、开始/结束时间、人工介入次数、实际积分与可用消耗记录。无API账单时只写WorkBuddy积分，不按目录单价捏造本任务费用。
- 退出：关键金额核对不过时先记录失败，允许一次定向修改；仍不过就收窄为表格清洗局限复盘，不硬写成自动经营分析成功。

**备选一：截图复刻一个可操作的报价计算器。** 用自有简图规定商品、数量、折扣与总价，先准备三组手算答案。观察视觉还原、按钮可用、金额正确和一次改需求后的回归。适合Coding主线；暂缓的原因是单做漂亮网页难体现办公任务成本优势，需同题对照才更有解释力。

**备选二：多份公开产品资料做带出处的选型比较。** 固定官方来源、版本和问题，要求每个关键参数附出处，不确定项留空。观察跨材料检索与引用是否匹配。适合长上下文与深度搜索；暂缓的原因是成品视觉展示性较弱，且当前试验并不能验证1M全长度可靠性。

若做Hy4对照，两模型用相同素材、新会话、相同工具和思考设置，分别记录总耗时、结果正确性、修改轮次与实际费用。单个案例只支持该任务的观察，不验证官方总体胜率。
