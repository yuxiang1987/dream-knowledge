如果你在用 Claude、Codex、Openclaw 或者 Deepseek Harness 这类的 Agent 工具。
那一定存在可能和我一样的问题。
我们使用AI的时间越来越长，也花了不少时间，让它熟悉自己的工作。
但开一个新会话，开始下一轮任务，上下文清零，之前确认过的东西，又得重来。
比如说：
项目里面的一些前提条件、每次做 PPT 时候的经验归纳等等，每次都是从头再来。
其实，问题就出在，记忆。
最近，我在 Github 上发现一个爆火的开源 Agent 记忆项目 MemOS，12k 的 star，经过深度的使用，我觉得是时候给大家整个 Agent 记忆的教程了。
方法很简单，但是效果很炸裂，一套好的记忆系统可以让我们在用 Agent 的时候：
1. 比 Skill 更轻松的经验沉淀。
2. 项目进度和客户画像持续跟踪。
3. 每次新开对话不需要再复述以前的要求。
4. 大幅节省 token 消耗（这个最实在了）。
那么问题来了，怎么做出一套好的记忆系统，不用担心，今天这篇文章会用这个开源免费的 MemOS 记忆系统，讲清以下的内容：
1. 给正在用的Agent接上记忆。
2. 怎样沉淀记忆。
3. 让上一次的经验，用到下一次任务里。
4. 跨 Agent 也能用，团队也能用。
5. 省 Token 方法！
下面以Codex为例。其他 Agent 也是完全一样的逻辑。
现在开始，让 Agent 真正成为自己的分身。
一、先给正在用的Agent接上记忆。
你可以把MemOS理解成一本能查询、能修订的工作笔记。
记忆的本质逻辑是：
接入记忆后，Agent可以在回答前查相关记忆，把适用内容带进当前任务，回答结束后再写入新的问答。
我们先准备好记忆的 API-KEY。
🔗：memos-dashboard.openmem.net，注册并登录。
找到API Key的创建入口，生成一个Key，保存好。
Key留着稍后在本机终端输入，不用粘贴进Codex对话。
打开Codex，发这段Prompt。
●●●
请按 https://github.com/MemTensor/MemOS-Cloud-CLI 为当前Codex安装配置MemOS，直接执行并验证。
1. 检查Node.js、npm和memos，补齐环境；缺CLI时运行 npm install -g @memtensor/memos-cloud-cli ，检查版本与帮助。
2. 先备份配置，沿用已有Key和user_id，没有user_id则用 memos_article_demo 。初始化后对照备份，保留无关设置。
3. 用确定的user_id执行 memos init --agent codex --user-id 实际标识 。缺Key时先把命令交给我在本机终端隐藏输入，回复“已完成”后核验，不再重复初始化。Key不得进入对话或日志。
4. 检查接入配置，用 memos_search "MemOS连接检查" --format json 验证请求。报告版本、user_id、结果及重启步骤，自动检索和写入留待新会话验证。
需要Key时，在自己电脑的终端运行它给出的命令。
●●●
memos init --api-key YOUR_API_KEY --agent codex
这里把 YOUR_API_KEY 换成咱们上面拿到的就行了。
配置之后终端会返回这些内容。
再回Codex回复已完成。
至此，配置就完全 ok 了。
恭喜，你的 Agent 有了专属于你的记忆。
我先简单说下，记忆的几个重要场景。
1. 做完一件事之后，让他记住过程中我们有什么未来可以复用的要求。
2. 如果是客户，记住客户的信息和一些偏好。
3. 你自己的个人情况，比如说我写作喜欢，开头告诉大家能获得什么。
4. 多个 Agent 能够共用一套记忆，这个很有价值。
如果多个 Agent 都要共用记忆，那就各自配置一下。
比如说，Claude Code对应 memos init --agent claude，DeepSeek Harness对应 memos init --agent deepseek。
接下来，实操一下。
二、先留下几条真正用得上的记忆。
比如说，我最常用的场景。就是我做项目，一个客户，基本会做个 4、5 个 PPT，其实做来做去，都是那一个风格。
每次做新的 PPT，
听众是谁、喜欢什么版式、上次改过哪些地方，每次都需要重新交代。
不过最近我的方案换了。
用 Agent 记忆，记住了所有事情。
我先正常做一个 PPT，当然过程中我和他交互了很多论，产出了一个我比较满意的版本。
这时候，我会告诉他。
●●●
请你仔细检查做这个 ppt 的过程中，我和你讨论的一些做这个类型 PPT 规则。
为我梳理有哪些适合放入 MemOS 中的，未来我可以进行复用的的记忆。
梳理出来了多种层次的记忆，然后我让他存储起来。
可以在后台看到记忆列表。
其中会记住的主要有几个部分。
这个项目的对象画像是谁、这个类型的 ppt 的思路、排版以及表达逻辑是什么。
它全记住了。
三、让上一次的经验，用到下一次任务里。
为了实测一下，这个记忆准确不准确。以及，跨 Agent，跨项目能不能用。
我这次新开一个文件夹，在 Claude 中发布任务。
当然，我已经在 Claude 中配置好了。
●●●
memosinit--agentclaude
直接发需求。
在计划阶段，就已经把我的记忆抽出来，而且针对当前项目进行了计划。
比如说，大纲逻辑、板式逻辑、色系等等。
然后就是 Claude 凭借着记忆和当前的资料，做出了以下这份设计方案。
然后，Agent 就自己做了。第一版出来的效果长这样。
这个完成度，我觉得已经挺能打了。
白底、蓝色分隔线，重点用红色提出来，整套看下来，风格很统一。热力图、柱状图、流程图也都用上了，讲数据、讲关系、讲方法，各有各的表达。
尤其这种技术分享，信息量本来就大。能把内容分清楚，让讲的人有顺序，听的人能跟上，就已经有了一个很好的底子。
这里也能看出来记忆和模板是互相配合的。
模板提供具体的版式和色值，记忆用来延续之前确认的制作要求，新资料决定这次讲什么。
接着往下改就行。比如，我希望听众看图的时候，能马上知道这页想说明什么。
●●●
请给这份“AI时空数据分析”PPT的每张核心图表配一句结论，放在图表旁边，结论必须有当前资料支持。把这条要求记为本项目后续PPT的制作规则。
改完，做 PPT 的记忆里又多了一条。
PPT 制作，讲解页面，必须有当前资料支持，且进行结论输出。
这次改过的地方，值得留给下一次用。
四、要求变了，也要让记忆跟着变。
记住还不够，要求也会变。
比如，如果客户要把这套PPT拿到会议室里讲，字就得放大，太满的页面也得拆开。
这时候，可以用feedback更新要求。在终端输入。
●●●
memosfeedback"后续用于现场汇报的PPT，正文至少18pt，内容放不下时拆页；此前更小的正文字号要求不再适用于现场汇报。"--formatjson
当然也可以直接告诉 Agent。
这里值得注意的是，
记忆更新后，旧PPT文件不会自己改变，要让Agent重新修改或制作。
前面已经从 Codex 换到Claude做过一次。
以后继续换工具，就能接着查这份记忆。
这个事情在之前，至少需要几天时间调一个精确的 Skill 出来下次才能复现。
现在，只需要，记住就好。
五、Token也能省下来。
这一点，放回刚才做PPT的过程里，就很好理解。
第一份PPT，我大概来回聊了十几二十轮。改大纲、调版式、补结论，一点点把它磨成我想要的样子。
这些对话里，其实藏着很多以后能用的东西。
这个客户关心什么，哪种讲法更合适，什么地方必须给结论，做成什么样才算合格。
接上记忆之后，交互过程可以自动记录下来，我们再把确认过的要求整理好，留给后续任务使用。
等到做第二份PPT，我就可以把新需求、新资料和需要的模板交给Agent，让它沿用之前的经验开始做。
前面换到Claude，也是把这份积累接着用。
这些反复确认和返工少了，多轮对话消耗的Token就有机会省下来。
官方评测也给出了这方面的结果。
MemOS在LoCoMo长期对话记忆评测中，相比OpenClaw原生记忆，Token消耗减少超过80%。这个提升还是很大的。
