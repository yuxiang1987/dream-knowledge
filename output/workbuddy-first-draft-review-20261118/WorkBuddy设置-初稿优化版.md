# WorkBuddy 做好这几个设置，让 WorkBuddy 越来越懂你

![WorkBuddy 地铁广告](<../../raw/article/程序员梦哥/assets/WorkBuddy 做好这几个设置，让WorkBuddy越来越懂你/file-20261116212958406.png>)

最近用 WorkBuddy 的人真是越来越多了，连地铁广告牌上都挂上了一整排「WorkBuddy 我帮你」。

更有意思的是，连我家孩子的小伙伴家长，也来打听 WorkBuddy 怎么用。

![家长询问 WorkBuddy 的聊天截图](<../../raw/article/程序员梦哥/assets/WorkBuddy 做好这几个设置，让WorkBuddy越来越懂你/file-20261116213620465.png>)

和朋友聊下来，我发现不少人都是装好就用。打开对话框，交代任务，设置里有什么，平时还真没怎么翻过。

这样当然也能用。但如果每次开个新对话都要重复交代，或者做完任务总找不到文件，就值得回头看看设置。下面这七项，你可以挑用得上的改。

## 01 先看存储路径，别让新任务都挤在 C 盘

我电脑原来只有一块 512 GB 的硬盘，C 盘更是只有可怜的 125 GB。用了 WorkBuddy 一阵子，那会儿 C 盘动不动就满，搞得我隔几天就得清理一次。后来赶上硬盘涨价，我还忍痛加了一块 1 TB 的固态硬盘，真是肝疼！

我把 WorkBuddy 装在了 D 盘，后来打开设置，才留意到「系统缓存目录」仍显示在 C 盘。程序装在哪儿，和任务、缓存放在哪儿，是几件不同的事。

**打开「设置」，在「通用」下找到「存储」。** 下面是我加盘之后截的图，和上面说的旧硬盘配置不是同一个阶段。

![系统缓存目录和默认工作空间](<../../raw/article/程序员梦哥/assets/WorkBuddy 做好这几个设置，让WorkBuddy越来越懂你/file-20261116214902068.png>)

上面一项是「系统缓存目录」，说明里写着存放对话记录、运行缓存和临时文件。下面一项是「默认工作空间存储路径」，旁边的「更改」按钮只管以后新建的任务和分组，已有数据会留在原处。

如果你的 C 盘本来就紧张，可以把默认工作空间设到空间更充足的盘，单独建个好找的文件夹。改完新建一个测试任务，看看生成的文件实际存在哪儿。要查已经占用的空间，再分别去看旧工作空间和系统缓存目录。

## 02 自定义指令，把常用要求提前说清楚

我开始用一个新的 Agent 工具，通常会先设置自定义指令。说白了，就是把经常提醒它的话提前写好。比如「只改我点名的地方」「遇到不确定的数据别猜」「改完自己检查一遍」。以后开新任务，它就有这些要求可参考。

用过 Claude Code、Codex 或 OpenCode 的朋友，可能见过 CLAUDE.md、AGENTS.md 这样的规则文件。WorkBuddy 可以直接在设置里填。

**打开「设置」，选择「个性化」，在「给 WorkBuddy 的指令」旁边点击「编辑」，填好后保存。**

![给 WorkBuddy 的指令](<../../raw/article/程序员梦哥/assets/WorkBuddy 做好这几个设置，让WorkBuddy越来越懂你/file-20261116225021232.png>)

下面这份是我常用的指令，主要针对写代码时容易出现的问题。比如我只要改一个按钮，它就该先看看相关代码，改完检查效果，别顺手把整个页面重做一遍。

```自定义指令
# 行为准则  
减少常见 LLM 编码错误的行为准则。可根据需要与项目特定说明合并使用。  
权衡：这些准则偏向谨慎而非速度。对于琐碎任务，请自行判断。  
  
1. 编码前先思考  
不要假设。不要隐藏困惑。要摆出权衡。  
在实现之前：  
明确陈述你的假设。如果不确定，就提问。  
如果存在多种理解方式，把它们都列出来——不要默默选择一种。  
如果有更简单的方案，就说出来。该反对时就反对。  
如果有不清楚的地方，停下来。指出困惑点。提问。  
  
2. 简单优先  
用最少的代码解决问题。不做任何投机性设计。  
不添加未被要求的功能。  
不为一次性代码做抽象。  
不添加未被要求的“灵活性”或“可配置性”。  
不为不可能发生的场景写错误处理。  
如果你写了 200 行而其实 50 行就够，重写它。  
问自己：“资深工程师会觉得这过度复杂吗？”如果会，就简化。  
  
3. 外科手术式修改  
只动你必须动的地方。只清理你自己造成的混乱。  
编辑现有代码时：  
不要“改进”相邻的代码、注释或格式。  
不要重构没坏的东西。  
匹配现有风格，即使你自己会写得不一样。  
如果发现无关的死代码，提一下——不要删除。  
当你的改动产生孤儿代码时：  
移除因你的改动而变得未使用的导入/变量/函数。  
不要移除预先存在的死代码，除非被要求。  
检验标准：每一行改动都应能直接追溯到用户的需求。  
  
4. 目标驱动执行  
定义成功标准。循环直到验证通过。  
把任务转化为可验证的目标：  
“添加验证” → “为非法输入写测试，然后让它们通过”  
“修复 bug” → “写一个能复现它的测试，然后让它通过”  
“重构 X” → “确保重构前后测试都通过”  
对于多步骤任务，先说明简要计划：  
[步骤] → 验证：[检查项]  
[步骤] → 验证：[检查项]  
[步骤] → 验证：[检查项]  
强的成功标准能让你独立循环推进。弱的标准（“让它能跑”）则需要不断澄清。  
  
如果出现以下情况，说明这些准则正在起作用：diff 中不必要的改动更少、因过度复杂而重写的情况更少、澄清性问题出现在实现之前而不是犯错之后。
```

平时主要用 WorkBuddy 做表格的朋友，可以先写自己经常提醒它的两三条。比如「缺失金额单独标出来」「结果另存一份」「汇总后核对行数」。临时要求随任务说就行，像「这份表先按客户名排序」，写进全局指令，下次做另一张表时反倒容易添乱。

## 03 回复风格，选一个你聊着舒服的

有时候只想问下一步怎么做，它却先讲了半页背景。遇到这种情况，可以去「设置」里的「个性化」，换一下「回复风格」。

![回复风格菜单](<../../raw/article/程序员梦哥/assets/WorkBuddy 做好这几个设置，让WorkBuddy越来越懂你/file-20261117214549904.png>)

这几种风格，用大白话说还挺好分。

- **专业严谨** 像个认真做汇报的同事，愿意把来龙去脉讲清楚。想把问题掰开来看，可以试试。
- **高效务实** 主打一个「说重点」。活儿已经交代清楚了，就少铺垫，直接说怎么做。
- **启发引导** 适合「我有个想法，但一时半会儿说不明白」的时候。让它帮你把问题问清楚，再接着聊。

我平常用得最多的是「高效务实」，回答简短，比较合我的习惯。这里调的是默认语气，涉及数字和事实，还是要看它给的依据。

同一页还可以改名字和称呼。我给 WorkBuddy 起名叫「大黄」，让它叫我「boss」。

![WorkBuddy 名字与称呼](<../../raw/article/程序员梦哥/assets/WorkBuddy 做好这几个设置，让WorkBuddy越来越懂你/file-20261117215038827.png>)

## 04 人设和长期记忆，分别写什么

这两个入口也在「个性化」，都能点「编辑」，不过填的东西不一样。

**人设设定**写的是你希望 WorkBuddy 怎么跟你打交道。比如我希望大黄像熟悉的同事一样说话，有不同意见直接说。简单问题先给结论，复杂问题说清理由。至于「修改文件前先读原文」这种具体做事要求，放在前面的自定义指令里就够了。

![人设设定](<../../raw/article/程序员梦哥/assets/WorkBuddy 做好这几个设置，让WorkBuddy越来越懂你/file-20261118145732609.png>)

**长期记忆**写的是以后换个对话也用得上的信息。像你平时做什么、常交付什么东西、有哪些已经确认的偏好，都可以留几条。比如你经常给客户做报价表，表里金额统一用人民币，这条就值得留。「这次先给我英文版」只适用于这次，过了就不用一直带着。

![长期记忆入口](<../../raw/article/程序员梦哥/assets/WorkBuddy 做好这几个设置，让WorkBuddy越来越懂你/file-20261118145712556.png>)

新任务要接着做旧项目时，可以直接给它看项目文件或简短的交接记录。长期记忆适合帮它快速认识你，某一轮讨论定下来的具体内容，留在项目里更好找。

刚开始不知道怎么写，可以先把自己的真实需求告诉 WorkBuddy，让它整理成几条，自己读一遍再贴进去。以后发现它把一次性的要求当成了你的习惯，就回到这里改掉那条。

## 05 经常做的项目，可以留下一些约定

**打开「设置」，进入「记忆与进化」，找到「本地记忆与技能」。** 我用的版本里，这项已经开启。界面说明它会记录有长期价值的项目成果和约定，支持用户级和项目级。

如果你经常在 WorkBuddy 里接着做同一个项目，可以先留着这一项。比如你一直做几张不同用途的表，关于日期格式的习惯可以是通用的。某个项目约定「每周的统计从周一到周日」，就放在那个项目里，别让它跑到别的表格里去。

还有一种情况，每周都要按同样的步骤整理一份订单表。先统一字段，缺失金额单独标注，最后核对行数并另存。如果这套做法已经跑顺，可以考虑整理成 Skill，把什么时候用、输入长什么样、结果怎样检查写清楚。**本地记忆可以帮它接上之前的约定，Skill 适合保存一整套反复使用的步骤。** 换一份同类材料再试一遍，就知道这个流程能不能复用。

## 06 模型、思考强度和上下文，按任务选

WorkBuddy 可以在对话框下方切换模型。像图里的混元 Hy4 flash，截图时标着「限时免费」。优惠有时限，试用时看客户端的活动说明。 [腾讯混元发布说明](https://www.tencent.com/zh-cn/tencent-launches-hy4-flash-to-power-high-speed-cost-efficient-ai-deployment-for-everyday-workflows/)

![模型列表](<../../raw/article/程序员梦哥/assets/WorkBuddy 做好这几个设置，让WorkBuddy越来越懂你/file-20261118151235237.png>)

你也可以先用列表里的「快速」「均衡」「极致」三个档位。简单问答、改几行字，可以从快速开始。日常整理文档、分析表格，拿不准就先用均衡。步骤多、要反复核对，再考虑极致。 [WorkBuddy 模型配置说明](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Model)

在我这个版本里，把鼠标放到模型名上，部分模型会显示「思考强度」和「上下文窗口」。图里用的是 DeepSeek-V4.1-Flash，当时选的是「高」和「1M」。

![思考强度和上下文窗口](<../../raw/article/程序员梦哥/assets/WorkBuddy 做好这几个设置，让WorkBuddy越来越懂你/file-20261118151348857.png>)

**思考强度看问题有没有难度，上下文窗口看要带多少资料。** 比如，同时读几份长报告，要考虑资料能不能装得下。定位一段代码里的问题，材料可能很少，但它需要多想几步。拿不准就从默认设置开始，只有资料确实太多、模型也支持时，再考虑调大窗口。提高思考强度可以让模型多花一些功夫，结果还要靠测试或原始资料来核对。

还有个和长对话有关的开关，在「设置 → 智能体 → 经济模式」。开启后，WorkBuddy 会在合适的时候压缩上下文，减少重复传输的内容。 [WorkBuddy 模型配置说明](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Model)

一个项目如果已经聊了很多轮，我更建议按阶段留一份台账。写下现在要做什么、哪些决定已经确认、做到哪一步、下一步要看哪个文件。比如首页已经定稿，下一步只调移动端布局，就把这两点写上。另开对话时，让它先读台账和当前用得上的文件，省去重讲前情，也不容易把旧的方案又翻出来。

## 07 换工具时，再看看「数据导入」

如果之前在别的 AI 工具里攒了不少内容，可以打开「设置」，选择「数据导入」，再点「导入其他应用数据」。

我这边的列表里能看到 ChatGPT、Cursor、Claude Code 和 Claude Cowork。展开 ChatGPT，能看到任务、空间、记忆、技能和连接器等分类。截图里 Cursor 显示 0 项，ChatGPT 的「记忆」一栏虽然显示有条目，右侧按钮却是灰色。具体能导什么，要看展开后当前可点的选项。

![导入其他应用数据](<../../raw/article/程序员梦哥/assets/WorkBuddy 做好这几个设置，让WorkBuddy越来越懂你/file-20261118152041770.png>)

我建议先挑一个还用得上的分类导入。比如想接着做一项旧任务，导入后先打开看看，确认对话和这次要用的资料是否齐全。要是带过来的是技能，先用少量材料试一下。任务能不能接着做，也要看本地文件、工作目录和连接器权限是否还对得上。
